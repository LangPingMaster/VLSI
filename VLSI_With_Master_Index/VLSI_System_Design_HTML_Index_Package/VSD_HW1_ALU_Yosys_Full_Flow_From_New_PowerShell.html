3. 本次遇到的 Yosys SystemVerilog 相容性問題

原始 helper functions 使用 return，例如：

return cnt;

Yosys frontend 曾在此報 syntax error。修改為 Verilog function-name assignment，例如：

clz = cnt;
ctz = cnt;
cpop = cnt;

sat8_add / sat8_sub 也改成：

if (sum > 9'sd127)
    sat8_add = 8'h7f;
else if (sum < -9'sd128)
    sat8_add = 8'h80;
else
    sat8_add = sum[7:0];

CLZ/CTZ 原本的 break 也以 synthesizable 的控制方式取代。修改後 read_verilog -sv ALU.sv 成功。

5. 輸出 Synthesis Netlist

在 Yosys 中：

write_verilog -noattr ALU_synth.v

成功時：

Executing Verilog backend.
Executing BMUXMAP pass.
Executing DEMUXMAP pass.
Dumping module `\ALU'.

離開 Yosys

exit

確認檔案

dir .\ALU_synth.v

本次產生：

ALU_synth.v
Size = 1,179,858 bytes  (約 1.18 MB)

查看前 40 行

Get-Content .\ALU_synth.v -TotalCount 40

可看到外部介面仍維持 32-bit instruction、src_A、src_B 與 result：

module ALU(instruction_i, src_A_i, src_B_i, result_o);
input  [31:0] instruction_i;
input  [31:0] src_A_i;
input  [31:0] src_B_i;
output [31:0] result_o;

查看最後 40 行

Get-Content .\ALU_synth.v -Tail 40

Yosys 展開 functions 後可能留下 function-scope 暫時 net 的 x assignment；不能單靠這些行判定 ALU 輸出為 X。真正應確認的是 result_o 的 driver。

搜尋 result_o

Select-String -Path .\ALU_synth.v -Pattern 'assign result_o'

本次 32 個 result bits 都有實際 Boolean logic，例如：

assign result_o[0]  = ~(_11008_ & _11100_);
assign result_o[1]  = ~(_10903_ & _10998_);
...
assign result_o[31] = ~(_11110_ & _11218_);

~(A & B) 就是 NAND，因此可直接把 netlist 中的 Boolean expression 與 Yosys cell 統計連起來理解。

SystemVerilog RTL ↓ Yosys ↓ Synthesis / Logic Mapping ↓ AND / NAND / XOR / MUX / ... ↓ ALU_synth.v

6. Post-Synthesis / Gate-Level Functional Simulation

回到 Sim 目錄

cd ..\Sim
dir

本次已有 ALU_tb_iverilog.sv、pattern 與原本的 RTL simulation 檔。

第一次 compile 為什麼失敗？

直接執行：

iverilog -g2012 -o ALU_gate_sim.vvp ..\Src\ALU_synth.v .\ALU_tb_iverilog.sv

會出現 ALU 重複宣告，因為 testbench 第 3 行本身包含：

`include "../Src/ALU_iverilog.sv"

因此同時存在 ALU_synth.v 的 module ALU 與 ALU_iverilog.sv 的 module ALU。

建立 Gate-Level 專用 Testbench

Copy-Item .\ALU_tb_iverilog.sv .\ALU_tb_gate.sv

只修改副本，保留原本 RTL TB。從新副本移除 include：

(Get-Content .\ALU_tb_gate.sv) |
Where-Object { $_ -notmatch 'ALU_iverilog\.sv' } |
Set-Content .\ALU_tb_gate.sv

確認已移除：

Select-String -Path .\ALU_tb_gate.sv -Pattern 'include'

沒有任何輸出即表示找不到 include，符合預期。

Compile Gate-Level Simulation

iverilog -g2012 -o ALU_gate_sim.vvp ..\Src\ALU_synth.v .\ALU_tb_gate.sv

成功時 Icarus 通常不輸出訊息，直接回到 PowerShell。

執行

vvp .\ALU_gate_sim.vvp
