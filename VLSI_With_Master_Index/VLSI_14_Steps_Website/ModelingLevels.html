1. Modeling Levels 到底是什麼？

Verilog 可以用不同「抽象程度」描述同一個數位電路。最重要的差別不是語法漂亮與否，而是： 你要告訴工具多少硬體結構細節？

Behavioral / RTL描述「做什麼」
→
Dataflow描述「資料如何運算」
→
Structural / Gate描述「由哪些元件組成」
→
Transistor / Layout接近實體 IC
核心直覺： Behavioral / RTL 越像在說明功能；Gate-Level 越像在畫電路圖。 最後 synthesis 會把可合成的高階描述轉成由 Standard Cells 組成的 Gate-Level Netlist。
層級主要問題典型 Verilog設計者控制程度
Behavioral這個電路要「做什麼」？always, if, case, for低層細節少、功能意圖高
RTL每個 clock 之間資料如何流動與被暫存？always @(posedge clk), reg, mux, arithmetic架構控制很高
Dataflow輸出和輸入之間的邏輯/算術關係是什麼？assign, ?:, +, &, |, ^中等
Structural / Gate到底用了哪些 gate / module，怎麼接？and, or, not, xor, module instances非常高

2. 從 Specification 到 Layout：Modeling Level 在整個 IC 流程的位置

Specification需求、功能、介面
↓
Behavior演算法 / 行為
↓
RTLregister + combinational logic
↓
Gatestandard cells
↓
Circuit / Layouttransistor / geometry

對數位 IC 課程來說，你最常寫的是 RTL。Gate-Level 通常由 synthesis 工具產生； Layout 再由 P&R 工具完成。因此學 Modeling Levels 的目的，是理解： 同一個邏輯功能可以由不同抽象層級表示，而且高階描述最後仍會被實作成真實 gates。

3. Structural / Gate-Level Modeling

Structural modeling 就像「在 Verilog 裡畫 schematic」。你明確列出 AND、OR、NOT、XOR、NAND， 或者例化其他 modules，並用 wires 把它們接起來。

3.1 最基本範例：f = (x1 & x2) | (~x2 & x3)

module logic_structural (
    input  x1, x2, x3,
    output f
);
    wire g, k, h;

    and (g, x1, x2);   // g = x1 & x2
    not (k, x2);       // k = ~x2
    and (h, k, x3);    // h = ~x2 & x3
    or  (f, g, h);     // f = g | h
endmodule
x1,x2 → AND → g↘ OR → f ↗x2 → NOT, 與 x3 → AND → h

3.2 Structural 不一定只用 primitive gates

你也可以例化自己寫的 module。這是「階層式設計（hierarchical design）」的核心。

module half_adder(
    input  a, b,
    output sum, carry
);
    xor (sum, a, b);
    and (carry, a, b);
endmodule

module full_adder_struct(
    input  a, b, cin,
    output sum, cout
);
    wire s1, c1, c2;

    half_adder HA0(.a(a),  .b(b),   .sum(s1),  .carry(c1));
    half_adder HA1(.a(s1), .b(cin), .sum(sum), .carry(c2));

    or (cout, c1, c2);
endmodule
何時適合 Structural？ 教 gate-level、做特殊 datapath、例化 IP / memory / standard-cell-like block、 或當你真的需要控制硬體結構時。

4. Dataflow Modeling

Dataflow 主要透過 assign 與運算式直接描述訊號之間的關係。 它非常適合組合邏輯。你不需要手動拆成每一顆 gate，synthesis 會幫你完成。

4.1 同一個邏輯函數

module logic_dataflow (
    input  x1, x2, x3,
    output f
);
    assign f = (x1 & x2) | (~x2 & x3);
endmodule

4.2 2-to-1 MUX

module mux2_dataflow(
    input  a, b, sel,
    output y
);
    assign y = sel ? b : a;
endmodule

硬體直覺：?: 通常會合成成 multiplexer。

4.3 4-bit Adder

module add4_dataflow(
    input  [3:0] a, b,
    input        cin,
    output [3:0] sum,
    output       cout
);
    assign {cout, sum} = a + b + cin;
endmodule

4.4 Comparator

module compare8(
    input  [7:0] a, b,
    output       gt, eq, lt
);
    assign gt = (a > b);
    assign eq = (a == b);
    assign lt = (a < b);
endmodule

4.5 Decoder

module decoder2to4(
    input  [1:0] a,
    output [3:0] y
);
    assign y = 4'b0001 << a;
endmodule
Dataflow 的重要觀念是「連續指定」：右邊的輸入只要改變，左邊的 net 就重新求值。 它不是 CPU 逐行執行程式，而是在描述持續存在的硬體關係。

5. Behavioral Modeling

Behavioral modeling 直接描述「如果發生某個條件，輸出應該怎麼變」。 常見語法是 always、if、 case、for。

5.1 2-to-1 MUX：if / else

module mux2_behavioral(
    input  a, b, sel,
    output reg y
);
    always @(*) begin
        if (sel)
            y = b;
        else
            y = a;
    end
endmodule

5.2 4-to-1 MUX：case

module mux4_behavioral(
    input  [3:0] d,
    input  [1:0] sel,
    output reg   y
);
    always @(*) begin
        case (sel)
            2'b00: y = d[0];
            2'b01: y = d[1];
            2'b10: y = d[2];
            2'b11: y = d[3];
        endcase
    end
endmodule

5.3 Priority Encoder：if / else-if

module priority_encoder4(
    input  [3:0] req,
    output reg [1:0] code,
    output reg       valid
);
    always @(*) begin
        valid = 1'b1;

        if      (req[3]) code = 2'd3;
        else if (req[2]) code = 2'd2;
        else if (req[1]) code = 2'd1;
        else if (req[0]) code = 2'd0;
        else begin
            code  = 2'd0;
            valid = 1'b0;
        end
    end
endmodule
重要： Behavioral 不代表「不能合成」。只要使用的是 synthesizable subset， behavioral / RTL code 一樣可以合成成真實硬體。

6. RTL（Register-Transfer Level）與 Behavioral 的關係

RTL 可以視為「可合成 Behavioral modeling 中最重要的一種設計風格」。 它明確表達兩件事：register 在哪裡，以及 register 之間的 combinational logic 是什麼。

Register A→ Combinational Logic
+ / MUX / ALU→ Register B

每一個 clock edge 把新資料存入下一級 register。

6.1 D Flip-Flop

module dff(
    input  clk,
    input  d,
    output reg q
);
    always @(posedge clk) begin
        q <= d;
    end
endmodule

6.2 帶 reset 的 8-bit Register

module reg8(
    input        clk,
    input        rst_n,
    input  [7:0] d,
    output reg [7:0] q
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            q <= 8'h00;
        else
            q <= d;
    end
endmodule

6.3 Counter

module counter8(
    input        clk,
    input        rst_n,
    input        en,
    output reg [7:0] count
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            count <= 8'd0;
        else if (en)
            count <= count + 1'b1;
    end
endmodule

6.4 Shift Register

module shift4(
    input        clk,
    input        rst_n,
    input        din,
    output reg [3:0] q
);
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            q <= 4'b0000;
        else
            q <= {q[2:0], din};
    end
endmodule
在 clocked always block 中，通常使用 nonblocking assignment： <=。這樣能正確表達「所有 flip-flops 在同一個 clock edge 同步更新」。

7. 同一個功能，用三種 Modeling Level 改寫

例 1：2-to-1 MUX

module mux2_struct(input a,b,sel, output y);
    wire nsel, w0, w1;
    not (nsel, sel);
    and (w0, a, nsel);
    and (w1, b, sel);
    or  (y, w0, w1);
endmodule
module mux2_df(input a,b,sel, output y);
    assign y = sel ? b : a;
endmodule
module mux2_beh(input a,b,sel, output reg y);
    always @(*) begin
        if (sel) y = b;
        else     y = a;
    end
endmodule

這三段 code 在功能上可以完全相同，但抽象層級不同。Structural 明確指名 gate； Dataflow 直接寫 Boolean / conditional expression；Behavioral 用程序式敘述表達條件。

例 2：1-bit Full Adder

Structural

xor (sum, a, b, cin);
and (c1, a, b);
and (c2, a, cin);
and (c3, b, cin);
or  (cout, c1, c2, c3);

Dataflow

assign sum  = a ^ b ^ cin;
assign cout = (a & b) |
              (a & cin) |
              (b & cin);

Behavioral

always @(*) begin
    {cout, sum} = a + b + cin;
end
最值得記住：不是哪一種寫法「比較硬體」才叫 Verilog。 三種都是硬體描述；差別是你把多少低階結構交給 synthesis tool 決定。

8. 大量範例：看到題目時，如何選 Modeling Style？

8.1 AND / OR / NOT 邏輯

// Gate
and (w1, a, b);
not (w2, c);
or  (y, w1, w2);

// Dataflow
assign y = (a & b) | ~c;

// Behavioral
always @(*) begin
    y = (a & b) | ~c;
end

8.2 8-bit ALU

module alu8(
    input  [7:0] a, b,
    input  [2:0] op,
    output reg [7:0] y
);
    always @(*) begin
        case (op)
            3'b000: y = a + b;
            3'b001: y = a - b;
            3'b010: y = a & b;
            3'b011: y = a | b;
            3'b100: y = a ^ b;
            3'b101: y = a << 1;
            3'b110: y = a >> 1;
            default: y = 8'h00;
        endcase
    end
endmodule

這是典型 Behavioral / RTL combinational logic，case 多半對應到 mux + arithmetic / logic units。

8.3 Signed / Unsigned Max

// unsigned compare
assign max_u = (a > b) ? a : b;

// signed compare
wire signed [7:0] as = a;
wire signed [7:0] bs = b;
assign max_s = (as > bs) ? as : bs;

8.4 8-bit Population Count（for loop）

module popcount8(
    input  [7:0] x,
    output reg [3:0] count
);
    integer i;
    always @(*) begin
        count = 0;
        for (i = 0; i < 8; i = i + 1)
            count = count + x[i];
    end
endmodule
固定邊界的 synthesizable for loop 通常會在 synthesis 時展開成硬體。 它不是「只做一顆加法器，跑 8 個 clock」；除非你另外設計 FSM / counter 讓它逐 cycle 執行。

8.5 8-to-3 Encoder：case

always @(*) begin
    case (in)
        8'b0000_0001: code = 3'd0;
        8'b0000_0010: code = 3'd1;
        8'b0000_0100: code = 3'd2;
        8'b0000_1000: code = 3'd3;
        8'b0001_0000: code = 3'd4;
        8'b0010_0000: code = 3'd5;
        8'b0100_0000: code = 3'd6;
        8'b1000_0000: code = 3'd7;
        default:      code = 3'd0;
    endcase
end

8.6 Saturating Adder

wire [8:0] temp;
assign temp = a + b;
assign y = temp[8] ? 8'hFF : temp[7:0];

8.7 Register with Enable

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 8'h00;
    else if (en)
        q <= d;
end

若 en=0，q 沒有被重新指定，這在 clocked block 中代表「保持原本 register 值」。

8.8 Finite State Machine（FSM）

module simple_fsm(
    input  clk, rst_n, start, done,
    output reg busy
);
    localparam IDLE = 1'b0,
               RUN  = 1'b1;

    reg state, next_state;

    // state register
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    // next-state logic
    always @(*) begin
        next_state = state;
        case (state)
            IDLE: if (start) next_state = RUN;
            RUN : if (done)  next_state = IDLE;
        endcase
    end

    // output logic
    always @(*) begin
        busy = (state == RUN);
    end
endmodule

FSM 是最典型的 RTL：一個 state register + 一段 combinational next-state logic + output logic。

9. Modeling Level 與「組合 / 時序」不要混在一起

很多人會誤以為「Dataflow = 組合、Behavioral = 時序」。這是不對的。 Modeling level 是描述方式；combinational / sequential 是電路種類。

組合邏輯時序邏輯
Dataflow 非常常見：assign y = a & b; 通常不直接用 assign 來描述 flip-flop
Behavioral always @(*) + blocking = always @(posedge clk) + nonblocking <=
Structural 例化 AND/OR/MUX 也能直接例化 DFF cells

10. Synthesis 如何看待不同 Modeling Levels？

Synthesis 不在乎你「寫得像 C 還是像 schematic」，它在乎： 這段 HDL 能否對應成實際硬體，而且邏輯意圖是否明確。

RTL / Behavioral / Dataflow可合成 HDL
→
Elaboration展開 hierarchy / parameters
→
Logic OptimizationBoolean / arithmetic optimization
→
Technology Mapping映射到 standard cells
→
Gate-Level NetlistINV / NAND / DFF / MUX...

10.1 這三種可能合成到幾乎一樣的硬體

// A
assign y = (a & b) | (a & c);

// B
always @(*) begin
    y = a & (b | c);
end

// C
wire t;
or  (t, b, c);
and (y, a, t);

因為布林代數等價，工具通常會做最佳化。這就是為什麼高階 RTL 不需要手動把每個 gate 都「最佳化」到最底層。

12. 常見錯誤與考試重點

12.1 Behavioral 不是 software

Verilog 的 if、case 看起來像 C，但合成後通常變成 MUX、decoder、enable logic， 並不是「CPU 執行 if 敘述」。

12.2 Combinational always 必須完整賦值

// 錯誤：sel=0 時沒有指定 y → 可能推導 latch
always @(*) begin
    if (sel)
        y = a;
end

// 正確
always @(*) begin
    if (sel)
        y = a;
    else
        y = b;
end

12.3 Sequential 用 <=，Combinational 常用 =

// sequential
always @(posedge clk)
    q <= d;

// combinational
always @(*)
    y = a & b;

12.4 wire / reg 的傳統 Verilog 觀念

傳統 Verilog 中，continuous assignment / module output connection 常使用 wire； procedural block 內被賦值的變數使用 reg。但 reg 這個名字 不保證一定合成成 register，是否是 register 取決於你的描述方式。

12.5 Gate-Level 並不等於「手寫 gate 才是專業」

真正大型設計如果全部手寫 gate，維護、驗證與最佳化成本極高。現代數位 IC 設計的重點是： 用清楚、可合成、可驗證的 RTL 表達架構，再讓 EDA 工具做 synthesis 與 mapping。

12.6 快速自我測驗

Q1：assign y = sel ? a : b; 大多會合成成什麼？

2-to-1 Multiplexer。

Q2：always @(*) 是不是代表 flip-flop？

不是。它通常表示 combinational procedural block；是否產生 latch 取決於是否有未完整賦值的路徑。

Q3：always @(posedge clk) q <= d; 代表什麼？

典型 edge-triggered D Flip-Flop。

Q4：Dataflow 一定比 Behavioral 更接近 gate 嗎？

通常抽象程度可視為介於 gate 與 behavioral 之間，但 synthesis 會做最佳化，最終 netlist 不一定保留你原本運算式的表面結構。

13. 一頁記憶版

Structural

想像：「我自己接 gates / modules。」

and, or, not, instance

Dataflow

想像：「我寫出輸入到輸出的運算關係。」

assign, operators, ?:

Behavioral / RTL

想像：「我描述功能、clock、state 與資料轉移。」

always, if, case, for

最後一句： 同一個 circuit 可以有多種 Verilog 寫法；真正重要的是功能是否正確、是否可合成、 推導出的硬體是否符合你的 architecture、timing、area、power 目標。
