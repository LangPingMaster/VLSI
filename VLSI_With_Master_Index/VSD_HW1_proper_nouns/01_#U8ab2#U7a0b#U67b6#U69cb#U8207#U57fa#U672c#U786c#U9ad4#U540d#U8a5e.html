01｜課程、架構與基本硬體名詞

VSD HW1 名詞＋專有名詞詳細學習版。每個條目均提供「作業中的依據 → 詳細說明 → 至少 2 個例子」，並使用下拉式互動呈現。
資料標示原則：直接來自 HW1 的規格會寫在「作業中的依據」。像 RTL、Datapath、Combinational Logic 等若 PDF 沒有正式定義，頁面會明確標示為「背景補充」，避免把一般知識誤當成老師在 PDF 中的原文定義。

本章名詞在 HW1 中的位置

01VSD超大型積體電路系統設計⌄
課程專有名詞英文／全名：VLSI System Design

作業中的依據

HW1 首頁的課程名稱為「VLSI System Design 2026 Fall」。作業內容以 ALU 與 FPU 兩個硬體設計問題為核心。

詳細說明

VSD 在這份作業中是課程名稱的縮寫。從 HW1 的要求可以看到，課程不是只討論抽象邏輯，而是要求把功能規格轉成可模擬的 SystemVerilog 硬體模組，並使用 testbench、patterns 與 Superlint 檢查。

至少 2 個例子

例 1｜ALU 設計

Prob. A 要你設計 32-bit ALU，支援 RV32IM、RV32B 與 Custom DSP 指令。這就是 VSD 中「System Design」的具體例子：先理解 instruction specification，再設計 datapath/logic。

例 2｜FPU 設計

Prob. B 要你設計 IEEE-754 single-precision FPU，處理 MIN、MAX、ADD、SUB、NaN、Inf、Zero、Normalization 與 GRS rounding，代表系統設計需要同時處理正常資料路徑與特殊情況。

02VLSI超大型積體電路⌄
領域專有名詞英文／全名：Very Large Scale Integration

作業中的依據

PDF 的課程名稱包含 VLSI；但這份 HW1 沒有另外對 VLSI 這個縮寫下定義。

詳細說明

因此，「Very Large Scale Integration」的全名屬於一般領域背景補充，而不是 PDF 內文對它的定義。在本作業脈絡中，你實際接觸的是以 RTL/SystemVerilog 描述數位硬體功能，再進行 simulation 與 lint 檢查。

至少 2 個例子

例 1｜RTL 模組

你撰寫 ALU.sv，把 ADD、SUB、MUL、BSET 等功能描述成硬體邏輯；這是 VLSI 數位設計流程前端常見的 RTL 工作。

例 2｜FPU 資料路徑

把 floating-point ADD/SUB 拆成 Unpack、Align、Mantissa ADD/SUB、Normalize、Round、Repack，可以把複雜功能切成可實作的硬體步驟。

03HW1作業一⌄
作業名詞英文／全名：Homework 1

作業中的依據

PDF 標題為 HW1；Grading Policy 指定 Prob. A ALU 40%、Prob. B FPU 40%、Report 20%。

詳細說明

HW1 是本課程第一次作業。它同時考察整數/位元/DSP ALU 與 IEEE-754 FPU。除了功能正確，還要求遵守檔案 hierarchy、通過 simulation patterns、hidden tests，並達成 Superlint coverage 要求。

至少 2 個例子

例 1｜功能部分

ALU 必須支援總計 31 條 operations；只完成 ADD/SUB 並不等於完成 HW1。

例 2｜繳交部分

即使 RTL 功能正確，如果沒有依 StudentID.pdf、Src、Sim、Pattern 的 hierarchy 整理，PDF 規定會有扣分。

04ALU算術邏輯單元⌄
硬體模組英文／全名：Arithmetic Logic Unit

作業中的依據

Prob. A 要求設計 32-bit ALU；I/O 為 instruction_i、src_A_i、src_B_i、result_o。ALU operation 由 instruction_i 的欄位解碼。

詳細說明

ALU 接收兩個 32-bit operands 與一個 32-bit instruction。核心工作不是單純做加法，而是先 decode instruction，再選擇對應的 arithmetic、logical、shift、multiply、bit-manipulation 或 DSP operation，最後輸出 result_o。

至少 2 個例子

例 1｜ADD

若 instruction_i 解碼為 ADD，src_A_i=10、src_B_i=7，則 ALU 執行 10+7，result_o=17。

例 2｜BSET

若解碼為 BSET，rs2[4:0]=3，則依 PDF 定義執行 rs1 | (1 << 3)，也就是把 rs1 的 bit 3 設為 1。

05FPU浮點運算單元⌄
硬體模組英文／全名：Floating Point Unit

作業中的依據

Prob. B 要求 32-bit IEEE-754 single-precision FPU，instruction 0=min、1=max、2=add、3=sub，並輸出 co 與 valid。

詳細說明

FPU 處理的不是一般 32-bit integer，而是 IEEE-754 floating-point bit pattern。因此 ADD/SUB 需要拆解 Sign/Exponent/Fraction、處理特殊值、對齊 exponent、計算 mantissa、normalize、使用 GRS round-to-even，再 repack 成 32 bits。

至少 2 個例子

例 1｜ADD

ai、bi 都是 IEEE-754 single precision。FPU 不能直接把兩個 32-bit bit pattern 當整數相加，而要依 PDF 的 ADD/SUB 流程處理。

例 2｜NaN

若輸入 exponent=255 且 fraction 非零，PDF 將其判定為 NaN；ADD/SUB special-case table 指定 NaN result 為 32'hFFC00000。

06RV32IMB本作業使用的 32-bit RISC-V 指令相關集合⌄
ISA 專有名詞英文／全名：RV32I / M / B related instruction set used in HW1

作業中的依據

PDF 的 General Description 寫「31 Instructions from RV32IMB + Custom DSP Extension」，並分別列出 RV32IM 14 條、RV32B 12 條與 DSP 5 條。

詳細說明

這個詞在 HW1 中用來概括 ALU 要處理的 RISC-V 指令來源。PDF 實際把標準部分拆成 RV32IM 與 RV32B 表格，再加上自訂 DSP。這裡最重要的是依作業表格的 opcode/funct 欄位與 operation 定義實作，而不是自行擴充其他 RISC-V 指令。

至少 2 個例子

例 1｜RV32IM

MULH 屬於 PDF 的 RV32IM 表：signed(rs1) × signed(rs2)，取 product[63:32]。

例 2｜RV32B

CLZ 屬於 PDF 的 RV32B 表：result 是 rs1 的 leading zeros 數量。

07DSP數位訊號處理⌄
領域／指令專有名詞英文／全名：Digital Signal Processing

作業中的依據

PDF 定義 Custom DSP Extension 五個 operations：DOTP4、SADD8、SSUB8、ABS、CLIP8。

詳細說明

在這份 HW 中，DSP 不是要求你完成完整的訊號處理器，而是用五個 custom operations 練習 packed 8-bit lanes、signed two's-complement、dot product、saturation、absolute value 與 clipping。

至少 2 個例子

例 1｜DOTP4

兩個 32-bit operands 各拆成四個 signed 8-bit elements；四組相乘後相加，形成 dot product。

例 2｜SADD8

每個 8-bit lane 獨立做 signed addition 並 saturation。例如 PDF 明示 100+50 會飽和為 127，而不是發生一般 8-bit wraparound。

08RTL暫存器傳輸層⌄
硬體設計專有名詞英文／全名：Register Transfer Level

作業中的依據

PDF 要求提交 ALU.sv、FPU.sv 等 SystemVerilog source，但 PDF 這 28 頁沒有專門定義「RTL」一詞；本項全名與說明屬硬體設計背景補充。

詳細說明

RTL 是以暫存器、組合邏輯與資料在 clock 邊緣間的傳遞來描述數位硬體的抽象層級。對本 HW 而言，重點是讓 SystemVerilog 描述符合指定 I/O、功能與時序，並可被提供的 testbench 模擬。

至少 2 個例子

例 1｜組合 ALU

ALU 可以依 instruction decode 後用 combinational logic 計算 result_o；這是 RTL 中描述 datapath/function 的典型情境。

例 2｜FPU valid

FPU 具有 clk、rst、enable、valid；若你的架構使用 registers 分階段保存結果，就會涉及 clocked RTL 與資料傳遞時序。

09SystemVerilogSystemVerilog 硬體描述／驗證語言⌄
語言專有名詞英文／全名：SystemVerilog

作業中的依據

PDF 提交檔案使用 .sv，VCS command 使用 -sverilog；PDF 沒有提供 SystemVerilog 語言教科書式定義。

詳細說明

在這份 HW 中，SystemVerilog 是你撰寫 ALU、FPU 與 testbench 的語言環境。作業真正檢查的是你的 .sv 是否能在 SoC Lab environment compile、simulate 並通過測試。

至少 2 個例子

例 1｜ALU.sv

你會在 ALU.sv 中根據 instruction_i 決定 ADD、SUB、MUL、CLZ、DOTP4 等輸出。

例 2｜FPU_tb.sv

testbench 會提供 ai、bi、instruction 等刺激，等待 valid 後把 co 與 golden answer 比較。

10I/O Port輸入／輸出埠⌄
硬體介面名詞英文／全名：Input / Output Port

作業中的依據

PDF 的 ALU 與 FPU 都有 I/O Port 表，列出 Signal、Type、Bits、Description。

詳細說明

Port 是模組和外部交換資料或控制資訊的介面。Input 由外部送進模組；Output 由模組送出去。位寬必須符合 PDF 規格。

至少 2 個例子

例 1｜ALU ports

instruction_i、src_A_i、src_B_i 是 Input；result_o 是 Output。四者都是 32 bits。

例 2｜FPU ports

clk/rst/enable 是控制 input，ai/bi 是 32-bit data input，instruction 是 2-bit operation input，co 與 valid 是 output。

11Signal訊號⌄
硬體基本名詞英文／全名：Signal

作業中的依據

PDF 的 I/O 表以 Signal 欄列出 ALU/FPU 各訊號名稱。

詳細說明

Signal 是硬體中傳遞資料或控制狀態的名稱。理解一個 module 時，先分清楚每個 signal 的方向、位寬與意義，通常比直接讀內部 code 更重要。

至少 2 個例子

例 1｜資料訊號

src_A_i 是 32-bit data signal，內容代表 rs1 的資料。

例 2｜控制訊號

valid 是 1-bit output control signal；PDF 要求 valid 拉高後才用 golden 檢查 co。

12Bit位元⌄
數位基本名詞英文／全名：Binary Digit

作業中的依據

PDF 以 Bits 欄表示訊號寬度，並大量使用 [31:0]、[63:32]、rs2[4:0] 等 bit ranges。

詳細說明

Bit 的值為 0 或 1。多個 bits 組成欄位或資料字。硬體設計中特別重要的是 bit width 與 bit slicing，因為不同 operation 只會使用某些位元。

至少 2 個例子

例 1｜32-bit input

src_A_i 有 32 bits，可標示為 [31:0]。

例 2｜shift amount

SLL/SRL/SRA 只使用 rs2[4:0]，也就是 5 bits，因此可表示 0～31 的位移量。

13Operand運算元⌄
運算基本名詞英文／全名：Operand

作業中的依據

PDF 的 ALU I/O 描述 src_A_i 為 rs1 data、src_B_i 為 rs2 data；FPU 則以 operand A/B 描述 ai、bi 的特殊情況。

詳細說明

Operand 就是被 operation 使用的輸入數值。要注意同一組 32 bits 可以依指令被解讀成 signed、unsigned 或 IEEE-754 floating-point，因此「bit pattern」相同不代表數值語意相同。

至少 2 個例子

例 1｜ALU

ADD 的兩個 operands 是 src_A_i 與 src_B_i；若分別為 5 和 3，結果為 8。

例 2｜FPU

ADD/SUB 的 operand A/B 是 ai、bi；FPU 會先把它們 unpack 成 S/E/F，而不是直接做 integer arithmetic。

14Instruction指令⌄
ISA 基本名詞英文／全名：Instruction

作業中的依據

ALU 的 instruction_i 是 32-bit RISC-V instruction；FPU 另有 2-bit instruction，0=min、1=max、2=add、3=sub。

詳細說明

Instruction 告訴硬體要執行哪個 operation。本 HW 有兩種不同語境：ALU 的 32-bit RISC-V instruction 需要解析 opcode/funct fields；FPU 的 2-bit instruction 則直接選擇四種浮點 operation。

至少 2 個例子

例 1｜ALU instruction

當 opcode/funct fields 對應 SUB 時，ALU 執行 rs1-rs2。

例 2｜FPU instruction

當 FPU instruction=2 時，PDF 定義 operation 為 add；instruction=3 時為 sub。

15Decode指令解碼⌄
硬體控制名詞英文／全名：Instruction Decoding

作業中的依據

PDF 的 ALU I/O 說明：「ALU operation is decoded from the corresponding fields of instruction_i」。

詳細說明

Decode 是從 instruction bit fields 判斷要執行哪一個 operation。對 ALU 而言，常需要同時查看 opcode、funct3、funct7 或特定固定欄位，才能唯一辨認指令。

至少 2 個例子

例 1｜ADD vs SUB

PDF 表中 ADD 與 SUB 的 funct3 都是 000，但 funct7 不同，所以不能只看 funct3。

例 2｜DSP

Custom DSP 使用 opcode=0001011，再搭配 funct7、funct3 等欄位辨認 DOTP4、SADD8、SSUB8、ABS、CLIP8。

16Datapath資料路徑⌄
硬體架構專有名詞英文／全名：Data Path

作業中的依據

PDF 沒有把 Datapath 當作獨立詞條定義；此項用來解讀 PDF 的 FPU architecture 與 ADD/SUB 流程圖，屬背景補充。

詳細說明

Datapath 指資料在硬體中經過運算、移位、比較、選擇與暫存的路徑。FPU 特別適合用 datapath 思考，因為資料會依序經過多個處理步驟。

至少 2 個例子

例 1｜ALU datapath

src_A_i/src_B_i 進入不同運算邏輯，再依 decode 結果選出 result_o，可視為 ALU datapath。

例 2｜FPU datapath

ai/bi → Unpack → Align → Mantissa ADD/SUB → Normalize → GRS rounding → Repack → co，是本作業最重要的資料路徑。

17Module硬體模組⌄
硬體架構名詞英文／全名：Hardware Module

作業中的依據

PDF 的提交 hierarchy 指定 ALU.sv、FPU.sv，並允許 Other user-defined .sv files；PDF 未提供 module 的一般教科書定義。

詳細說明

Module 可以把一組功能與 I/O 封裝成可管理的硬體區塊。本作業至少要有 ALU 與 FPU；若需要，也可以把複雜功能拆成其他 user-defined .sv files，但仍需符合指定 hierarchy。

至少 2 個例子

例 1｜ALU module

ALU module 對外只需依規格接收 instruction_i、src_A_i、src_B_i 並輸出 result_o。

例 2｜FPU 子模組

你可以概念上把 comparator、adder、normalizer 等拆成子模組；PDF architecture 本身也以 FPU Adder、FPU Comparator、MUX 呈現功能區塊。

18Combinational Logic組合邏輯⌄
硬體基本專有名詞英文／全名：Combinational Logic

作業中的依據

PDF 沒有獨立定義此詞；本項是理解 ALU operation 的背景補充。

詳細說明

組合邏輯的輸出由目前輸入決定，不依賴過去狀態。許多 ALU operations 天然可表示成組合邏輯；實際 RTL 如何安排仍要以你的設計與作業時序要求為準。

至少 2 個例子

例 1｜AND

result = src_A_i & src_B_i，輸出直接由當前兩個 operands 決定。

例 2｜SLTU

比較兩個 unsigned operands 後輸出 0 或 1，也可視為一種組合功能。

19Sequential Logic循序邏輯／時序邏輯⌄
硬體基本專有名詞英文／全名：Sequential Logic

作業中的依據

PDF 的 FPU interface 含 clk、rst、enable、valid，Data Transfer 頁以 cycles 描述資料傳輸；PDF 沒有獨立定義此詞。

詳細說明

循序邏輯會受到 clock 與先前狀態影響。這個背景概念有助於理解為什麼 FPU 不是只看 co，而要依 enable 送入資料、等待 valid，再檢查輸出。

至少 2 個例子

例 1｜valid timing

輸入送入 FPU 後，testbench 等待 valid 拉高才認定 co 有效，這是一個明確的時序介面概念。

例 2｜reset

rst 用於重置 FPU 狀態；Data Transfer 頁先處理 reset，再拉高 enable 餵入資料。
