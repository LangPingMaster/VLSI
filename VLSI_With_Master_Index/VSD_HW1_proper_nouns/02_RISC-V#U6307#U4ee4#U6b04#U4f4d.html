02｜RISC-V 指令欄位

以 VSD HW1 的 ALU instruction encoding 為核心，詳細整理 RISC-V instruction、R-type、opcode、funct7、funct3、rs1、rs2、rd、bit fields、fixed encoding 與 Custom DSP encoding。每個名詞都有至少 2 個例子。
內容原則：以 HW1 PDF 的 instruction tables 與 I/O 說明為主要依據。若加入 bit slicing、Decode Key 等教學詞彙，會明確標成背景／教學整理，不把它冒充成 PDF 原文。

01RISC-VRISC-V 指令集架構⌄
ISA 專有名詞英文／全名：RISC-V Instruction Set Architecture

HW1 中的依據

HW1 的 ALU 輸入 instruction_i 是 32-bit RISC-V instruction；PDF 再依 RV32IM、RV32B 與 Custom DSP 列出作業要支援的 operations。

詳細說明

在本章最重要的不是背 RISC-V 的所有規格，而是理解一條 32-bit instruction 如何被切成不同欄位，再由 ALU decode。PDF 明確說 ALU operation 是從 instruction_i 對應欄位解碼而來。

例子（至少 2 個）

例 1｜RV32IM

ADD、SUB、MULH 等由 PDF 的 RV32IM 表指定 funct7、funct3 與共同 opcode=0110011。

例 2｜RV32B

CLZ 與 ROL 都屬 RV32B，但 CLZ 的 opcode=0010011，而 ROL 的 opcode=0110011，所以 decode 必須查看實際欄位。

02Instruction32-bit RISC-V 指令⌄
核心名詞英文／全名：32-bit RISC-V instruction

HW1 中的依據

PDF 定義 instruction_i 為 32-bit RISC-V instruction，用來 decode ALU operation。

詳細說明

Instruction 是硬體要執行之 operation 的編碼。本作業 ALU 不是額外收到一個文字名稱「ADD」，而是收到 32 bits；你的 decode logic 要從其中的 opcode、funct3、funct7，以及某些 [24:20] 固定值判斷是哪條指令。

例子（至少 2 個）

例 1｜ADD

當 instruction 的欄位符合 ADD：funct7=0000000、funct3=000、opcode=0110011，ALU 執行 rs1+rs2。

例 2｜CTZ

CTZ 在 PDF 中使用 funct7=0110000、[24:20]=00001、funct3=001、opcode=0010011；這些欄位共同辨識 CTZ。

03Instruction Format指令格式⌄
格式專有名詞英文／全名：Instruction Format

HW1 中的依據

PDF 在 ALU I/O 頁提供「R-type & M Standard instruction format」，並在 RV32B/DSP 表格列出各 instruction fields。

詳細說明

Instruction format 是把 32-bit instruction 分成有意義欄位的配置方式。對這份 HW，最常使用的欄位概念包括 funct7、rs2/[24:20]、rs1/[19:15]、funct3、rd/[11:7]、opcode。

例子（至少 2 個）

例 1｜R-type

ADD 可用 funct7 + rs2 + rs1 + funct3 + rd + opcode 的欄位方式理解。

例 2｜RV32B 特例

CLZ 的 [24:20] 不是一般 rs2 operand，而是固定 00000；CTZ 則固定 00001。

04R-typeR-type 暫存器型指令格式⌄
格式專有名詞英文／全名：Register-type instruction format

HW1 中的依據

PDF 明確顯示 R-type & M Standard instruction format，並以 funct7、rs2、rs1、funct3、rd、opcode 構成。

詳細說明

R-type 的核心概念是 instruction 中含兩個來源暫存器欄位 rs1、rs2 與一個目的暫存器欄位 rd，再用 opcode/funct fields 指定 operation。這是理解本 HW 大量 ALU instructions 的基礎。

例子（至少 2 個）

例 1｜ADD

ADD 讀取 rs1 與 rs2 的資料，相加後把結果對應到 rd。

例 2｜MULHU

MULHU 同樣使用兩個 source operands，但 funct7=0000001、funct3=011，表示 unsigned×unsigned 並取 product[63:32]。

05M Standard Instruction FormatM 標準乘法相關指令格式⌄
格式專有名詞英文／全名：M Standard / Multiply Extension related format

HW1 中的依據

PDF 的 I/O 頁將圖稱為「R-type & M Standard instruction format」，RV32IM 表中的 MUL、MULH、MULHSU、MULHU 使用 funct7=0000001。

詳細說明

就這份作業而言，M 相關指令最重要的辨識特徵是 PDF 表中四個 multiply operations 的 funct7 都是 0000001，再以 funct3 區分結果類型。

例子（至少 2 個）

例 1｜MUL

funct7=0000001、funct3=000，取乘積 [31:0]。

例 2｜MULH vs MULHU

兩者 funct7 都是 0000001，但 MULH funct3=001 且 signed×signed；MULHU funct3=011 且 unsigned×unsigned。

06opcode操作碼⌄
指令欄位英文／全名：Operation Code

HW1 中的依據

PDF RV32IM 表指定 opcode=0110011；RV32B 表則出現 0010011 與 0110011；DSP custom opcode=0001011。

詳細說明

opcode 是 decode 的第一層重要欄位，可先把 instruction 分到某個編碼類別。但在本 HW 中，opcode 通常不能單獨唯一決定 operation，還必須配合 funct3、funct7 或其他固定欄位。

例子（至少 2 個）

例 1｜0110011

ADD、SUB、ROL、ROR、MIN、BSET 等都可能使用 0110011，所以看到這個 opcode 還不能立刻知道是哪一條。

例 2｜0001011

Custom DSP 五條指令都使用 0001011；接著再以 funct3=000~100 區分 DOTP4 到 CLIP8。

07funct77-bit 功能欄位⌄
指令欄位英文／全名：7-bit function field

HW1 中的依據

PDF 的 RV32IM/RV32B/DSP tables 都列出 funct7。

詳細說明

funct7 是高位側的重要 function field，常與 funct3、opcode 合作辨識 operation。它尤其能區分 funct3 相同但功能不同的指令。

例子（至少 2 個）

例 1｜ADD vs SUB

兩者 funct3 都是 000、opcode 都是 0110011；ADD funct7=0000000，而 SUB=0100000。

例 2｜BSET vs BCLR

兩者 funct3=001、opcode=0110011；BSET funct7=0010100，BCLR=0100100。

08[31:25]指令 bit 31～25⌄
位元範圍英文／全名：Instruction bits 31 through 25

HW1 中的依據

R-type 圖中此 7-bit 區域對應 funct7。

詳細說明

這是 bit slicing 的寫法，表示從 32-bit instruction 取出 bit 31 到 bit 25，共 7 bits。對 R-type-like decode 而言，通常就是 funct7 的位置。

例子（至少 2 個）

例 1｜SUB

instruction[31:25]=0100000 時，搭配 funct3=000、opcode=0110011 可對應 PDF 的 SUB。

例 2｜MUL

instruction[31:25]=0000001，搭配 funct3=000、opcode=0110011 可對應 MUL。

09rs2來源暫存器 2⌄
暫存器欄位英文／全名：Source Register 2

HW1 中的依據

PDF：src_B_i = $(rs2)，且 src_B_i 是 Second source operand。

詳細說明

rs2 是第二來源暫存器欄位；在 ALU module 外部，實際 rs2 data 已透過 src_B_i 提供。要區分「instruction 裡的 rs2 欄位」與「src_B_i 裡的 32-bit 資料」。

例子（至少 2 個）

例 1｜ADD

instruction 的 rs2 欄位指出第二來源 register；其資料透過 src_B_i 參與 rs1+rs2。

例 2｜BSET

PDF 的 BSET 使用 rs2[4:0] 作 bit index，因此實際 operation 會使用第二 operand 的低 5 bits。

10[24:20]指令 bit 24～20⌄
位元範圍英文／全名：Instruction bits 24 through 20

HW1 中的依據

RV32B table 特別把這欄標成 [24:20]；對 ROL/ROR/MIN/MAX 等填 rs2，但 CLZ/CTZ/CPOP 分別固定 00000/00001/00010。

詳細說明

這個欄位非常值得獨立記住，因為它不一定永遠代表一般 rs2。PDF 的 unary-like bit-count instructions 把它當成辨識功能的固定 encoding。

例子（至少 2 個）

例 1｜CLZ

[24:20]=00000，配 funct7=0110000、funct3=001、opcode=0010011。

例 2｜CPOP

[24:20]=00010；其他主要欄位與 CLZ/CTZ 相近，因此這 5 bits 參與區分三者。

11rs1來源暫存器 1⌄
暫存器欄位英文／全名：Source Register 1

HW1 中的依據

PDF：src_A_i = $(rs1)，src_A_i 是 First source operand。

詳細說明

rs1 是第一來源暫存器欄位；ALU 真正計算時使用 src_A_i 所帶的 rs1 data。很多 unary operations 的主要資料也來自 rs1。

例子（至少 2 個）

例 1｜SUB

SUB 執行 rs1-rs2，因此 src_A_i 是被減數。

例 2｜CLZ

CLZ 的 operation 是 count_leading_zeros(rs1)，所以被計數的 32-bit operand 來自 rs1。

12[19:15]指令 bit 19～15⌄
位元範圍英文／全名：Instruction bits 19 through 15

HW1 中的依據

RV32B table 將 [19:15] 欄填為 rs1。

詳細說明

這 5 bits 是 rs1 register field 的位置。它是 instruction encoding；它本身不是 rs1 的 32-bit data，而是用來表示哪個來源 register。

例子（至少 2 個）

例 1｜R-type

對 ADD，instruction[19:15] 是 rs1 欄位，而 src_A_i 才是該 register 的 32-bit data。

例 2｜CLZ

即使 CLZ 的 [24:20] 固定 00000，[19:15] 仍是 rs1，因為 CLZ 要對 rs1 的資料計算 leading zeros。

13funct33-bit 功能欄位⌄
指令欄位英文／全名：3-bit function field

HW1 中的依據

PDF 的 RV32IM、RV32B、DSP tables 均列 funct3。

詳細說明

funct3 只有 3 bits，因此最多只有八種 bit patterns；它通常必須與 opcode、funct7 一起使用。不同 extension 中相同 funct3 完全可能代表不同 operation。

例子（至少 2 個）

例 1｜RV32IM

ADD/SUB 的 funct3 都是 000，而 XOR 是 100、OR 是 110、AND 是 111。

例 2｜DSP

DOTP4/SADD8/SSUB8/ABS/CLIP8 的 funct3 依序為 000/001/010/011/100，opcode 都是 0001011。

14[14:12]funct3 的 bit 位置⌄
位元範圍英文／全名：Instruction bits 14 through 12

HW1 中的依據

R-type standard format 中 funct3 為 3-bit field；本項將其 bit 位置 [14:12] 作為格式閱讀背景補充。PDF 表本身以 funct3 名稱呈現。

詳細說明

在 RTL decode 時，常會從 32-bit instruction 中切出這三個 bits，再與其他欄位一起比對。這是理解 funct3 與 bit slicing 的連結。

例子（至少 2 個）

例 1｜SLL

funct3=001，搭配 funct7=0000000 與 opcode=0110011 對應 SLL。

例 2｜SRA

funct3=101，搭配 funct7=0100000 與 opcode=0110011 對應 SRA。

15rd目的暫存器⌄
暫存器欄位英文／全名：Destination Register

HW1 中的依據

PDF：result_o = $(rd)，result_o 是 ALU output result。

詳細說明

rd 是目的暫存器欄位，表示 operation 結果應對應到哪個 destination register。你的 ALU module 只輸出 result_o，實際 register-file write-back 不在這幾頁 ALU I/O 規格中展開。

例子（至少 2 個）

例 1｜ADD

ADD 計算完成後，PDF 以 rd=rs1+rs2 描述結果語意。

例 2｜BEXT

BEXT 的 rd 只會得到抽出的 bit 值 0 或 1，但仍以 32-bit result_o 輸出。

16[11:7]指令 bit 11～7⌄
位元範圍英文／全名：Instruction bits 11 through 7

HW1 中的依據

RV32B table 把 [11:7] 欄標為 rd。

詳細說明

這 5 bits 對應 destination register field。和 [19:15]、[24:20] 一樣，它是 instruction 中的 register identifier 欄位，而不是 32-bit register data 本身。

例子（至少 2 個）

例 1｜MIN

MIN 的 [11:7] 是 rd，最後選出的較小 signed operand 對應寫到 rd。

例 2｜CPOP

CPOP 計算 rs1 中 1 的數量，結果對應到 [11:7] 所指定的 rd。

17[6:0]opcode 的 bit 位置⌄
位元範圍英文／全名：Instruction bits 6 through 0

HW1 中的依據

PDF tables 的最後一欄為 opcode；R-type standard format 中 opcode 是 7-bit field。本項 bit 位置用於幫助閱讀格式。

詳細說明

它是 instruction 的最低 7 bits。在 decode 中，通常先查看 opcode，再進一步看 funct3/funct7。

例子（至少 2 個）

例 1｜RV32IM

PDF 的 14 條 RV32IM operations 共用 opcode=0110011。

例 2｜CLZ

CLZ 的 opcode=0010011，與 ROL 的 0110011 不同。

18Register Field暫存器編號欄位⌄
概念專有名詞英文／全名：Register identifier field

HW1 中的依據

PDF 的 R-type format 包含 rs1、rs2、rd，並說 src_A_i/src_B_i/result_o 分別對應其資料。

詳細說明

Register field 是 instruction 中用來指定 register 的欄位；它與 register 裡的 32-bit data 是兩件事。這個區別對寫 ALU.sv 很重要，因為本 module 已直接收到 src_A_i/src_B_i。

例子（至少 2 個）

例 1｜rs1 vs src_A_i

rs1 是 instruction 的 5-bit register field；src_A_i 是對應 rs1 的 32-bit operand data。

例 2｜rd vs result_o

rd 是 instruction 中的 destination field；result_o 是 ALU 計算出的 32-bit result。

19Bit Field位元欄位⌄
格式基本名詞英文／全名：Bit Field

HW1 中的依據

PDF 明確說 ALU operation 由 instruction_i 的 corresponding fields decode，並以 funct7、[24:20]、[19:15]、funct3、[11:7]、opcode 等呈現。

詳細說明

Bit field 是一串連續 bits，被賦予特定語意。32-bit instruction 之所以能同時表達 operation 與 registers，就是因為不同 bit fields 各自承擔不同資訊。

例子（至少 2 個）

例 1｜funct7

[31:25] 共 7 bits，可作為 funct7 field。

例 2｜rs1

[19:15] 共 5 bits，PDF RV32B table 將其標示為 rs1。

20Bit Slicing位元切片⌄
RTL 背景名詞英文／全名：Selecting a bit range

HW1 中的依據

PDF 大量使用 rs2[4:0]、rs1[8i+7:8i]、product[63:32] 等寫法；PDF 沒有獨立定義「Bit Slicing」這個術語。

詳細說明

Bit slicing 是從一個較寬的 vector 取出特定位元範圍。這是解碼 instruction 與實作 ALU operation 時非常常見的 RTL 技巧。

例子（至少 2 個）

例 1｜shift amount

SLL 使用 rs2[4:0]，只取第二 operand 的最低 5 bits。

例 2｜MULH

64-bit product 只取 [63:32] 作為 MULH 的 32-bit result。

21Fixed Encoding固定編碼⌄
Decode 概念英文／全名：Fixed bit pattern

HW1 中的依據

PDF RV32B table 中 CLZ/CTZ/CPOP 的 [24:20] 分別固定為 00000/00001/00010；DSP unary ABS/CLIP8 的 rs2 field 必須為 00000。

詳細說明

固定編碼表示某個 field 在特定 instruction 中不是任意 register，而必須符合指定 bit pattern；decode 時若忽略它，可能把不同指令誤判。

例子（至少 2 個）

例 1｜CLZ vs CTZ

兩者 funct7、funct3、opcode 相同，但 [24:20] 分別 00000 與 00001。

例 2｜ABS

PDF notes 要求 unary ABS 的 rs2 field=00000；因此完整 decode 應尊重這項規格。

22R-type-like Custom Encoding類 R-type 自訂編碼格式⌄
DSP 專有名詞英文／全名：R-type-like custom encoding format

HW1 中的依據

PDF Notes 明確說 DSP instructions use the R-type-like custom encoding format，且 custom opcode=0001011。

詳細說明

它表示 DSP 指令沿用類似 R-type 的欄位思考方式，但屬於這份作業指定的 custom encoding。實作時應依 PDF 的 funct7/funct3/opcode 與 unary rs2 規則，不自行假設其他編碼。

例子（至少 2 個）

例 1｜DOTP4

funct7=0000000、funct3=000、opcode=0001011，使用 rs1 與 rs2 的四個 signed 8-bit lanes。

例 2｜CLIP8

funct7=0000000、funct3=100、opcode=0001011，而且作為 unary operation，rs2 field 必須為 00000。

23Decode Key解碼條件組合⌄
教學整理名詞英文／全名：Combination of instruction fields

HW1 中的依據

PDF 沒有使用「Decode Key」這個正式名稱；本項是把「decode corresponding fields」整理成容易實作的概念。

詳細說明

可以把 opcode + funct3 + funct7 + 必要固定欄位想成一組 decode key。重點不是這個名稱，而是不要只用單一欄位判斷所有 instructions。

例子（至少 2 個）

例 1｜SUB

可用 opcode=0110011 + funct3=000 + funct7=0100000 辨識。

例 2｜CTZ

需包含 opcode=0010011 + funct3=001 + funct7=0110000 + [24:20]=00001，才能與 CLZ/CPOP 區分。
