二、數位邏輯：Binary、Hex、補數、組合/循序

Binary / Hex / bit slicing

opcode = instruction[6:0];
funct3 = instruction[14:12];
funct7 = instruction[31:25];

RTL 是逐 bit 描述硬體，因此必須熟悉 bit range、concatenation、mask、shift。

Two's Complement

patternunsignedsigned
7FFFFFFF21474836472147483647
800000002147483648-2147483648
FFFFFFFF4294967295-1

這直接決定 SLT/SLTU、SRA、MULH、DSP signed lane 的正確性。

Combinational vs Sequential

ALU 主要是 combinational datapath；FPU 有 clk/rst/enable/valid，所以還要懂 flip-flop、clock edge、state/latency 與 handshake。

三、SystemVerilog / RTL 必備語法

概念用途

always_comb組合邏輯；所有路徑要完整賦值避免 latch。
always_ff @(posedge clk)clocked register/state。
caseinstruction decoder。
$signed(...)明確 signed interpretation。
{{N{x[MSB]}},x}sign extension 的典型概念。
<< / >> / >>>logical/arithmetic shifts。
=== / !==TB bit-exact compare，連 X/Z 都能辨識。

核心思維：SystemVerilog RTL 不是一般軟體流程，而是在描述實際資料路徑、mux、adder、register 與 control。

四、RISC-V Instruction Decode

instruction[31:0]→opcode→funct3→funct7/fields→Operation→Datapath

本作業 ALU 同時涵蓋 RV32IM、RV32B 與 Custom DSP，因此要會從 instruction fields 做階層式 decode，而不是只看一個 operation number。

六、Width / Signedness / Overflow

Operand width+Signedness→Expression width→Intermediate→Extend/Truncate→Result

這是 hidden test 與 lint 最常抓到的問題。high-word multiply 必須先以足夠寬度計算；常數也應注意 explicit sizing。看到 width warning 不應直接關掉。

FPU debug 時第一步就是把 A/B/EXP 拆成 S/E/F 並 classify。

八、FPU ADD/SUB Datapath

Unpack→Classify→Special?→Exp Compare→Align+Sticky→Mantissa +/-→Normalize→GRS/RNE→Pack

GRS

G=第一個捨棄 bit；R=第二個；S=其後所有捨棄 bits 的 OR。Round-to-nearest-even 可用 round_up = G & (R | S | LSB) 理解。GRS=100 是 exactly-halfway，因此還要看 LSB 決定是否進位到 even。

九、Testbench 與 Handshake

ALU

FPU

不讀 TB，就不知道資料何時送入、何時被取樣、valid 何時必須出現，也不知道 simulation hang 是算術錯還是控制錯。
