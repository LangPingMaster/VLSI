00-1｜Binary / Hex / 補數：VSD HW1 必備數字表示法

這一章專門補強寫 ALU/FPU 前最基本、也最容易造成 RTL 錯誤的數字觀念：二進位、十六進位、位元寬度、unsigned、signed two's complement、符號延伸、截斷、overflow。這些概念會直接出現在 SLT/SLTU、SRL/SRA、MULH、DSP 8-bit lane，以及 IEEE-754 的 bit-level 操作。

一、整體學習流程

Decimal↔Binary↔Hex→Fixed Width→Unsigned / Signed→Two's Complement→Extend / Truncate→RTL Arithmetic

二、Binary：電路真正看到的是 0 與 1

一個 N-bit unsigned binary number的每一位具有權重 2i。例如：

(101101)2 = 1×2⁵ + 0×2⁴ + 1×2³ + 1×2² + 0×2¹ + 1×2⁰ = 45
bit543210

weight32168421

對 32-bit RTL 而言，[31] 是最高位 MSB，[0] 是最低位 LSB。

logic [31:0] x;

x[0]        // LSB
x[7:0]      // 最低 8 bits
x[31:24]    // 最高 8 bits

−2ᴺ⁻¹ ～ 2ᴺ⁻¹ − 1

8-bit signed 範圍就是 -128 ～ +127；32-bit 是 -2147483648 ～ +2147483647。

七、為什麼補數可以讓加法器同時做正負數？

固定 N-bit 硬體實際上做的是 modulo 2ᴺ arithmetic。例如 8-bit：

  0000 0101   (+5)
+ 1111 1011   (-5)
-----------
1 0000 0000

第 9 個 carry 被 8-bit result 截掉，留下 0000_0000，正好是 0。這使同一套 binary adder 能處理 two's complement signed addition。

減法也可以變加法

A − B = A + (~B + 1)

這就是 two's complement 對 ALU 設計非常重要的原因。

八、Signed vs Unsigned：bit pattern 一樣，答案可以完全不同

考慮：

A = 32'hFFFF_FFFF
B = 32'h0000_0001
解讀ABA < B?
unsigned42949672951false
signed-11true

因此 RISC-V 的 SLT 與 SLTU 絕對不能使用相同的 comparison interpretation。

// signed compare 的概念
$signed(src_A_i) < $signed(src_B_i)

// unsigned compare 的概念
src_A_i < src_B_i

九、Zero Extension 與 Sign Extension

Zero extension

8'b1111_1011  →  16'b0000_0000_1111_1011
若原本視為 unsigned 251，擴展後仍是 251。

Sign extension

8'b1111_1011  →  16'b1111_1111_1111_1011
若原本視為 signed -5，擴展後仍是 -5。

sign extension 的本質是複製原本 MSB。DSP 8-bit signed lane、MULH/MULHSU 的 operand widening 都需要特別注意這件事。

十、Overflow 與 Truncation

Unsigned overflow

8'hFF + 8'h01 = 9'h100
若 result 只有 8 bits → 8'h00

Signed overflow

8'sd127 + 8'sd1

所以 RTL 中即使使用 >>>，也必須注意左 operand 是否真的具有 signed interpretation。

十二、乘法為什麼要注意 64-bit Intermediate？

兩個 32-bit operands 相乘，完整 product 最多需要 64 bits。MUL 只取低 32 bits；MULH 類則要高 32 bits。

32-bit A×32-bit B→64-bit Product→[63:32] / [31:0]

若 expression 在乘法當下已經因位寬規則失去高位，之後再 assign 到 64-bit variable 也無法恢復。因此要先設計 operand extension 與 product width。

十三、這些觀念如何直接用在 DSP？

32-bit operand 可拆成 4 個 8-bit lane：

[31:24] [23:16] [15:8] [7:0]
 lane3    lane2    lane1  lane0

若每個 lane 都是 signed two's complement，8'hFF 不是 255，而是 -1；8'h80 是 -128；8'h7F 是 +127。

十六、與 HW1 的直接連結

Binary/Hex→Instruction Fields→Signed/Unsigned→ALU→DSP Lanes→FPU Bit Fields

如果 Binary / Hex / Two's Complement 不熟，後面最常出現的情況就是：RTL 語法沒有錯、simulation 也能跑，但 SLT/SRA/MULH/DSP boundary 一直得到錯誤答案。
