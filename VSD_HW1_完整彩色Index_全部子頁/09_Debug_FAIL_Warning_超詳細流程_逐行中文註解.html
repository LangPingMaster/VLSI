09｜看到 FAIL / X / Hang / Warning：如何一步一步找到真正 Root Cause

Debug 的核心不是一直改 code 直到 PASS，而是：固定第一個失敗 → 分類症狀 → 建立最小重現 → 從 input 沿 datapath 找第一個錯掉的 signal → 修一般規則 → full regression。

一、Debug Master Flow

看到 Error/FAIL→保存第一筆訊息→分類：Compile / Path / X / Wrong / Hang / Lint→最小 testcase→FSDB

↓

Input 正確？→Decode/Classify 正確？→Intermediate 正確？→Output/Valid 正確？→找第一個錯訊號→修 Root Cause→Full Regression

二、第一件事：先分類，不要直接改 RTL

症狀代表什麼方向第一個檢查點
Compile error工具尚未建立 simulation第一個 syntax/module/port/include error
Cannot open CSV/include多半是 working directory/pathpwd、ls
Output X/Z未賦值、latch、driver、indexresult driver 與 combinational default
ALU GOT != EXPdecode 或 arithmetic/bit logicinst ID → opcode/funct3/funct7
FPU GOT != EXPclassify/alignment/arithmetic/normalize/round/pack先拆 S/E/F
FPU simulation hanghandshake/controlclk/rst/enable/valid/state
Lint warningRTL 結構/語意風險理解 warning，不先 lint_off

三、ALU FAIL：由 Instruction 一路追到 result_o

[FAIL] Inst 7 | A=... B=... Inst=... | GOT=... EXP=...
Inst ID→instruction hex→opcode/funct3/funct7→decoder branch→operand interpretation→intermediate width/sign→result_o
FAIL 特徵優先懷疑
SRA 像 SRL$signed / arithmetic shift signedness
SLT 負數比較錯signed compare
MULH/MULHSU high word 錯64-bit product 寬度與 sign extension 發生時機
shift 32 以上怪異是否只取 rs2[4:0]
DSP 某一 lane 錯8-bit slice/sign extension/per-lane saturation
result 是 Xcase default、always_comb 賦值完整性

四、FPU FAIL：不要直接看最後 32 bits

[FAIL] line=N A=........ B=........ GOT=........ EXP=........
A/B 拆 S/E/F→Classify→Special bypass?→Effective sign→Exp diff→Align+Sticky→Add/Sub→Normalize→GRS/RNE→Pack
症狀最值得先看
NaN/Inf/Zero 錯class flags 與 special-case mux priority
數值差非常大exponent alignment / effective operation
接近相消結果錯magnitude compare / leading-zero normalize
只差 1 ULPG/R/S、LSB、round_up
round 後 exponent 錯round carry 是否再次 normalize
一直不結束valid generation / FSM / reset

五、Lint Warning：要修「原因」，不是只讓訊息消失

例如 width-expand 類 warning 可能代表條件運算兩邊寬度不同，工具正在做 implicit extension。若 exponent 是 8-bit，常數與中間變數的 width 應明確設計；不要一看到 warning 就用 lint_off 隱藏。

Warning→定位 source line→理解 operands width/sign→判斷硬體語意→明確 cast/resize/default→Simulation regression→Lint again
類型典型 root cause修正方向
WIDTHEXPAND/TRUNC兩側位寬不同明確-sized constant / intermediate width
Signednesssigned 與 unsigned 混算在正確位置明確 cast
Latch組合路徑未完整賦值default assignment + 完整 branches
Undrivensignal 沒有來源追 driver/port/assignment
Unusedsignal 未使用確認是多餘還是漏接

六、Waveform Debug：找「第一個錯掉的訊號」

Console 第一筆 FAIL→定位 transaction/time→Inputs→Decode/Classify→Intermediate→Result

假設最後 co 錯，不要從 co 倒猜。若 exp_diff 已經錯，後面的 aligned mantissa、GRS、round、pack 全錯都是「後果」。真正 root cause 是 exp compare/alignment 前面的那一級。

七、建立最小 Debug Case：每行 Code 中文註解

下面兩段是額外的 debug helper，不是老師 official TB。用途是把 console 中的一筆 FAIL 固定下來，讓你每次修改 RTL 都能快速重現。

12 #10;註解：說明此段的 debug 目的，不直接形成硬體/執行動作。

B. FPU 單筆 Debug Task + Timeout

行Code / Command中文逐行註解
1// FPU debug helper：加入 timeout，避免 valid 永遠不來註解：說明此段的 debug 目的，不直接形成硬體/執行動作。
2task automatic debug_fpu_case(宣告可重複呼叫的 TB debug task，方便把單一 failing case 固定重現。
3 input logic [1:0] op,FPU operation code：0 MIN、1 MAX、2 ADD、3 SUB。
4 input logic [31:0] a_bits,輸入 A 的 32-bit bit pattern。
5 input logic [31:0] b_bits,輸入 B 的 32-bit bit pattern。
6 input logic [31:0] expected該 failing case 的 golden expected，用於 bit-exact compare。
7);此行是 debug task/command 的語法或資料控制，需與前後行一起理解。
8 int cycles;記錄等待 FPU valid 的 cycles，兼作 latency 與 timeout 計數。
9begin控制結構/task 區塊的結束或分支。
10 instruction <= op;設定 FPU operation。
11 a <= a_bits;送入 FPU A operand。
12 b <= b_bits;送入 FPU B operand。
13 start <= 1'b1;assert enable/start，建立一筆 FPU request。
14 空行：分隔不同程式或 debug 階段。
15 @(posedge clk);等待 rising edge，讓 DUT capture request 或推進 pipeline/FSM。
16 start <= 1'b0;request pulse 結束，避免同一筆資料被重複接受。
17 空行：分隔不同程式或 debug 階段。
18 cycles = 0;timeout counter 歸零。
19 while (!ready && cycles < 100) begin等待 valid/ready，同時限制最多 100 cycles，避免 simulation 永久 hang。
20 @(posedge clk);等待 rising edge，讓 DUT capture request 或推進 pipeline/FSM。
21 cycles++;每等待一個 clock cycle 累加 latency/timeout counter。
22 end控制結構/task 區塊的結束或分支。
23 空行：分隔不同程式或 debug 階段。
24 if (!ready)超過 timeout 仍無 valid：優先查 reset、enable、state、valid generation。
25 $display("[TIMEOUT] op=%0d A=%h B=%h", op, a_bits, b_bits);將 PASS/FAIL/X/TIMEOUT 或 debug fields 印到 simulator log。
26 else if (result !== expected)valid 到來後做 bit-exact compare，signed zero/NaN encoding 差異也能抓到。
27 $display("[FAIL] op=%0d A=%h B=%h GOT=%h EXP=%h",將 PASS/FAIL/X/TIMEOUT 或 debug fields 印到 simulator log。
28 op, a_bits, b_bits, result, expected);此行是 debug task/command 的語法或資料控制，需與前後行一起理解。
29 else控制結構/task 區塊的結束或分支。
30 $display("[PASS] result=%h latency=%0d cycles", result, cycles);將 PASS/FAIL/X/TIMEOUT 或 debug fields 印到 simulator log。
31end控制結構/task 區塊的結束或分支。
32endtask控制結構/task 區塊的結束或分支。

九、修完 Bug 後怎樣才算完成？

Step必做
1原本 failing testcase 已 PASS。
2同類 boundary/corner cases 一起測。
3ALU 官方 2326 筆重新 regression。
4FPU 官方 2000 筆重新 regression。
5Defense tests 重新 regression。
6Superlint 再跑一次，確認修改沒有引入新結構問題。
7課程指定環境最後重現。

Debug 最重要的一句話

不要問「我要改哪一行才能 PASS？」；先問「資料從哪一級開始第一次變錯？」。找到第一個錯誤 stage，才是在修 root cause。
