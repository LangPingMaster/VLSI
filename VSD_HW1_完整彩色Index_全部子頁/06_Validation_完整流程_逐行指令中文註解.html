06｜從 Compile 到 Regression：VSD HW1 完整驗證與 Debug 工作流程

這一章把「寫完 RTL 之後到底要做什麼」串成一條完整工程流程：先確認路徑，再 compile，再跑官方 regression；有錯就看 log/FSDB；功能通過後再跑 Superlint；最後補 defense tests，任何 RTL 修改都重新 regression。

一、整個作業 Validation Master Flow

完成/修改 RTL→確認目錄與檔案→Compile→Official Simulation→PASS?

FAIL ↓　　　　　　　　　　　　　　　　↓ PASS

讀第一筆錯誤→Verdi / FSDB→定位 Root Cause→修 RTL↺重新 Compile + Regression

全部 PASS ↓

Superlint→處理重要 Warning/Error→Defense Tests→Full Regression→SoC Lab 最終重跑→Ready to Submit

      └─ pattern_fpu.csv

TB 使用相對 include/path，因此最安全的工作位置是 StudentID_HW1/Sim。如果 $fopen 失敗或 include 找不到，先檢查 working directory，不要第一時間改 RTL。

四、Stage 1：Compile 到底在驗證什麼？

TB.sv+RTL.sv→Parser→Elaboration→Executable Simulation
Compile error 類型常見原因先檢查
Syntax error缺 ;、begin/end、case/endcase錯誤行附近
Cannot open include執行目錄或檔名錯pwd、ls ../Src
Unknown modulemodule 名稱不一致TB instance 與 RTL module
Port mismatchport 名稱/位寬不同DUT interface
Width/Signed warning運算元寬度或 signedness 不一致不要直接忽略，可能影響 hidden cases

Compile 成功 ≠ 功能正確。它只代表工具可以建立可模擬的設計。

五、Stage 2：Official Regression

ALU：2326 patterns

CSV→TB drive inst/A/B→ALU combinational→#10→result vs expected

FAIL 時先記下 inst_id、instruction、A、B、GOT、EXP。第一筆錯誤通常最有定位價值。

FPU：2000 patterns

CSV→enable pulse→FPU→wait valid→co vs expected

若 simulation 不往下走，先看 valid/FSM；若差 1 ULP，再看 GRS/RNE。

Debug 不要只盯最後的 result。真正有效的方法是找「第一個開始和預期不同的中間訊號」。

七、Stage 4：Superlint

superlint.tcl→Read RTL→Elaborate→Static Rules→Warning/Error→修 RTL→重跑 Simulation
Lint 類型可能代表為何值得處理
WIDTH兩側位寬不同截斷/擴展可能改變算術結果
SIGNEDNESSsigned/unsigned 混用SLT、MULH、DSP、FPU 中間算術容易出錯
LATCH組合區塊未完整賦值ALU 不應意外保留前值
UNDRIVEN訊號沒有 driversimulation 可能出 X
UNUSED訊號/邏輯沒被使用可能是接錯或多餘程式

八、Stage 5：Defense Regression

Official PASS 只證明公開 patterns 通過。Hidden test defense 應補 boundary partitions：

ALUFPU
shift=0/1/31
signed vs unsigned extrema
MUL high word
CLZ/CTZ zero
bit index 0/31
DSP ±128/127 saturation
ABS 0x80000000		+0/-0
NaN/Inf
subnormal
large exponent difference
cancellation
GRS tie-even
round carry
overflow/underflow boundary

每次修 bug 都要重新跑：原本會失敗的 case + official regression + defense regression + lint，避免修 A 壞 B。

九、驗證 Command：每一行後面中文註解

行Command中文說明
1# 0. 進入作業的 Sim 目錄步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
2cd StudentID_HW1/Sim切換到 Sim 目錄。TB 的 include 與 CSV 使用相對路徑，因此執行位置很重要。
3 空行：分隔不同驗證階段。
4# 1. 確認目前位置與檔案步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
5pwd顯示目前工作目錄；先確認真的位於 StudentID_HW1/Sim。
6ls列出 Sim 目錄內容，確認 ALU_tb.sv、FPU_tb.sv 等檔案存在。
7ls ../Src確認上一層 Src 內存在 ALU/FPU RTL，避免 include 找不到。
8ls ./pattern確認 pattern CSV 位於 TB 預期的相對路徑。
9 空行：分隔不同驗證階段。
10# 2. ALU：VCS compile + simulation + FSDB步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
11vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDB編譯並執行 ALU testbench；-R 代表 compile 後直接 run，+define+FSDB 啟用 TB 波形 dump。
12 空行：分隔不同驗證階段。
13# 3. FPU：VCS compile + simulation + FSDB步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
14vcs -R -full64 -sverilog FPU_tb.sv -debug_access+all +define+FSDB編譯並執行 FPU testbench；FPU TB 會依 enable/valid handshake 逐筆驗證。
15 空行：分隔不同驗證階段。
16# 4. 開啟 ALU waveform步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
17verdi -ssf ALU.fsdb &用 Verdi 開啟 ALU.fsdb，追 instruction/A/B/result 與 decoder 相關訊號。
18 空行：分隔不同驗證階段。
19# 5. 開啟 FPU waveform步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
20verdi -ssf FPU.fsdb &用 Verdi 開啟 FPU.fsdb，追 enable/valid、IEEE-754 datapath、GRS/rounding 等訊號。
21 空行：分隔不同驗證階段。
22# 6. 執行 Superlint步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
23jg -superlint superlint.tcl啟動 JasperGold Superlint 並執行 superlint.tcl，做 static RTL 檢查。
24 空行：分隔不同驗證階段。
25# 7. 修正 RTL 後重新 regression步驟註解，用來標示目前 verification stage；Shell 不執行此行內容。
26vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDB編譯並執行 ALU testbench；-R 代表 compile 後直接 run，+define+FSDB 啟用 TB 波形 dump。
27vcs -R -full64 -sverilog FPU_tb.sv -debug_access+all +define+FSDB編譯並執行 FPU testbench；FPU TB 會依 enable/valid handshake 逐筆驗證。
28jg -superlint superlint.tcl啟動 JasperGold Superlint 並執行 superlint.tcl，做 static RTL 檢查。

課程原始說明提供的核心指令是 VCS simulation 與 jg -superlint superlint.tcl。Verdi 指令在此作為查看已產生 FSDB 的實務 debug 流程；實際工具環境與指令選項仍以 SoC Lab/TA 最新設定為準。

十、看到錯誤後不要亂改：Decision Flow

症狀第一步第二步
Compile fail看第一個 compiler error修 syntax/path/module/port
CSV open failpwd確認 ./pattern 路徑
ALU X看 decoder/default assignment查 latch/undriven
ALU wrong answer解碼第一筆 FAIL instruction追 intermediate/signedness/width
FPU hang看 enable/valid/state確認 transaction 能結束
FPU 差 1 ULP看 G/R/S/LSB查 tie-even/round carry
Lint warning理解 warning 對硬體的實際意義修 RTL 後重新 simulation

十一、什麼時候才算真的完成？

Checkpoint完成條件
Directory從指定目錄可找到 RTL/TB/CSV/TCL。
CompileALU/FPU 都可成功 compile/elaborate。
ALU official2326 筆公開 patterns 全部通過。
FPU official2000 筆公開 patterns 全部通過且 valid protocol 不 hang。
Waveform可以產生/開啟 FSDB，知道如何定位第一筆 fail。
Superlint完成 lint，理解並處理關鍵問題。
Defense自行補的 boundary/corner cases 通過。
Regression最後一次 RTL 修改後，全套重新跑過。
Environment在課程要求的 SoC Lab 環境可重現。

一句話記住整個流程

先讓工具讀得懂 → 再讓公開測資全對 → 用 waveform 找 root cause → 用 lint 找結構風險 → 用 corner tests 防 hidden → 最後全套重跑。
