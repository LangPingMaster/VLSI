07｜Hidden Test Defense：從公開 Pattern 擴展到完整規格空間

Hidden test defense 的目標不是猜老師的 hidden CSV，而是把公開測資未必覆蓋的 boundary、corner、signedness、rounding、special-value 與 protocol 狀況主動補齊。這份新版把「想到 corner case」進一步變成可以實際執行的工程流程。

一、Hidden Defense Master Flow

讀規格→整理 Operation→切 Input Partitions→列 Boundary→Directed Tests→Random/Differential

↓

出現 FAIL→縮小到最小 Reproducer→FSDB 找第一個錯訊號→修 RTL Root Cause→Official + Defense + Lint 全部重跑

二、Hidden Test 正確觀念

老師沒有提供 hidden CSV，所以不能聲稱「hidden test 已經 PASS」。你能做的是建立 coverage-oriented defense：對每一類 operation 主動問「哪個輸入 partition 最容易讓目前寫法失效？」

錯誤方法正確方法
猜老師會出哪 10 題依規格建立等價類別與邊界
看到公開 pattern PASS 就停止補公開 pattern 不保證覆蓋的 cases
為某一筆 FAIL hard-code修正 decoder/datapath/rounding 的一般規則
只跑新 case修 bug 後 official + defense 全 regression

五、如何自己「系統化生出」Hidden Defense Cases？

選 operation→找規格分支→每個分支找邊界→邊界 -1 / 邊界 / 邊界 +1→交叉 signed/special cases→建立 golden

例如 SADD8 的合法 signed 8-bit 範圍是 -128..127，因此至少要測 126+1、127+0、127+1，以及 -127-1、-128+0、-128-1；再把四個 lane 故意放成「有的 overflow、有的不 overflow」，才能抓到錯誤的整體 saturation 寫法。

七、Random / Differential Testing

Random A/B/op→Reference Model→Golden↘Bit-exact Compare→Mismatch 保存 seed/case
同一 A/B/op→RTL Simulation→DUT Result↗

ALU reference model 相對直接；FPU 則要特別小心。Host language 的 float 對 NaN payload、signed zero、rounding 與特殊值處理未必和作業 golden 完全一致，所以 reference model 必須先固定「作業規格」的 bit-level policy。

八、實際完成作業的 Hidden-Defense 工作流程

Step工作完成判準
1先讓 official ALU/FPU regression 通過。公開 patterns 沒有已知 FAIL。
2依本頁 matrix 為每個 operation 建 partitions。不是只測一般值。
3先寫 directed tests。每個 boundary 都有明確 expected。
4FAIL 時縮成最小 testcase。一筆 input 就能穩定重現。
5開 FSDB，找第一個錯的 intermediate signal。找到 root cause 所在 stage。
6修一般規則，不 hard-code testcase。同類 cases 一起被修好。
7加入 random/differential。擴大手工 directed tests 之外的 coverage。
8每次修改後重跑 official + defense + lint。沒有 regression。
9在 SoC Lab 指定環境做最後驗證。結果可重現。

最後觀念

Hidden defense 的成功標準不是「我猜中了老師的 hidden test」，而是「我的 RTL 對規格中的每個重要 partition 都有理由相信是正確的，而且每次修正都有 regression 保護」。
