03｜ALU：從規格 → Decoder → Datapath → RTL → Testbench → Hidden Test

本頁以你提供的 03 原始頁為基礎擴充。原頁的核心方向是先拆 opcode/funct3/funct7，為 MUL 與 DSP 規劃足夠 intermediate width，並使用 always_comb + default assignment 建立安全的 combinational ALU。

一、Problem A 最終目標

你的 ALU 接收 instruction_i + src_A_i + src_B_i，直接產生 result_o。依前一章 TB contract，老師改變三個 inputs 後只等待 #10 就比對，所以 ALU 不應依賴 clock/valid。

instruction_i→Field Split→Decoder→Operation Datapath→32-bit MUX→result_o

三、Instruction decoder 為什麼要分層？

FieldBits用途
opcode[6:0]先辨識 instruction family。
funct3[14:12]family 內的 operation selector。
funct7[31:25]區分 ADD/SUB、SRL/SRA、M-extension、RV32B。
subop[24:20]CLZ/CTZ/CPOP 額外固定欄位。
shamtsrc_B_i[4:0]RV32 shift/rotate/bit-index 0~31。

只用 funct3 decode 是不夠的。例如 ADD/SUB funct3 都是 000；SRL/SRA 都是 101。一定要搭配 funct7。

四、31 個 Operations 應該怎麼分群開發？

RV32IM：14

ADD、SUB、SLL、SLT、SLTU、XOR、SRL、SRA、OR、AND、MUL、MULH、MULHSU、MULHU。

重點：signedness、shamt、64-bit multiplication。

RV32B：12

CLZ、CTZ、CPOP、ROL、ROR、MIN、MAX、MINU、MAXU、BSET、BCLR、BEXT。

重點：subop、signed vs unsigned、rotate=0、bit index=31。

Custom DSP：5

DOTP4、SADD8、SSUB8、ABS、CLIP8。

重點：signed 8-bit lanes、per-lane saturation、ABS INT_MIN、CLIP sign extension。

類型Intermediate width為什麼
MUL/MULH64 bits先保留完整 product 才能正確取得 high half。
MULHSU顯式 signed/unsigned extensionmixed signedness 是 SystemVerilog 常見陷阱。
SADD8/SSUB8每 lane 至少 9-bit signed8-bit 加減先 overflow 再 saturation 就來不及。
DOTP4每 product 至少 16-bit signed + 足夠 accumulator四組 signed 8×8 product 再相加。

六、DSP 三個最容易寫錯的 operation

SADD8 / SSUB8：四個 lane 必須各自 saturation

// lane k 的概念
a9  = sign_extend(A[8*k +: 8]);   // 8-bit signed → 9-bit
b9  = sign_extend(B[8*k +: 8]);   // 8-bit signed → 9-bit
tmp = a9 + b9;                     // SADD8；SSUB8 改成 a9-b9

if (tmp > 127)       lane = 8'h7f;
else if (tmp < -128) lane = 8'h80;
else                 lane = tmp[7:0];

不能先用 8 bits 算完再判斷，因為 overflow 已經發生。例如 100+50 的 8-bit two's-complement 會 wrap；正確流程是先擴寬，再比較 +127/-128。

DOTP4

A0 = signed(A[7:0]);    B0 = signed(B[7:0]);
A1 = signed(A[15:8]);   B1 = signed(B[15:8]);
A2 = signed(A[23:16]);  B2 = signed(B[23:16]);
A3 = signed(A[31:24]);  B3 = signed(B[31:24]);

P0=A0*B0; P1=A1*B1; P2=A2*B2; P3=A3*B3;
SUM = P0 + P1 + P2 + P3;

四個 byte 都要獨立解讀為 signed two's-complement；不要把整個 32-bit A/B 當成一個 signed number 相乘。

九、FAIL 時怎麼由 log 追到 root cause？

記下 Inst ID→看 Inst Hex→拆 opcode/funct3/funct7→確認 decoder branch→檢查 signed/width→看 result vs EXP
症狀最可能原因

SLT/SLTU 其中一個錯signed/unsigned comparison 混用。
SRL pass、SRA 負數錯沒有 $signed 或用了 >> 而非 >>>。
MUL pass、MULH 錯product intermediate width/sign 錯。
rotate 只有 shamt=0 錯complementary shift 產生 shift-by-32 問題。
SADD8 邊界錯8-bit 先 overflow，沒有用 9-bit temporary。

十、Hidden Test Defense

Hidden test 無法靠「知道 hidden CSV」解決。防守方式是讓每一類 operation 的等價類、邊界值、signedness 與 width都被你自己的 directed tests 覆蓋。

Operation一定補測
Shift/Rotate0、1、31
Signed compare0x80000000、0xffffffff、0、1、0x7fffffff
MULH*+/+、+/−、−/+、−/−、INT_MIN
CLZ/CTZ/CPOP0、all ones、single-one at bit0/31
BSET/BCLR/BEXTindex 0、31
DSP每 lane 的 127、128、−128、−129 等邊界概念與 mixed lanes
ABS0、1、−1、0x80000000
