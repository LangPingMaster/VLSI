00-5｜DSP：DOTP4 / SADD8 / SSUB8 / ABS / CLIP8 超詳細教學

本章專門處理 VSD HW1 的 Custom DSP Extension。依作業規格，DSP 使用 opcode=0001011、funct7=0000000，再以 funct3 區分五個 operations。最核心的觀念是：DOTP4、SADD8、SSUB8 都必須把 32-bit operand 視為四個 signed 8-bit elements，而 SADD8/SSUB8 的 saturation 更必須逐 lane 獨立完成。

instruction→opcode=0001011?→funct7=0000000?→funct3→DOTP4 / SADD8 / SSUB8 / ABS / CLIP8→result_o

src_B_i = { B3[31:24], B2[23:16], B1[15:8], B0[7:0] }

因此若 lane 是 8'hFF，DSP arithmetic 必須把它當成 -1，不是 255。這也是為什麼 lane extraction 後要明確處理 signedness。

三、DOTP4：四組乘法再相加

DOTP4 = A0×B0 + A1×B1 + A2×B2 + A3×B3
A0×B0A1×B1A2×B2A3×B3→Signed Accumulator→32-bit result

8-bit signed × 8-bit signed 的完整 product 要保留足夠位寬；四個 products 相加時 accumulator 也不能過早截斷。最常見錯誤是 lane 被當 unsigned，或 multiplication/accumulation intermediate 太窄。

手算例子

A lanes = [  1,  -2,   3,  -4 ]
B lanes = [  5,   6,  -7,  -8 ]

DOTP4
= 1×5 + (-2)×6 + 3×(-7) + (-4)×(-8)
= 5 - 12 - 21 + 32
= 4

四、SADD8：不是一般 32-bit ADD

A0+B0A1+B1A2+B2A3+B3→各自 Saturate→Pack 4×8-bit

signed 8-bit range 是 -128～127。因此每個 lane 要先用至少 9-bit intermediate 算出真實和，再判斷：

if sum >  127 → output lane =  127 = 8'h7F
if sum < -128 → output lane = -128 = 8'h80
otherwise     → output lane = sum[7:0]
運算一般 8-bit wrapSADD8 saturation
127+1-128127

-128 + (-1)127-128
-20+10-10-10

關鍵：lane0 overflow 不可以影響 lane1。四個 lane 是四個獨立的小型 saturating adders。

temp_i = Ai - Bi

temp_i < -128 → -128

SADD8 與 SSUB8 最好共用同一個「signed 9-bit intermediate → saturate → 8-bit」觀念。

六、ABS：最危險的是 0x80000000

一般概念：

A >= 0 → A
A <  0 → -A

但 32-bit signed two's complement 的範圍是不對稱的：最小值是 -2147483648，而最大正數只有 +2147483647。因此 32'h80000000 沒有對應的正 32-bit signed magnitude。依本作業規格：

ABS(32'h80000000) = 32'h7FFFFFFF

所以這個 case 必須明確放在一般負數 negation 之前。

七、CLIP8：把 32-bit signed value 限制到 8-bit signed range

signed A→A > 127?Yes+127；No →A < -128?Yes-128；No →A→32-bit sign extension

規格特別指出 CLIP8 的結果要以 32-bit sign-extended result 輸出。

八、Saturation 的硬體思考

8-bit signed A/B→先擴成較寬 signed→9-bit Add/Sub→>127 / <-128?→7F / 80 / 原結果

若你先用 8-bit variable 計算，overflow 可能已經 wrap，之後再比較就太晚。例如 127+1 若先截成 8-bit 已經變成 -128，這時你再問「是否 >127？」永遠抓不到原本的 overflow。因此 先 widen、再算、再 saturate、最後 truncate/pack。

FAIL row→確認 DSP decode→拆 A0~A3/B0~B3→signed decimal 檢查→看 widened intermediate→saturation decision→pack/result_o
症狀Root cause 候選

CLIP8(-1)=000000FF漏做 32-bit sign extension；應為 FFFFFFFF

十二、一張圖記住 DSP

32-bit A/B→Signed interpretation→必要時切 4×8-bit lanes→Widen intermediate→Calculate→Saturate / Special Case→Pack / Sign Extend→result_o

最重要的一句：SADD8/SSUB8 不是「32-bit 加減後再 clip」，而是 四組獨立 signed 8-bit arithmetic，每一組各自 saturation，再 pack 回 32-bit。
