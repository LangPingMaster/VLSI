一、這一章的核心

FPU 和 ALU 最大差別是：FPU TB 不是「放 input 等 #10 就直接看 output」，而是 clocked transaction。TB 會先 pulse enable，然後等待 DUT 的 valid，valid 到來時才擷取 co 與 CSV golden answer 做 bit-exact compare。

二、FPU 四種檔案各自目的

檔案角色主要工作是否合成成硬體
FPU(3).svDUT RTLMIN/MAX/ADD/SUB、IEEE-754 datapath、valid protocol是
FPU_tb(3).svSimulation driver/checkerclock/reset、讀 CSV、pulse enable、wait valid、compare否
pattern_fpu(3).csvStimulus + Golden answerA、B、Expected、Instruction否
superlint(2).tclLint tool control script讀 RTL、elaborate、執行 static checks否

三、TB.sv、FPU.sv、TCL 相互運作流程圖

A. Simulation：功能是否正確？

pattern_fpu.csv→FPU_tb.sv→A/B/ins + enable→FPU.sv→co + valid→TB bit-exact compare→PASS/FAIL + FSDB

B. Superlint：RTL 結構是否健康？

superlint.tcl→Read/Analyze→FPU.sv→Elaborate→Static/Lint checks→Warnings/Errors

TCL 不會取代 FPU_tb；兩者是兩條不同驗證路徑，共同檢查同一份 FPU RTL。

五、FPU TB Transaction 時序圖

時間 / Clock        ─────┐   ┌─────┐   ┌─────┐   ┌─────┐
                         └───┘     └───┘     └───┘
enable/start        ____████___________...____________
A/B/instruction     ----[ 本筆輸入保持 ]----------------
                         ↑
                    DUT 可在此 posedge capture
valid/ready         _____________...________████_______
co/result           ------------------------[結果]------
                                             ↑
                                      TB 擷取並 compare

關鍵 contract：co 正確穩定時，valid 必須被 assert。 TB 使用 while(!ready) 等待，所以 valid 永遠不來會造成 simulation 卡住。

九、實際如何完成 FPU 作業

Step工作完成標準
1先確認 FPU module ports、include path、CSV path。TB 可以 compile 且 CSV 成功開啟。
2完成 reset/enable/valid shell。送一筆 request 後 valid 一定能在有限 cycles 出現。
3完成 IEEE-754 unpack/classify。Normal/Zero/Subnormal/Inf/NaN 能正確分類。
4先做 MIN/MAX。instruction 0/1 patterns 通過。
5完成 ADD/SUB alignment、magnitude arithmetic、normalize。一般 normal cases 正確。
6加入 GRS + round-to-nearest-even。不再出現大量差 1 ULP。
7加入 special cases / range boundaries。NaN/Inf/zero/subnormal 等符合題目/pattern。
8跑完整 2000 筆 CSV。500 MIN + 500 MAX + 500 ADD + 500 SUB 全部通過。
9執行 Superlint TCL，處理關鍵 warnings。width/latch/undriven/unreachable 等問題處理完成。
10在課程指定環境重新跑 simulation + lint。結果可重現後再提交。

Debug 時最重要的三件事

① TB 卡住：先看 valid，而不是先懷疑 floating-point 算式。② 結果差 1 ULP：先看 G/R/S、LSB 與 round_up。③ NaN/Inf/Zero 錯：先看 classify 與 special-case mux priority。
