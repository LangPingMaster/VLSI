00-3｜RISC-V Decode：如何從 instruction 分辨 Operation？

本頁直接以這份 VSD HW1 規格為基礎。ALU 收到的是完整 instruction_i[31:0]，不是已經解碼好的 ALU operation；因此第一件事就是從 instruction 的固定 bit fields 擷取 opcode、funct3、funct7，再逐層決定要執行哪個 datapath。

一、你真正要完成的事情

instruction_i[31:0]→取欄位→opcode：大分類→funct3：子分類→funct7 / 特定欄位：再區分→Operation→result_o

最重要觀念：不能只看 funct3，也不能只看 opcode。例如 ADD 與 SUB 的 funct3 都是 000，但 funct7 不同；SRL 與 SRA 也有相同 funct3=101，必須再看 funct7。

二、R-type 32-bit Instruction 欄位

31 ───── 25 | 24 ─ 20 | 19 ─ 15 | 14 ─ 12 | 11 ─ 7 | 6 ─── 0
funct7　　rs2　　 rs1　　 funct3　　 rd　　 opcode
FieldBits在本 HW1 的角色
opcode[6:0]第一層分類；例如 0110011 的 RV32IM/RV32B register operations，以及 0001011 的 Custom DSP。
rd[11:7]ISA 中目的 register 編號；本 ALU module 直接輸出 result_o，所以主要用於 instruction encoding。
funct3[14:12]第二層 operation selector。
rs1[19:15]來源 register 編號；真正 rs1 資料由 src_A_i 提供。
rs2 / [24:20][24:20]一般 R-type 是 rs2；某些 RV32B unary encoding 此欄位是固定 pattern。
funct7[31:25]再區分 ADD/SUB、SRL/SRA、M-extension、Bitmanip 等。

非常重要：instruction_i[19:15] 是「rs1 編號」，而 src_A_i 才是 rs1 register 中的 32-bit 資料；同理 src_B_i 是 rs2 的資料。

三、Decode 的正確層級

Step 1：opcode→Step 2：funct3→Step 3：funct7 / [24:20]→唯一 Operation→選 Datapath

你可以把 decoder 想成樹，而不是一張平面的巨大 if：

opcode
├─ 0110011
│  ├─ funct3=000
│  │  ├─ funct7=0000000 → ADD
│  │  ├─ funct7=0100000 → SUB
│  │  └─ funct7=0000001 → MUL
│  ├─ funct3=001
│  │  ├─ funct7=0000000 → SLL
│  │  ├─ funct7=0000001 → MULH
│  │  ├─ funct7=0110000 → ROL
│  │  └─ ...
│  └─ ...
├─ 0010011
│  └─ funct7=0110000, funct3=001, [24:20]=00000/00001/00010
│     → CLZ / CTZ / CPOP
└─ 0001011
   └─ funct7=0000000, funct3=000..100
      → DOTP4 / SADD8 / SSUB8 / ABS / CLIP8

CLZ/CTZ/CPOP 特別值得注意：它們不是一般「兩個 register operands 的 R-type」用法；規格表明 [24:20] 使用固定值來區分三者，因此 decoder 必須真的檢查這個欄位。

六、Custom DSP Decode

Instopcodefunct7funct3
DOTP400010110000000000
SADD800010110000000001
SSUB800010110000000010
ABS00010110000000011
CLIP800010110000000100

所以 DSP 可以先用 opcode==0001011 進入 DSP family，再確認 funct7==0000000，最後用 funct3 選 DOTP4/SADD8/SSUB8/ABS/CLIP8。

七、用官方 pattern 的 instruction hex 實際拆解

Example 1：002081B3

instruction = 32'h002081B3
opcode = instruction[6:0]   = 0110011
funct3 = instruction[14:12] = 000
funct7 = instruction[31:25] = 0000000
→ ADD

Example 2：402081B3

instruction = 32'h402081B3
opcode = 0110011
funct3 = 000
funct7 = 0100000
→ SUB

這兩個 instruction 的 funct3 完全相同；真正把 ADD 與 SUB 分開的是 funct7。這就是「不能只看 funct3」最直接的例子。

Example 3：002091B3

opcode = 0110011
funct3 = 001
funct7 = 0000000
→ SLL

八、SystemVerilog Decoder 教學骨架：每行中文註解

注意：以下是「decode 教學骨架」，刻意沒有填完全部 31 個 datapath，不應直接視為作業 golden ALU。目的在學會如何把欄位逐層解碼。

2logic [2:0] funct3;宣告 3-bit funct3；常作為第二層 operation selector。
3logic [6:0] funct7;宣告 7-bit funct7；R-type 中可再區分 ADD/SUB、SRL/SRA、M-extension 等。

5always_comb begin開始 combinational decoder/datapath；instruction 或 operands 改變時重新計算。

7 funct3 = instruction_i[14:12];擷取 instruction[14:12] 作為 funct3。
8 funct7 = instruction_i[31:25];擷取 instruction[31:25] 作為 funct7。
9 空行：用來分隔 decoder 層級，提高可讀性。
10 result_o = 32'b0;先給 result_o default，確保未命中 branch 時仍有確定值，避免 unintended latch/X。
11 空行：用來分隔 decoder 層級，提高可讀性。
12 case (opcode)第一層 decoder：先依 opcode 判斷屬於哪一類 instruction。
13 7'b0110011: begin依本作業規格，0110011 包含 RV32IM 多個 R-type operation，也包含多個 RV32B register operation。
14 case ({funct7, funct3})第二/三層 decode：將 funct7 與 funct3 組合起來區分 operation。
15 {7'b0000000, 3'b000}: result_o = src_A_i + src_B_i;ADD：funct7=0000000、funct3=000，結果 A+B。
16 {7'b0100000, 3'b000}: result_o = src_A_i - src_B_i;SUB：同 funct3=000，但 funct7=0100000，因此不能只看 funct3。

九、Decoder FAIL 時怎麼 Debug？

CSV instruction hex→instruction_i waveform→opcode→funct3→funct7/[24:20]→decoder branch→result_o
症狀優先檢查
ADD 正確、SUB 錯funct7=0100000 是否被 decode。
SRL 正確、SRA 錯funct7 + signed arithmetic shift。
MUL 正確、MULH 錯decode 之外還要查 64-bit width/signedness。
CLZ/CTZ/CPOP 混在一起[24:20] 固定值是否有 decode。
DSP 全部沒進去opcode 0001011。
某合法指令 result=0是否落入 default；把 opcode/funct3/funct7 印出。

十、學完後應該能回答

#問題答案
1opcode 位在哪？[6:0]
2funct3 位在哪？[14:12]
3funct7 位在哪？[31:25]
4ADD/SUB 為何不能只看 funct3？兩者 funct3 都是 000，要靠 funct7 分辨。
5SRL/SRA 同理看什麼？funct3=101 相同，funct7 不同。

9Decoder 本質上綜合成什麼？比較/控制邏輯 + mux/datapath selection。
10Debug decoder 第一件事？從 failing instruction 拆 opcode/funct3/funct7/[24:20]，確認進入哪個 branch。
