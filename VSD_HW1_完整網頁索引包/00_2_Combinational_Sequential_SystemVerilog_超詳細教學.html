00-2｜Combinational / Sequential + SystemVerilog 超詳細先修

這一章回答最重要的問題：「=、<=、always_comb、always_ff 到底差在哪？」，並把它連到 VSD HW1 的 ALU 與 FPU。你要建立的不是「語法背誦」，而是 SystemVerilog code → hardware structure → timing behavior 的對應。

一、先建立總觀念：RTL 在描述硬體

Specification→Combinational?或Sequential?→always_comb / always_ff→Synthesis→Mux / Adder / Logic / Register

軟體程式通常想的是「CPU 依序執行第 1 行、第 2 行」。RTL 更重要的是問：這一段 code 最後要形成什麼電路？訊號是在同一個時間由組合邏輯傳遞，還是要等 clock edge 才保存？

二、Combinational Logic：輸出只由「目前輸入」決定

Y(t) = f(Input(t))

組合邏輯沒有「記住上一拍」的需求。典型硬體包括 AND/OR/XOR、adder、comparator、mux、decoder、ALU datapath。

always_comb begin
    result_o = 32'b0;
    case (operation)
        ADD: result_o = src_A_i + src_B_i;
        SUB: result_o = src_A_i - src_B_i;
        XOR: result_o = src_A_i ^ src_B_i;
        default: result_o = 32'b0;
    endcase
end
行為硬體理解
A/B/operation 改變經 propagation delay 後 result 跟著改變
不需要 clock沒有 register 才能運作
所有 branch 都賦值避免意外推導 latch

三、Sequential Logic：輸出與「過去狀態」有關

State(t+1) = f(State(t), Input(t))

Sequential logic 必須保存狀態，典型硬體是 flip-flop/register、counter、FSM、pipeline register。

always_ff @(posedge clk) begin
    if (rst) begin
        valid <= 1'b0;
        state <= IDLE;
    end else begin
        valid <= next_valid;
        state <= next_state;
    end
end
Inputs / Current State→Combinational Next-State Logic→D→ clock edgeRegister Q→New State

五、Blocking「=」與 Nonblocking「<=」

Blocking assignment：=

always_comb begin
    temp = a + b;
    y    = temp ^ c;
end

在 procedural simulation semantics 中，第一個 assignment 更新 temp 後，下一行使用更新後的 temp。這種寫法適合表達組合計算步驟。

Nonblocking assignment：<=

always_ff @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
end

在同一個 clock edge，右邊先依 edge 前的值求值，更新排到 nonblocking update。硬體意義接近兩級 register：

d→FF q1→FF q2

因此 q2 在這一拍取得的是舊 q1，不是剛更新的新 q1。

六、為什麼 = / <= 用錯會造成 simulation 行為完全不同？

Sequential 正確典型

always_ff @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
end

edge 後：q1←舊 d；q2←舊 q1。

不建議用 blocking 描述這種 register chain

always @(posedge clk) begin
    q1 = d;
    q2 = q1;
end

procedural simulation 中 q1 先立刻改成 d，接著 q2 讀到新 q1，容易失去原本「兩級 FF」想表達的時序意義。

七、always_comb / always_ff / assign

寫法適用例子
assign y = a & b;簡單 continuous combinational assignmentAND、簡單 expression
always_comb較複雜 combinational procedural logicALU decoder、mux、next-state
always_ff @(posedge clk)flip-flop/registerstate、counter、valid、pipeline register

always_comb 會比傳統 always @(*) 更清楚表達「這應該是組合邏輯」的設計意圖；always_ff 則清楚表達「這是 flip-flop」。

八、最重要的 Combinational 陷阱：Latch

有問題

always_comb begin
    if (enable)
        y = a;
end

當 enable=0 時，y 沒被指定新值。若要求 y 保持舊值，就需要「記憶」，工具可能指出 latch 問題。

常見修法：先給 default

always_comb begin
    y = 32'b0;
    if (enable)
        y = a;
end
進入 always_comb→先給 default→case/if 覆蓋需要的結果→每條 path 都有值→No unintended latch

九、case / if 如何變成硬體？

always_comb begin
    result = 32'b0;
    case (op)
        2'b00: result = a + b;
        2'b01: result = a - b;
        2'b10: result = a ^ b;
        2'b11: result = a & b;
    endcase
end

不要只把它想成「程式分支」。綜合後更接近：

AdderSubtractorXORAND→MUX controlled by op→result

所以 ALU decoder 本質就是控制哪一條 datapath 被選到 output。

十、Clock、Reset、Enable

always_ff @(posedge clk) begin
    if (rst) begin
        valid <= 1'b0;
        co    <= 32'b0;
    end else if (enable) begin
        valid <= 1'b1;
        co    <= calculated_result;
    end else begin
        valid <= 1'b0;
    end
end
Signal概念
clk決定 sequential state 何時更新。
rst把 state/register 帶回已知狀態。
enable決定是否接受/處理一筆 transaction。
valid告訴外部目前 output 是否有效。

真正作業必須配合官方 FPU TB 的 handshake，而不是直接照這個教學片段複製。

十一、FSM：複雜 Sequential Control 的標準思考方式

Current State Register→Next-State Combinational Logic→Next State→ clockState Register
always_comb begin
    next_state = state;
    case (state)
        IDLE: if (enable) next_state = CALC;
        CALC:             next_state = DONE;
        DONE:             next_state = IDLE;
    endcase
end

always_ff @(posedge clk) begin
    if (rst)
        state <= IDLE;
    else
        state <= next_state;
end

這種「next-state combinational + state register sequential」的拆法非常適合理解 FPU control。

十二、直接連到 VSD HW1：ALU 與 FPU 怎麼分？

ALU

instruction_isrc_A_isrc_B_i→Decode + Datapath (Combinational)→result_o

ALU 沒有 clk/rst/valid interface，因此核心思路是 combinational decoder + datapath。

FPU

ai / bi / instructionenable→Arithmetic Datapath+Sequential Control/Register→co + valid

FPU 不只要算對 floating-point bit pattern，也要在正確的 protocol/timing 下讓 valid 出現。

十三、RTL 與 Testbench 的時間觀念

TB 的 #10 是 simulation delay；@(posedge clk) 是等待事件。這些常用於 testbench，但 synthesizable RTL 中不能隨便把 delay 當成真實硬體。

語法TB一般 synthesizable RTL
#10常見通常不可用來描述真正 delay hardware
@(posedge clk)可等待 clock用於 sequential event control
$displaydebug 常用不是 datapath hardware
$fopen/$fgets/$sscanf讀 pattern不是一般可綜合硬體

十五、寫 HW1 時可先遵守的 RTL Coding Rules

Rule原因
Combinational 優先用 always_comb + blocking =清楚表達組合 datapath。
Clocked registers 優先用 always_ff + nonblocking <=清楚表達 FF 同步更新。
always_comb 開頭先給合理 default降低漏 branch 造成 latch。
同一 register 不要到處寫避免 multiple driver / ownership 不清。
明確處理 resetsimulation 起始 state 可預測。
不要把 TB 的 #delay 搬進 RTLsimulation delay 不等於 synthesizable hardware。
修改 sequential control 後看 waveform一拍差異只看 console 很難發現。
