08｜從進入作業目錄到 VCS / Verdi / Superlint / tar：完整 Command 工作流程

這一章把指令從「一串要複製的 command」改成完整工作流程。重點是知道自己目前在哪個目錄、每個工具吃什麼輸入、產生什麼輸出，以及發生錯誤時要回哪一層檢查。

一、整份 HW1 Command Master Flow

登入 SoC Lab→cd StudentID_HW1→檢查 tree→cd Sim→VCS ALU→VCS FPU

↓

PASS?→No：Verdi/FSDB Debug→修 RTL↺VCS Regression

全部 PASS ↓

Superlint→修 Warning/Error→再 Regression→回上一層→tar→tar -tf 檢查→Submit

二、為什麼 Working Directory 很重要？

StudentID_HW1/
├── Src/
│   ├── ALU.sv
│   └── FPU.v / FPU.sv
└── Sim/
    ├── ALU_tb.sv
    ├── FPU_tb.sv
    ├── superlint.tcl
    └── pattern/
        ├── pattern_alu.csv
        └── pattern_fpu.csv

如果 TB 內寫 ../Src/ALU.sv 與 ./pattern/pattern_alu.csv，這些都是相對於「執行 simulation 時的 working directory」解析。因此從 Sim/ 執行最容易與 starter 設定一致。

Command回答的問題
pwd我現在到底在哪裡？
ls這層有哪些檔案？
ls ../SrcRTL 是否真的在 TB 預期位置？
ls ./patternCSV 是否真的在 TB 預期位置？
find ... | sort整份提交 tree 是否正確？

三、VCS 指令逐段拆解

vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDB
片段意義在 HW1 的作用
vcsSynopsys VCS simulator編譯/建立 simulation executable
-Rcompile 後直接 run不用另外再執行 simv
-full6464-bit mode配合課程環境
-sverilogSystemVerilog modeTB/RTL 可使用 SV 語法
ALU_tb.svtop testbench sourceTB 再 include/instance DUT
-debug_access+all保留 debug visibility方便 Verdi 觀察訊號
+define+FSDB定義 FSDB macro啟用 TB 中條件式 waveform dump
VCS reads TB→TB includes/instantiates RTL→Compile→Elaborate→Run→Console + FSDB

四、Verdi / FSDB 的運作

VCS Simulation→$dumpfile/$dumpvars→ALU.fsdb / FPU.fsdb→verdi -ssf→Waveform Debug
ALU 看什麼FPU 看什麼
instruction、opcode/funct、A/B、signed intermediate、shift amount、resultclk/rst/enable/valid、S/E/F、classify、exp diff、aligned mantissa、GRS、normalize、round、co

& 是 Shell 的背景執行符號：Verdi GUI 開啟後 terminal 仍可繼續使用。

五、Superlint 指令與 VCS 有什麼不同？

jg -superlint superlint.tcl
superlint.tcl→JasperGold→Read RTL→Elaborate→Static Checks→Warnings/Errors
VCS SimulationSuperlint
需要 TB + pattern核心是 RTL + TCL/tool settings
驗證實際 test vectors 的功能從程式結構找 width/latch/undriven/signedness 等風險
產生 PASS/FAIL、FSDB產生 lint diagnostics/report

若 starter 中沒有 TCL，應以課程/TA 提供版本或最新規定為準，不要任意假設腳本路徑與 top。

六、最後為什麼要先檢查再 tar？

Full Regression PASS→find 檢查 tree→tar -cvf→StudentID_HW1.tar→tar -tf→確認 archive
Option意義
ccreate archive
vverbose，顯示正在加入的檔案
f下一個參數是 archive filename
tlist archive contents，不解壓

九、實際完成作業的 Command Checklist

Step你應看到/確認什麼
1. cd + pwd確認進入自己的 HW1。
2. find/lsSrc、Sim、pattern、TB、RTL 都存在。
3. VCS ALU成功 compile/run，公開 ALU regression 通過。
4. VCS FPU成功 compile/run，公開 FPU regression 通過。
5. Verdi需要 debug 時能開啟對應 FSDB。
6. Superlint理解並處理關鍵 warning/error。
7. Re-runlint/RTL 修改後重新跑 ALU + FPU regression。
8. find提交 tree 與命名符合課程要求。
9. tar -cvf產生正確 archive。
10. tar -tf不解壓即可確認 tar 內容完整。

一句話記住

先確認「我在哪裡」→ 再確認「檔案在哪裡」→ 才執行工具；Simulation/Lint 都通過後，再從正確的上一層建立 tar，最後一定用 tar -tf 自己檢查一次。
