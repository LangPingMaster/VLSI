00-7｜FPU Datapath：Align → Add/Sub → Normalize → Round → Pack

本章直接沿著 VSD HW1 講義的 FPU 架構與 ADD/SUB 流程展開。FPU 介面包含 clk/rst/enable/ai/bi/instruction/co/valid，其中 instruction=0/1/2/3 分別為 MIN/MAX/ADD/SUB。本頁重點放在最難的 ADD/SUB datapath，並把 Special Cases、GRS 與 valid protocol 串起來。

一、FPU 完整 Master Flow

enable + ai/bi/op→Unpack S/E/F→Classify→Special Case?No →Effective Sign→Compare Exponent→Align + Sticky→Mantissa +/-→Normalize→GRS RNE→Pack→co + valid

這條鏈就是實作與 debug 的主幹。若最後答案錯，不要只盯著 co，而要找「第一個開始錯的 stage」。

二、HW1 FPU Interface 與四個 Operations

Signal用途
clkSequential control / result timing。
rst官方 TB 初始拉高、之後拉低；設計要配合此 reset 行為。
enable表示輸入 transaction 送入。
ai / bi兩個 IEEE-754 single-precision operands。
instruction[1:0]0=MIN、1=MAX、2=ADD、3=SUB。
co32-bit IEEE-754 result。
valid通知 TB：co 現在有效。

講義架構圖把 ADD/SUB datapath 與 MIN/MAX comparator 分開，再透過 mux 選 output。因此 MIN/MAX 不需要經過完整的 exponent alignment 與 mantissa arithmetic。

這一步先做完，後面的 normal datapath 才能假設 operands 是可正常進行 alignment/arithmetic 的 finite values。

四、Stage 2：Special-Case Bypass

Special-case priority 很重要：如果 NaN 已經成立，就不應再把 exponent=255 的 operand 丟進 normal alignment datapath。

五、Stage 3：Effective Sign——SUB 怎麼轉成共同 datapath？

A - B = A + (-B)

所以 SUB 可以先把 B 的 effective sign 反相：

ADD: signB_eff = signB
SUB: signB_eff = ~signB
signAsignB_effMantissa operation
相同相同Magnitude ADD
不同不同Magnitude SUB；較大 magnitude 減較小 magnitude

異號 subtraction 最後的 result sign 不是「永遠跟 A」，而是跟著較大 magnitude 的 operand。

六、Stage 4：Exponent Compare + Alignment

ΔE = |Ea - Eb|
比較 Ea/Eb→保留較大 exponent→較小 mantissa 右移 ΔE→產生 G/R/S

浮點加法不能直接把兩個 mantissa 相加，因為它們可能代表不同 2 的次方。必須先把較小 exponent 的 operand 對齊到較大的 exponent。

1.000 × 2^5
0.??? × 2^2
        ↑
第二個 mantissa 必須右移 3 位，兩邊才位於相同 exponent。

右移出去的 bits 不能全部消失；它們會影響最後 rounding，因此要形成 Guard、Round、Sticky。

七、Alignment 時如何形成 G / R / S？

名稱概念
Guard保留 fraction 後面的第一個被捨棄 bit。
Round第二個被捨棄 bit。
Sticky更低位只要曾經有任一個 1，就保持 1。

Sticky 的關鍵是 OR-reduction，而不是「最後一個 bit」。例如被移掉的尾巴是 001001000...，只要其中存在 1，Sticky 就必須為 1。

Exponent gap要特別測的原因
0完全不 shift。
1剛開始形成 G。
23/24/25接近 fraction precision 邊界。
>31小 operand 幾乎完全被 shift 掉，但 Sticky 仍可能影響 rounding。

八、Stage 5：Mantissa Add / Magnitude Subtract

Effective signs 相同

Aligned MA+Aligned MB→可能產生 carry

Effective signs 不同

比較 Magnitude→Large - Small→可能大量 leading zeros

這兩條路徑會導致兩種完全不同的 normalization：加法 carry 通常右移一位；接近 cancellation 的 subtraction 可能需要左移很多位。

九、Stage 6：Normalization

狀況動作Exponent
Add 產生 carryMantissa 右移 1E = E + 1
Sub cancellation找 leading 1，左移 kE = E - k
完全 cancellation結果變 Zero需依規格處理 zero sign
Raw Mantissa→Carry?或Leading Zero Count→Shift+Exponent Adjust

常見 bug 是 mantissa shift 正確，但 exponent 忘記同步修改。

十、Stage 7：GRS Round-to-Nearest-Even

round_up = G & (R | S | LSB)
GRSLSB動作
0xxX不進位
101/110/111X進位
1000不進位：已是 even
1001進位：讓結果變 even

而且 rounding 本身還可能讓 significand 從 1.111... + 1 ulp 變成 10.000...，此時必須再 normalize 一次並讓 exponent +1。

十一、Stage 8：Repack 成 32-bit IEEE-754

co = { sign_result, exponent_result[7:0], fraction_result[22:0] }
Normalized/Rounded significand→移除 hidden 1→取 23-bit fraction+8-bit exponent+sign→32-bit co

如果前面走的是 NaN/Inf/Zero special bypass，則直接使用該 special result，不必照 normal pack 路徑。

十二、MIN / MAX 為什麼是另一條較短路徑？

講義架構圖把 MIN/MAX comparator 與 ADD/SUB arithmetic 分開。MIN/MAX 的本質是比較兩個 IEEE-754 operands 後選 A 或 B，而不是重新做 floating-point addition。

ai / bi→Classify + FP Compare→MIN/MAX Select→Output MUX

NaN、±0 等比較規則若講義未完整列出全部細節，最終行為應以官方 pattern 為準，不能自行用 host-language 的一般 min()/max() 假定完全相同。

十三、Datapath 之外還有 enable / valid Protocol

官方 FPU TB 的 transaction 大致是：

設定 instruction/A/B→start(enable)=1→ posedgestart=0→ next posedgewhile(!valid) wait→capture co

因此「數學算對」不代表 FPU 一定過 TB。若 valid 永遠不拉高，TB 會一直等；若 valid 與 co 不在正確時序對齊，也會讀到錯誤 transaction。

十五、FPU FAIL：依 Stage 找第一個錯誤

FAIL A/B/OP→S/E/F→Class→ΔE→Aligned Mantissa+GRS→Raw Sum/Diff→Normalize→Round→Packed co
症狀先查哪一層
NaN/Inf 全錯Classify + special priority
exponent 差很大時錯Alignment + Sticky
相消附近錯Magnitude subtraction + LZC normalization
只差最後 1 bitGRS / RNE / tie-even
答案像差 2 倍Normalization / exponent ±1
co 正確但 TB 卡住valid protocol
MIN/MAX 少數 case 錯NaN / signed zero / comparator semantics

十六、完成 FPU 的實作順序

① Unpack/Classify→② Special Cases→③ MIN/MAX→④ Align+GRS→⑤ Add/Sub→⑥ Normalize→⑦ RNE→⑧ Pack→⑨ valid/control→⑩ Official Regression

不要一次把整個 FPU 寫完才測。每一 stage 都先準備幾個可手算的 directed cases，確認中間訊號，再進下一 stage。最後才用官方 2000 筆 pattern 做 bit-exact regression，並補 ±0、subnormal、Inf/NaN、exponent-gap、GRS tie、round carry 等 boundary defense。
