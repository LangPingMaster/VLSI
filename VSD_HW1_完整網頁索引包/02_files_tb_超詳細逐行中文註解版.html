02｜Starter Files 與 Testbench：從「老師怎麼測」反推「RTL 怎麼寫」

一、Testbench 的目的到底是什麼？

TB 不是你的硬體功能本身，而是驗證環境。它扮演四個角色：產生 stimulus、控制 transaction timing、取得 DUT output、與 golden answer 比較。真正被評分的是你的 ALU/FPU RTL，但你若看不懂 TB，就不知道老師何時送 input、何時讀 output、CSV 欄位代表什麼，以及什麼條件才算 PASS。

CSV Golden Pattern→TB Parser→Drive DUT Inputs→DUT RTL→Observe Output→Compare Golden→PASS / FAIL

檔案角色你要不要改？
ALU.svDUT：31 個 ALU operations主要開發檔
FPU.v / FPU.svDUT：MIN/MAX/ADD/SUB + IEEE-754主要開發檔；更名要同步 include
ALU_tb.sv讀 ALU CSV、drive A/B/instruction、10ns 後比對正式評分時通常不要改
FPU_tb.svclock/reset/start、等 valid、bit-exact compare正式評分時通常不要改
pattern_*.csv輸入與 golden output不要拿來「配答案」；可分析 coverage 並另建 corner tests

三、ALU_tb.sv 的完整運作流程

$fopen CSV→$fgets 一行→$sscanf 5 欄→Drive instruction/A/B→#10→檢查 X/Z→與 expected 比較→error[inst_id]

關鍵推論：ALU TB 沒有 clock，也沒有 valid handshake。輸入被直接改變後只等待 #10 就讀 result_o，因此你的 ALU 必須以combinational logic 的方式對 input 反應。若你自行加 clock/register latency，這個 TB 不會等你。

ALU CSV 欄位

欄位sscanf用途
1%d → inst_id0~30，決定哪一類 instruction 的 error counter。
2%h → inst_hex32-bit encoded instruction，真正 decoder input。
3%h → a_hexsrc_A_i。
4%h → b_hexsrc_B_i。
5%h → exp_hexGolden result。

五、FPU_tb.sv 的完整 transaction

Reset=1→20ns→Reset=0→讀 CSV→start=1 + A/B/ins→posedge→start=0→等待 ready→抓 result→bit-exact compare

這和 ALU 最大差別是 FPU 是有時序 protocol 的 DUT。TB 允許內部運算有 latency，因為它會等待 ready(valid)；但你的 DUT 必須在正確時間 assert valid，並確保那個時候 co 已經是本筆輸入的答案。

非常重要：while (!ready) 沒有內建 transaction timeout

如果你的 FPU 因 state machine/valid bug 永遠不把 ready 拉高，TB 可能卡在 while (!ready) @(posedge clk);。Debug 時若 console 看似「沒有 FAIL 也沒有 PASS」，第一件事就看 waveform 的 start/enable 與 ready/valid。

FPU CSV 欄位順序

欄位變數意義
1a_hexoperand A 的 IEEE-754 32-bit bit pattern
2b_hexoperand B
3exp_hexexpected 32-bit result
4in2-bit instruction：依 HW spec 對應 MIN/MAX/ADD/SUB

七、為什麼一定要理解 CSV，而不是只看最後 ALL PASS？

CSV 是老師公開的 specification examples。對 ALU，你可以依 inst_id 分組，檢查 31 種 operation 是否都有被測；對 FPU，可以依 instruction 分組，再分析 NaN/Inf/zero、正負數、exponent difference、rounding 等 case。這能告訴你公開測資覆蓋了什麼，以及 hidden test 還可能補什麼。

但公開 pattern PASS 不等於 hidden PASS。RTL 必須實作規格本身，而不是對 CSV 特定輸入 hard-code。

現象優先檢查常見原因
Cannot open patternpwd、Sim/pattern 路徑、大小寫不在 Sim 目錄執行

只有 signed cases 錯$signed / intermediate widthSV expression 被當 unsigned
FPU 卡住start、state、validFSM 沒到 DONE、valid 沒 pulse
FPU 差 1 ULPG/R/S、LSB、round carryround-to-even 寫錯
NaN/Inf/0 錯classify 與 special-case priority先進一般 arithmetic 才處理 special case
