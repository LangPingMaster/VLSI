00-10｜VCS / Verdi / Superlint：從 RTL 到 PASS、Waveform、Lint 的完整操作

這是 VSD HW1 十個先修主題的最後一章。重點不是背三套工具，而是理解它們在驗證流程中的不同角色：VCS 負責 compile/elaborate/simulate，Verdi 負責 waveform/debug，Superlint 負責靜態 RTL 品質檢查。本頁的 HW1 指令以課程作業講義中的 command 為主，並結合 starter TB 的實際相對路徑說明。

一、整個工具流程先看懂

ALU.sv / FPU RTL+TB + CSV→VCS Compile→Elaboration→Simulation→PASS / FAIL+FSDB→Verdi Debug
RTL→Superlint→Warning / Error / Coverage→修 RTL→重新 Regression

Simulation PASS ≠ Lint PASS；Lint clean ≠ Function correct。兩種驗證解決的是不同問題，最後都要過。

二、VCS、Verdi、Superlint 各自在做什麼？

工具主要工作你會看到什麼回答的問題
VCSCompile + elaborate + simulate RTL/TBcompile errors、simulation log、PASS/FAIL、FSDB「我的 RTL 對這些 test patterns 算得對嗎？」
VerdiWaveform / hierarchy / signal tracingclk、inputs、intermediate、output、X「第一個錯的訊號在哪一個 cycle 出現？」
SuperlintStatic RTL analysiswarning/error/structural issues/coverage「即使 simulation 沒撞到，RTL 結構是否仍有危險？」

三、第一步永遠是 Working Directory

Starter archive 的實際核心結構是：

StudentID_HW1/
├─ Src/
│  ├─ ALU.sv
│  └─ FPU.v
└─ Sim/
   ├─ ALU_tb.sv
   ├─ FPU_tb.sv
   └─ pattern/
      ├─ pattern_alu.csv
      └─ pattern_fpu.csv

作業 PDF 的 hierarchy 範例與 starter archive 存在命名差異，例如 PDF 寫 FPU.sv、Pattern/，starter 則是 FPU.v、pattern/。實際提交時要以當期助教最新規定為準；若自行 rename，TB 的 `include 與 TCL 也要同步修改。

$ cd StudentID_HW1/Sim $ pwd $ ls $ ls ../Src $ ls ./pattern

很多「VCS 壞掉」其實只是目前目錄不對，導致 ../Src/ALU.sv 或 ./pattern/pattern_alu.csv 找不到。

四、VCS Command 逐 token 解釋

vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDB
Token作用
vcs啟動 Synopsys VCS。
-R完成 compile/elaboration 後直接執行 simulation。
-full64使用 64-bit 執行環境。
-sverilog啟用 SystemVerilog parsing。
ALU_tb.sv以 testbench 為 compilation input；TB 再 include/instantiate DUT。
-debug_access+all保留較完整 debug visibility，方便 waveform/debug。
+define+FSDB定義 FSDB macro，讓 TB 中 `ifdef FSDB 的 dump code 生效。

五、Compile / Elaborate / Simulate 是三個不同概念

Parse / Compile→Elaborate Hierarchy→Run Simulation
階段常見問題
Compilesyntax error、undeclared signal、width/type 問題、include 找不到
Elaborationmodule 找不到、port mismatch、multiple definition、hierarchy 問題
Simulation功能答案錯、X、valid hang、timing/protocol 錯

所以看到 Error 時，第一件事不是直接開 Verdi，而是先判斷「現在到底有沒有成功進入 simulation」。Compile error 還沒產生可執行的正確 DUT 行為，waveform 通常不是第一優先。

六、ALU Official Regression

$ cd StudentID_HW1/Sim $ vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDB
ALU_tb.sv→pattern_alu.csv→instruction/A/B→ALU.sv→result_o↔expected

ALU starter pattern 共涵蓋 31 個 operation IDs。若 FAIL，先記住第一筆 instruction/A/B/GOT/EXP，再回到 decoder、signedness、width、shift amount 或 DSP lane 邏輯找 root cause。

七、FPU Official Regression

$ vcs -R -full64 -sverilog FPU_tb.sv -debug_access+all +define+FSDB
FPU_tb.sv→pattern_fpu.csv→enable + A/B/op→FPU→wait valid→co === expected

FPU starter pattern 有 2000 筆，四種 instruction 各 500 筆。若 simulation 卡住，優先看 valid；starter TB 的 while(!ready) 沒有 per-transaction timeout。

八、FSDB 是 VCS 與 Verdi 中間的橋

VCS Simulation→$dumpfile / $dumpvars→ALU.fsdb / FPU.fsdb→Verdi

若沒有加 +define+FSDB，而 TB 的 dump code 又包在 `ifdef FSDB 中，就可能沒有產生預期的 FSDB。功能 simulation 可以跑，但你之後沒有 waveform 可看。

九、Verdi：不是看漂亮波形，而是找第一個錯誤

$ verdi -ssf ALU.fsdb & $ verdi -ssf FPU.fsdb &
FAIL case→定位時間→確認 Inputs→Decode/Classify→Intermediate→Output/valid→第一個錯訊號
ALU 建議看FPU 建議看
instruction/opcode/funct3/funct7clk/rst/enable/valid
src_A/src_BS/E/F classification
signed compare / shamtexp_diff/aligned mantissa
product / lane intermediateG/R/S、raw add/sub
result_onormalized/rounded mantissa、co

十、Superlint：Simulation 沒測到的問題也要抓

$ jg -superlint superlint.tcl

HW1 講義指定以這個 command 執行 Superlint，並且 grading 說明中特別提到 Superlint coverage；因此 lint 不是可有可無的額外步驟。

Lint 類型典型問題可能後果
Width8-bit 與 32-bit expression 混用sign/zero extension 或截斷錯誤
Signednesssigned/unsigned 混合比較/乘法SLT、MULH、DSP/FPU 邊界錯
Incomplete assignmentcombinational path 沒有賦值latch / X
Unused/dead logic訊號宣告但無作用設計結構可疑、coverage 降低
Multiple driver同一 signal 被多個 procedural blocks 驅動衝突/X/不可綜合風險
Unreachable branchdecoder 條件永遠不可能成立某 operation 永遠跑不到

十一、Superlint.tcl 在扮演什麼角色？

superlint.tcl→指定/讀取 RTL→設定 Top / Language / Options→Elaborate→Lint Checks→Report

你可以把 TCL 想成「告訴 Superlint 這個 project 要讀哪些檔、top 是誰、要執行哪些分析」的腳本。starter archive 本身沒有附上 PDF hierarchy 所列的 Superlint.tcl，因此若課程平台另有最新版檔案，應使用助教提供版本，不要自行猜測完整內容。

十二、看到 Warning 不要先用 disable 壓掉

例如 width warning 的正確處理流程：

Warning→看 operator 期望 width→看兩側 expression width→確認 signed/unsigned→明確 extend/cast→重跑 lint + regression

例如 exponent 是 8-bit，卻與 unsized integer literal 1 放在 conditional expression 中，工具可能把另一側擴展成較大的整數寬度。比起關閉 warning，更好的做法是明確寫出你真正要的 width，例如依語意使用 8'd1。

十三、Error / FAIL / Warning 要開哪個工具？

現象第一步主要工具
Syntax Error看第一個 compiler error 與 line numberVCS log/editor
Module/File not foundpwd、ls、檢查 relative pathShell + VCS
Simulation FAIL保存第一筆 failing vectorVCS → Verdi
Simulation Hang看 clk/rst/enable/validVerdi
X/Z往 driver/source 逆追Verdi + lint
Width/Signed Warning檢查 expression width/castSuperlint/compiler
Lint coverage 不佳看未覆蓋/不可達/未使用結構Superlint

十四、HW1 Command Runbook：逐行說明

Command用途
pwd顯示目前工作目錄。第一個 debug 動作通常就是確認自己到底在哪裡。
ls列出目前目錄內容，確認 ALU_tb.sv、FPU_tb.sv、Superlint.tcl 等檔案是否真的存在。
ls ../Src確認 testbench 使用的相對路徑能找到 Src/ALU.sv、FPU.v 或依最新版要求命名的 FPU.sv。
ls ./pattern確認 pattern_alu.csv、pattern_fpu.csv 的相對路徑正確。
vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDBHW1 講義的 ALU VCS 執行方式：編譯、建立模擬執行檔並直接執行；同時開啟 SystemVerilog、debug access 與 FSDB define。
vcs -R -full64 -sverilog FPU_tb.sv -debug_access+all +define+FSDBFPU 對應的 VCS simulation command；講義頁面有大小寫 Vcs 的排版，Unix/Linux command 實際應使用安裝環境中的 vcs executable。
verdi -ssf ALU.fsdb &用 Verdi 開啟 ALU FSDB waveform；& 讓 shell 在背景啟動 GUI。
verdi -ssf FPU.fsdb &用 Verdi 開啟 FPU FSDB waveform。
jg -superlint superlint.tclHW1 講義指定的 Superlint 啟動方式：由 JasperGold/Superlint 讀取 TCL 設定並進行 RTL lint。
tar -cvf StudentID_HW1.tar StudentID_HW1建立作業要求的 .tar 封裝；-c 建立、-v 顯示檔案、-f 指定輸出檔名。
tar -tf StudentID_HW1.tar不解壓，直接列出 tar 內容，送出前確認 hierarchy 與檔案沒有漏掉。

十五、真正建議的每日開發循環

改一小段 RTL→Compile→Directed Test→Official Regression→FAIL?→Verdi Root Cause→Superlint→再 Regression

不要累積 300 行修改後才第一次 compile。ALU 可按 operation family 分階段；FPU 可按 Classify → Special → Align → Add/Sub → Normalize → RNE → Pack → valid 分階段。

十六、送出前 Final Validation

ALU Regression→FPU Regression→Defense Tests→Superlint→Report Evidence→Hierarchy Check→tar -cvf→tar -tf
cd StudentID_HW1/Sim
pwd
ls
ls ../Src
ls ./pattern

vcs -R -full64 -sverilog ALU_tb.sv -debug_access+all +define+FSDB
vcs -R -full64 -sverilog FPU_tb.sv -debug_access+all +define+FSDB
jg -superlint superlint.tcl

cd ../..
tar -cvf StudentID_HW1.tar StudentID_HW1
tar -tf StudentID_HW1.tar

作業講義要求以 .tar 形式提交，並要求在 SoC Lab 環境確認 compile/simulation。最終原則是：你報告裡描述的 RTL、最後 regression 的 RTL、lint 的 RTL、打進 tar 的 RTL 必須是同一版。

十七、學完十章後應能回答

問題答案
VCS 做什麼？Compile/elaborate/simulate RTL + TB。
Verdi 做什麼？從 waveform/hierarchy 找第一個錯誤訊號與時間。
Superlint 做什麼？靜態檢查 RTL 結構、width、signedness、latch、dead/unreachable 等問題。
PASS 就不用 lint？不對；simulation 與 lint 檢查不同面向。
找不到 pattern 第一個查什麼？pwd、ls、相對路徑。
FPU simulation 卡住先看什麼？clk/rst/enable/valid handshake。
FAIL 後最重要原則？保存最小 failing case，在 waveform 找第一個錯訊號，修 root cause，再全量 regression。

至此 00-1～00-10 的 HW1 先修鏈完成：Binary/Hex → Combinational/Sequential → Decode → ALU → DSP → IEEE-754 → FPU Datapath → GRS/RNE → TB/Handshake → VCS/Verdi/Lint。
