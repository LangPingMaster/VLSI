Gate-Level Netlistcell instances + nets
一句話：RTL 描述「功能與暫存器傳輸行為」，Synthesis 把它轉成實際 gates / cells 的連線。

課程強調 Behavioral Model 的價值之一，就是可以避免手動處理 gate-level 細節，並把最佳化工作交給 synthesis tool。

2. RTL 是什麼？

RTL = Register Transfer Level。它描述資料如何經過 combinational logic， 在 clock edge 被 register 儲存，再流向下一級。

2.1 Combinational RTL

assign y = (a & b) | c;

2.2 Sequential RTL

always @(posedge clk)
    q <= d;

2.3 RTL 的重點不是 gate 名稱

always @(posedge clk) begin
    if (en)
        q <= a + b;
end

這段 RTL 沒有指定「用哪顆 adder cell、哪顆 DFF cell」，那些由 synthesis / library mapping 決定。

3. Synthesis 到底在做什麼？

1. 讀懂 RTL

解析 module、port、always、assign、operator。

2. 推導硬體

辨識 MUX、FF、Adder、Comparator、Decoder。

3. 最佳化

減少 gate、縮短 critical path、調整 cell strength。

4. Mapping

將 generic logic 映射到 standard-cell library。

5. 輸出 Netlist

產生 cell instances 與 nets。

5. Logic Optimization

5.1 Boolean Optimization

assign y = (a & b) | (a & c);

邏輯等價於：

assign y = a & (b | c);

Synthesis tool 可能採用更省面積或更符合 timing 的等價實作。

5.2 課程中的 Boolean Optimization 範例

課程展示一個由多個 AND / OR structural primitives 組成的 Boolean network， 並標示 Before synthesis / After synthesis，強調 synthesis 不只是翻譯，還會做最佳化。

實際最佳結果依 library、timing constraint、area goal、fanout 等條件而不同，不一定永遠選「gate 數最少」。

6. Technology Mapping

Synthesis 前的內部邏輯可能只是 generic AND、OR、MUX、FF。 Technology Mapping 會根據目標 standard-cell library，選用實際可製造的 cells。

Generic LogicAND / OR / FF / MUX
→
Library Searchtiming / area / power
→
Mapped CellsNAND2_X1, DFF_X1...

Drive Strength

課程指出同一類邏輯 function 可能有 1X、2X、4X、8X 等 drive strength variants， 讓 synthesis tool 在 area、delay、load capacitance 之間折衷。

7. Gate-Level Netlist 是什麼？

Gate-Level Netlist 不再以高層次 if、+、case 為主， 而是列出「哪些 standard cells 被 instantiated、它們怎麼接線」。

RTL

assign y = a & b;

可能的 Gate-Level Netlist（示意）

AND2_X1 U1 (
    .A1(a),
    .A2(b),
    .ZN(y)
);

Register RTL

always @(posedge clk)
    q <= d;

可能的 Gate-Level Netlist（示意）

DFFQ_X1 U_REG (
    .D(d),
    .CK(clk),
    .Q(q)
);
cell 名稱如 AND2_X1、DFFQ_X1 是示意；真正名稱取決於使用的 standard-cell library。

8. 大量 RTL → Synthesis → Gate-Level 例子

例 1：AND Gate

// RTL
assign y = a & b;

// Gate-level concept
AND2 U1 (.A(a), .B(b), .Y(y));

例 2：OR Gate

assign y = a | b;

// possible mapped cell
OR2_X1 U1 (...);

例 3：NOT Gate

assign y = ~a;

// possible mapped cell
INV_X1 U1 (...);

例 4：2-to-1 MUX

assign y = sel ? b : a;

// synthesis may map to
MUX2_X1 U1 (...);

例 5：Comparator

assign eq = (a == b);

// synthesis builds XOR/XNOR + reduction logic
// or maps to available comparator structures

例 6：4-to-1 MUX

always @(*) begin
    case(sel)
        2'b00: y = d0;
        2'b01: y = d1;
        2'b10: y = d2;
        2'b11: y = d3;
    endcase
end

可能映射成多層 MUX cells。

例 7：Adder

assign sum = a + b;

Synthesis 推導 adder network；實際可能由 full-adder cells、NAND/XOR 結構或 library 中的 arithmetic cells 實作。

例 8：1-bit Full Adder（課程 Dataflow）

assign s    = x ^ y ^ cin;
assign cout = (x & y) | (x & cin) | (y & cin);

課程也給了 Behavioral 版本：

always @(x or y or cin)
    {cout, s} = x + y + cin;

兩種 RTL/Dataflow 描述都可以在 synthesis 後得到功能等價的 gate-level implementation。

例 9：DFF

always @(posedge clk)
    q <= d;

→ DFF cell。

例 10：Register Enable

always @(posedge clk)
    if (en)
        q <= d;

→ 可能是 enable FF，或 MUX + DFF。

例 11：Async Reset Register

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 0;
    else
        q <= d;
end

→ 可能映射到具有 asynchronous reset pin 的 DFF cell。

例 12：Counter

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        count <= 0;
    else
        count <= count + 1'b1;
end

→ Register bank + incrementer logic。

例 13：Shift Register

always @(posedge clk) begin
    q[0] <= din;
    q[1] <= q[0];
    q[2] <= q[1];
    q[3] <= q[2];
end

→ 4 個串接的 flip-flops。

例 14：FSM

always @(posedge clk)
    state <= next_state;

always @(*) begin
    case(state)
        IDLE: next_state = start ? RUN : IDLE;
        RUN : next_state = done  ? IDLE : RUN;
    endcase
end

→ State registers + next-state combinational logic。

例 15：Pipeline

always @(posedge clk) begin
    s1 <= a + b;
    s2 <= s1 ^ c;
end

→ Adder logic + stage-1 register + XOR logic + stage-2 register。

9. Standard Cell Library 在 Synthesis 裡的角色

課程列出 library view formats，其中：

檔案用途
.lib / .dbTiming & Power View，包含 propagation delay、setup/hold、dynamic/leakage power 等資訊
.v / .slibFunctional View，可作 gate-level Verilog simulation
.lefP&R 使用的 abstract geometry
.gds / .gdsii完整 physical layout mask data
.cdl / .spiSPICE / LVS circuit view
Synthesis 最重要的不是只知道「AND gate 存在」，而是要知道 library 中有哪些 cells，以及每顆 cell 的 timing / area / power 特性。

10. Constraints 為什麼會影響合成結果？

以下屬於延伸實務說明：課程片段本身強調 synthesis optimization 與 cell drive-strength tradeoff，但沒有在本段完整列出 constraint command。

同一段 RTL，在不同 clock period、area goal、fanout / load 條件下，可能得到不同 gate-level netlist。 

// RTL 一樣
assign y = a & b;

// 但若 timing 很緊，tool 可能選較強 cell
AND2_X4 ...

// timing 寬鬆時，可能選較小 cell
AND2_X1 ...

11. Synthesis 前後怎麼驗證？

RTL Simulation

確認 RTL function 是否符合 specification。

Gate-Level Simulation

用 mapped netlist + cell functional models 驗證合成後功能。

課程指出 .v / .slib 可作 functional view，用於 gate-level Verilog netlist / behavioral description 的 functional simulation。

課程 Blocking/Nonblocking 範例也直接比較 behavioral simulation 與 gate-level 結果，提醒 RTL coding style 必須讓 RTL behavior 與 gate-level hardware 一致。

12. 常見誤解與考試重點

誤解 1：Synthesis = 把每一行 RTL 翻成一顆 gate

錯。Synthesis 會做 inference、optimization、technology mapping，不是逐行機械翻譯。

誤解 2：RTL 長得像什麼，gate netlist 就一定長得一樣

錯。只要功能與時序需求等價，tool 可以重寫 Boolean network。

誤解 3：Gate-Level Netlist 就是 Layout

錯。Netlist 主要描述 cells 與 connectivity；layout 還需要 placement、routing、physical verification 等後續流程。

誤解 4：所有 DFF 都一樣

錯。library 中可能有不同 reset/preset、drive strength、threshold voltage、scan 等 variants。

誤解 5：cell 越大一定越好

錯。drive 越強常代表 area / power 也更高，需要平衡。

13. 自我測驗

Q1：RTL 與 Gate-Level Netlist 最大差別？

RTL 描述高層次資料與暫存器行為；Gate-Level Netlist 描述實際 cell instances 與 nets。

Q2：a+b 在 synthesis 時可能變成什麼？

Adder logic，具體由何種 cells 組成取決於 library 與 optimization。

Q3：sel ? a : b 常推導什麼？

Multiplexer。

Q4：always @(posedge clk) 常推導什麼？

Flip-flop / register。

Q5：為什麼同一段 RTL 可能得到不同 netlist？

因為 library、timing、area、power、load 與 optimization goals 不同。

Q6：.lib / .db 主要放什麼？

Cell timing 與 power 資訊，例如 propagation delay、setup/hold、dynamic/leakage power。
