1. Blocking 與 Nonblocking Assignment 到底差在哪？

Blocking Assignment

=

目前這一行執行完成後，才繼續下一行。

Nonblocking Assignment

<=

先計算 RHS，LHS 的更新排程到稍後，block 可以繼續執行後面 statements。

最常用的設計規則：
Combinational procedural logic 通常用 =。
Clocked sequential logic 通常用 <=。

2. Blocking Assignment：=

Blocking assignment 的概念是： 當前 assignment 完成後，才往下一個 statement 執行。

2.1 最簡單例子

begin
    a = b;
    c = a;
end

第二行看到的是第一行已經更新後的 a。

Step 1：a 立即取得 b
Step 2：c 取得新的 a

2.2 Combinational logic 很適合 blocking

always @(*) begin
    temp = a & b;
    y    = temp | c;
end

這種逐步計算中，第二行需要使用第一行剛算出的 temp，所以 blocking 非常直觀。

3. Nonblocking Assignment：<=

Nonblocking assignment 的核心是： RHS 先取值，但 LHS 的實際更新被排程到目前 time step 的後段。

3.1 最簡單例子

begin
    a <= b;
    c <= a;
end

兩行 RHS 都使用「進入 block 時的舊值」來計算。

Step 1：先記住 b 的舊值，準備更新 a
Step 2：再記住 a 的舊值，準備更新 c
最後：a、c 在排程點一起更新

3.2 這正符合 Flip-Flop 同步更新的直覺

always @(posedge clk) begin
    q0 <= din;
    q1 <= q0;
    q2 <= q1;
end

在同一個 clock edge，q0、q1、q2 都取 edge 前的舊值，因此形成真正的 pipeline / shift register。

5. 經典例子：4-bit Shift Register

5.1 用 Blocking Assignment

always @(posedge clk) begin
    qout[0] = sin;
    qout[1] = qout[0];
    qout[2] = qout[1];
    qout[3] = qout[2];
end

因為每一行都立即更新，後一行可能直接看到前一行的新值。 這樣在 simulation 中可能造成資料在一個 clock edge 就「一路穿過去」。

5.2 用 Nonblocking Assignment

always @(posedge clk) begin
    qout[0] <= sin;
    qout[1] <= qout[0];
    qout[2] <= qout[1];
    qout[3] <= qout[2];
end

每一級都取前一個 clock cycle 的值，這才符合真正 4-stage shift register 的行為。

這正是課程投影片用來比較 blocking 與 nonblocking 的核心例子。

6. Race Condition 為什麼會發生？

6.1 Blocking 版本

always @(posedge clk)
    x = y;

always @(posedge clk)
    y = x;

兩個 always block 在同一個 clock edge 都被觸發。 如果 simulator 執行 block 的先後順序不同，結果可能不同。

6.2 Nonblocking 版本

always @(posedge clk)
    x <= y;

always @(posedge clk)
    y <= x;

兩邊都先取舊值，再一起更新，因此更符合兩個 FF 同時 sample 的硬體語意。

在多個 clocked always blocks 中使用 blocking assignment 是常見 race-condition 來源。

7. Combinational Logic：為什麼通常用 Blocking？

7.1 2-to-1 MUX

always @(*) begin
    if (sel)
        y = b;
    else
        y = a;
end

7.2 ALU

always @(*) begin
    case (op)
        3'b000: y = a + b;
        3'b001: y = a - b;
        3'b010: y = a & b;
        3'b011: y = a | b;
        default: y = 0;
    endcase
end

7.3 多步驟 combinational 計算

always @(*) begin
    sum   = a + b;
    carry = (sum > 8'hFF);
    y     = sum[7:0];
end
Combinational block 中 blocking assignment 很直觀，因為你通常希望後面的 statement 能使用前面剛算出的中間結果。

8. Sequential Logic：為什麼通常用 Nonblocking？

8.1 D Flip-Flop

always @(posedge clk)
    q <= d;

8.2 Counter

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        count <= 8'd0;
    else
        count <= count + 1'b1;
end

8.3 Pipeline Registers

always @(posedge clk) begin
    stage1 <= din;
    stage2 <= stage1;
    stage3 <= stage2;
end

每一級 register 都應該在同一個 clock edge 同時 sample 舊值，所以 nonblocking 更貼近真實硬體。

9. 大量 Blocking / Nonblocking 範例

例 1：Combinational AND

always @(*) begin
    y = a & b;
end

例 2：MUX

always @(*) begin
    y = sel ? b : a;
end

例 3：Priority Encoder

always @(*) begin
    if      (req[3]) code = 2'd3;
    else if (req[2]) code = 2'd2;
    else if (req[1]) code = 2'd1;
    else             code = 2'd0;
end

例 4：Decoder

always @(*) begin
    case(sel)
        2'd0: y = 4'b0001;
        2'd1: y = 4'b0010;
        2'd2: y = 4'b0100;
        2'd3: y = 4'b1000;
    endcase
end

例 5：DFF

always @(posedge clk)
    q <= d;

例 6：Register Enable

always @(posedge clk) begin
    if (en)
        q <= d;
end

例 7：Asynchronous Reset

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 0;
    else
        q <= d;
end

例 8：Counter

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        count <= 0;
    else if (en)
        count <= count + 1;
end

例 9：Shift Register

always @(posedge clk) begin
    q <= {din, q[3:1]};
end

例 10：Pipeline

always @(posedge clk) begin
    a1 <= a0;
    a2 <= a1;
    a3 <= a2;
end

例 11：FSM State Register

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        state <= IDLE;
    else
        state <= next_state;
end

例 12：FSM Next-State Logic

always @(*) begin
    next_state = state;

    case(state)
        IDLE: if (start) next_state = RUN;
        RUN : if (done)  next_state = IDLE;
    endcase
end

例 13：Combinational Temporary Variables

always @(*) begin
    temp1 = a ^ b;
    temp2 = temp1 & c;
    y     = temp2 | d;
end

例 14：Sequential swap

always @(posedge clk) begin
    a <= b;
    b <= a;
end

這會在一個 clock edge 後交換 a 與 b 的舊值。

例 15：Blocking swap 的問題

always @(posedge clk) begin
    a = b;
    b = a;
end

第二行看到的是更新後的 a，所以結果不是一般人直覺中的「交換」。

例 16：Count / Finish 經典差異

// 假設進入 block 前 count=1, finish=0

always @(posedge clk) begin
    count = count - 1;
    if (count == 0)
        finish = 1;
end

Blocking 版本中，if 看到的是已更新後的 count，因此 finish 會被設成 1。 

always @(posedge clk) begin
    count <= count - 1;
    if (count == 0)
        finish <= 1;
end

Nonblocking 版本中，if 判斷看到的是舊的 count=1，因此這個 cycle finish 不會變成 1。

10. 同一個 always block 混用 = 與 <= 好嗎？

一般初學與大多數 RTL coding guideline 中， 不建議在同一個 clocked always block 隨意混用 blocking 與 nonblocking， 因為容易造成 simulation 語意難懂，也容易引入前後依賴。

容易混淆的例子

always @(posedge clk) begin
    temp = a + b;
    q    <= temp;
end

這種寫法有時是刻意使用 blocking temporary variable，再用 nonblocking 更新 register。 但若沒有清楚的 coding convention，很容易讓閱讀者誤判資料更新時序。

初學者最安全的原則： 組合 always 用 =；clocked always 用 <=。

11. Synthesis 觀點：= 與 <= 不只是「語法風格」

Synthesis 主要根據 event control 與 assignment structure 推導硬體。 例如 always @(posedge clk) 本身就強烈表示 sequential storage。 不過 assignment 類型會影響 simulation semantics，因此 coding style 必須讓 RTL simulation 與實際硬體行為一致。

12. 常見錯誤與考試重點

錯誤 1：把 = 與 <= 當成只是兩種等號

它們的 simulation scheduling 不同，因此在 sequential code 中可能造成完全不同結果。

錯誤 2：Clocked shift register 用 blocking

always @(posedge clk) begin
    q0 = din;
    q1 = q0;
    q2 = q1;
end

可能造成資料在同一 event 中連續傳遞，而不像真正三級 FF。

錯誤 3：多個 clocked blocks 用 blocking

always @(posedge clk) x = y;
always @(posedge clk) y = x;

容易產生 race condition。

錯誤 4：Combinational logic 一律用 <=

雖然某些情況可能仍可模擬/合成，但會使逐步資料相依不直觀，也不符合常見 RTL coding convention。

錯誤 5：以為 Nonblocking 是「真的平行硬體」

它是一種 simulator scheduling semantics，用來更好地模擬同步硬體的同時更新。

13. 自我測驗

Q1：Combinational always block 一般建議使用哪種 assignment？

Blocking assignment =。

Q2：Clocked always block 一般建議使用哪種 assignment？

Nonblocking assignment <=。

Q3：a=b; c=a; 中 c 看到的是新 a 還是舊 a？

新 a，因為 blocking assignment 立即更新。

Q4：a<=b; c<=a; 中 c 看到的是新 a 還是舊 a？

舊 a，因為 nonblocking 先取 RHS 舊值，再延後更新 LHS。

Q5：為什麼 shift register 應使用 nonblocking？

因為每一級 FF 應在同一個 clock edge 同時 sample 前一級的舊值。

Q6：兩個 clocked always blocks 使用 blocking assignment 最大風險是什麼？

Race condition，結果可能受 simulator 執行順序影響。
