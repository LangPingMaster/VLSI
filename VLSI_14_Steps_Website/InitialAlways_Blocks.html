1. initial 與 always 是什麼？

initial 與 always 都是 Verilog 的 procedural blocks。 也就是說，它們裡面可以放 procedural statements，例如 assignment、if、case、for、 delay、event control 等。

initial

模擬時間 0 開始。

整個 block 只執行一次。

always

模擬時間 0 開始。

執行完後會持續重複。

課程投影片的核心定義就是：
initial：executes precisely once during simulation。
always：executes continuously during simulation。

2. initial Block 詳細說明

2.1 最簡單形式

reg x;

initial
    x = 1'b0;

模擬一開始，x 被設成 0。這個 initial block 執行完後就結束，不會自動重跑。

2.2 多個敘述：使用 begin / end

reg x, y, z;

initial begin
    x = 1'b0;
    y = 1'b1;
    z = 1'b0;
end

這和課程投影片中的 complex statement 概念相同。

2.3 initial 裡使用 delay

initial begin
    x = 1'b0;
    #10 x = 1'b1;
end
t = 0：x = 0
等待 10 個 time units
t = 10：x = 1
initial 結束

2.4 initial 最常見用途

Testbench 初始化
設定 input、reset、control signal。
產生 stimulus
不同時間送不同測試資料。
控制模擬流程
例如最後呼叫 $finish。
課程來源明確說明的是 simulation 行為。 一般 ASIC RTL 設計中，initial 常主要出現在 testbench；不同工具與實作平台對 initial 的 synthesizability 可能有不同支援，因此不要把 testbench 用法直接等同於一般可合成 ASIC RTL。

3. always Block 詳細說明

always 會不斷重複執行。實際上，它通常會搭配 delay 或 event control， 否則可能在 simulation time 不前進的情況下無限迴圈。

3.1 課程中的 clock generator

reg clock;

initial clock = 1'b0;

always #5
    clock = ~clock;
t = 0：clock = 0
t = 5：clock = 1
t = 10：clock = 0
t = 15：clock = 1
...：持續切換

這會產生週期 10 time units 的 clock。

3.2 always 搭配事件

always @(posedge clk) begin
    q <= d;
end

這個 always block 並不是「一直不停算」，而是每次遇到 clk 的正緣時執行一次。

4. begin / end：一個 statement 與多個 statements

4.1 單一敘述可以不寫 begin/end

initial x = 1'b0;

4.2 多個敘述要用 begin/end 包起來

initial begin
    x = 0;
    y = 1;
    z = 0;
end

4.3 always 也是一樣

always @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
    q3 <= q2;
end
常見錯誤：忘記 begin/end，造成只有第一行屬於 if / always，而後面的敘述實際上跑到區塊外。

5. Delay Control：#5、#10

5.1 單純等待

initial begin
    a = 0;
    #10;
    a = 1;
end

5.2 在 assignment 前加 delay

initial begin
    a = 0;
    #10 a = 1;
end

5.3 多段 stimulus

initial begin
    sel = 0;
    a   = 0;
    b   = 1;

    #10 sel = 1;
    #10 a   = 1;
    #10 b   = 0;
end
這種 #delay 很適合 testbench 模擬 stimulus。 對一般 synchronous RTL，硬體時序通常應透過 clock、register、counter、FSM 等方式描述， 而不是靠 #10 要求真實電路等待固定時間。

6. Event Control：@、posedge、negedge

6.1 任一輸入改變時觸發

always @(a or b or sel) begin
    if (sel)
        y = b;
    else
        y = a;
end

6.2 使用 @(*)

always @(*) begin
    if (sel)
        y = b;
    else
        y = a;
end

@(*) 表示工具自動將右側讀到的相關訊號納入 sensitivity list， 可避免人工漏寫輸入訊號。

6.3 正緣觸發

always @(posedge clk) begin
    q <= d;
end

6.4 負緣觸發

always @(negedge clk) begin
    q <= d;
end

課程投影片列出的 edge-triggered event control 正是 @(posedge clock) 與 @(negedge clock)。

7. always 描述 Combinational Logic

7.1 2-to-1 MUX

module mux2(
    input  a, b, sel,
    output reg y
);
    always @(*) begin
        if (sel)
            y = b;
        else
            y = a;
    end
endmodule

7.2 4-to-1 MUX

always @(*) begin
    case (sel)
        2'b00: y = d0;
        2'b01: y = d1;
        2'b10: y = d2;
        2'b11: y = d3;
    endcase
end

課程也用 always @(*) 搭配巢狀 if...else 描述 4-to-1 MUX。

7.3 Full Adder

always @(*) begin
    {cout, sum} = a + b + cin;
end
Combinational always block 的重點是：
1. sensitivity 要完整；2. 每條路徑都要對輸出賦值；3. 通常使用 blocking assignment =。

8. always 描述 Sequential Logic

8.1 D Flip-Flop

always @(posedge clk) begin
    q <= d;
end

8.2 4-bit Shift Register

always @(posedge clk) begin
    qout[0] <= sin;
    qout[1] <= qout[0];
    qout[2] <= qout[1];
    qout[3] <= qout[2];
end

這和課程投影片的 4-bit shift register 例子相同，使用 nonblocking assignment 描述同步更新。

8.3 Counter

always @(posedge clk) begin
    count <= count + 1'b1;
end

8.4 帶非同步 Reset

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 8'h00;
    else
        q <= d;
end

8.5 課程中的 4-bit Counter 風格

always @(negedge clock or posedge clear)
    if (clear)
        qout <= 4'd0;
    else
        qout <= qout + 1'b1;

9. initial 與 always 在 Testbench 裡怎麼配合？

initial初始化 / stimulus
+
always產生 clock
→
DUT接受測試

完整小型 Testbench

`timescale 1ns/1ps

module tb;

    reg clk;
    reg rst_n;
    reg d;
    wire q;

    dff DUT (
        .clk(clk),
        .rst_n(rst_n),
        .d(d),
        .q(q)
    );

    // clock generator
    initial clk = 1'b0;
    always #5 clk = ~clk;

    // stimulus
    initial begin
        rst_n = 1'b0;
        d     = 1'b0;

        #12 rst_n = 1'b1;
        #8  d = 1'b1;
        #10 d = 1'b0;
        #10 d = 1'b1;

        #20 $finish;
    end

endmodule

這裡兩個 procedural blocks 會平行存在： 一個 initial 負責 stimulus，另一個 always 持續產生 clock。

11. initial / always 與 Blocking / Nonblocking

使用情境常見寫法運算子
Testbench stimulusinitial常見 =
Combinational RTLalways @(*)通常 =
Sequential RTLalways @(posedge clk)通常 <=

為什麼 clocked logic 常用 <=？

always @(posedge clk) begin
    q0 <= din;
    q1 <= q0;
    q2 <= q1;
end

所有 RHS 都取 clock edge 前的舊值，較符合一組 flip-flops 同時更新的 gate-level 行為。

課程也直接比較 blocking / nonblocking，並指出 clocked blocks 使用 blocking 可能得到 和 gate-level 不同的結果；nonblocking 更符合這類 sequential hardware 的同步更新。

12. 常見錯誤與考試重點

錯誤 1：沒有 delay / event 的 always

always begin
    a = ~a;
end
這可能形成 zero-time infinite loop，使 simulator 無法正常讓 simulation time 前進。

錯誤 2：Combinational sensitivity list 漏訊號

always @(a) begin
    y = a & b;   // b 改變時 block 不會觸發
end

較安全的傳統 Verilog 寫法：

always @(*) begin
    y = a & b;
end

錯誤 3：Combinational output 沒有完整賦值

always @(*) begin
    if (en)
        y = a;
end

en=0 時 y 必須保留舊值，可能推導出 latch。

錯誤 4：兩個 clocked always 使用 blocking 造成 race

always @(posedge clk)
    x = y;

always @(posedge clk)
    y = x;

課程投影片把這列為 race condition 的例子；改用 nonblocking： 

always @(posedge clk)
    x <= y;

always @(posedge clk)
    y <= x;

錯誤 5：以為 initial 與 always 會照原始碼上下順序執行

不會。不同 procedural blocks 在模擬中是並行的；每個 block 內部的 procedural statements 才有自己的執行順序與事件控制。

錯誤 6：把 testbench 的 #delay 直接當 RTL timing

#10 很適合 testbench 模擬，但一般合成設計的真實硬體 timing 要透過 clock architecture、register、combinational delay 與 synthesis / STA 處理。

14. 自我測驗

Q1：initial 會執行幾次？

一次，從 simulation time 0 開始。

Q2：always #5 clk = ~clk; 在做什麼？

每 5 time units 將 clk 反相一次，因此形成週期 10 time units 的 clock。

Q3：always @(*) 一般用在哪？

常用來描述 combinational procedural logic。

Q4：always @(posedge clk) 代表什麼？

只有 clk 從 0 變 1 的 edge 發生時才執行 block。

Q5：為什麼多行 statement 要用 begin/end？

因為 begin/end 把多個 procedural statements 組成同一個 compound statement。

Q6：不同 initial / always block 是順序執行嗎？

不是，它們在 Verilog 模擬模型中是並行的 procedural processes。

15. 一頁記憶版

initial

time 0 開始，只執行一次。

always

time 0 開始，持續重複。

begin / end

把多行 procedural statements 包成一個區塊。

#delay

常用於 simulation / testbench 時間控制。

@(*)

常見 combinational sensitivity 寫法。

posedge / negedge

描述 edge-triggered event。

最後一句：
initial 適合「從某個起點做一次的流程」； always 適合「持續等待事件並重複反應的硬體/模擬流程」。
