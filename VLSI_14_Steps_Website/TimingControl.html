1. Timing Control 到底在控制什麼？

Verilog 是 event-driven simulation language。Timing Control 的核心目的就是： 控制 procedural statement 何時被執行。

Delay Control

等固定時間後再執行。

#10 x = 1;

Event Control

等某個事件發生後再執行。

@(posedge clk) q <= d;

一句話：
Delay 是「等多久」；Event Control 是「等什麼事件」。

2. Delay Timing Control

課程將 Delay Timing Control 分成兩類： Regular Delay Control 與 Intra-assignment Delay Control。

Regular Delay#25 y <= ~x;
vs.
Intra-assignment Delayy <= #25 ~x;
兩者外觀看起來只是 #25 放的位置不同，但 simulation 語意並不完全相同。

3. Regular Delay Control

課程投影片定義：Regular delay control 會 defer the execution of the entire statement， 也就是整個 statement 等指定時間後才開始執行。

3.1 基本語法

#delay statement;

3.2 例子

#25 y <= ~x;

意思是：先等待 25 time units，再執行 y <= ~x。

t = 0：statement 尚未執行
等待 25
t = 25：計算 RHS 並進行 assignment

3.3 連續兩個 Regular Delay

initial begin
    #25 y <= ~x;
    #15 count <= count + 1;
end
t = 25：第一個 statement 執行
再等待 15
t = 40：第二個 statement 執行

這正是課程投影片用來說明： #25 後第一個 assignment 在 t=25， 接著 #15 使下一個 statement 到 t=40 才執行。

4. Intra-assignment Delay Control

課程投影片定義：Intra-assignment delay control 會 defer the assignment to the left-hand-side variable。

4.1 語法位置

y = #25 ~x;
y <= #25 ~x;

注意 #25 放在 assignment operator 與 RHS 之間。

4.2 Blocking intra-assignment

y = #25 ~x;

概念上，RHS 的值在 statement 被執行時取樣，LHS 在 delay 之後才更新； blocking form 會阻塞目前 procedural flow，直到 assignment 完成。

4.3 Nonblocking intra-assignment

y <= #25 ~x;

RHS 先被取樣，更新 y 的動作排程到 25 time units 之後。 目前 block 可以繼續往下執行其他 statements。

4.4 為什麼課程投影片的時間會不同？

y     <= #25 ~x;
count <= #15 count + 1;

因為 nonblocking intra-assignment 不需要讓整個 block 等 25 才進到下一行， 所以兩個更新可以分別排在 t=25 與 t=15。

t = 0：排程 y 在 t=25 更新
t = 0：接著排程 count 在 t=15 更新
t = 15：count 更新
t = 25：y 更新
這是考試很容易考的地方：
Regular delay 是先「等」再執行整個 statement；
Intra-assignment delay 是把「LHS 更新」安排到未來。

5. Event Control

Event Control 不指定「等幾個 ns」，而是指定： 等某個訊號事件發生。

5.1 一般事件

@(a)
y = b;

當 a 發生變化時，才繼續執行。

5.2 多個訊號

always @(a or b or sel) begin
    if (sel)
        y = b;
    else
        y = a;
end

5.3 使用 @(*)

always @(*) begin
    if (sel)
        y = b;
    else
        y = a;
end

@(*) 常用於 combinational procedural logic， 避免手動 sensitivity list 漏掉 RHS 訊號。

6. Edge-Triggered Event Control

課程投影片明確列出兩種 edge-triggered event control：

posedge

@(posedge clock)

等 clock 上升緣。

negedge

@(negedge clock)

等 clock 下降緣。

6.1 D Flip-Flop

always @(posedge clk) begin
    q <= d;
end

6.2 Negative-edge Register

always @(negedge clk) begin
    q <= d;
end

6.3 課程投影片中的複合 timing control

always @(posedge clock) begin
    reg1 <= #25 in_1;
    reg2 <= @(negedge clock) in_2 ^ in_3;
    reg3 <= in_1;
end

這個例子同時展示： clock 正緣啟動 procedural block、intra-assignment delay、以及 assignment 內等待另一個 edge event。

7. 多事件 Sensitivity：Clock + Reset

7.1 正緣 clock + 負緣 reset

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 8'h00;
    else
        q <= d;
end

這表示： clk 上升緣 或 rst_n 下降緣 任一事件發生，都會進入 block。

7.2 課程中的 4-bit Counter

always @(negedge clock or posedge clear)
    if (clear)
        qout <= 4'd0;
    else
        qout <= qout + 1'b1;

課程範例是 clock 下降緣計數，而 clear 上升緣立即清零。

9. Timing Control 在 Testbench 裡的用途

Testbench 是 Timing Control 最直觀的應用場景，因為你常常需要： 產生 clock、產生 reset、安排 input stimulus、等待某個 DUT event、最後結束模擬。 

`timescale 1ns/1ps

module tb;

    reg clk;
    reg rst_n;
    reg [7:0] data;
    wire [7:0] q;

    DUT U0(
        .clk(clk),
        .rst_n(rst_n),
        .data(data),
        .q(q)
    );

    initial clk = 0;
    always #5 clk = ~clk;

    initial begin
        rst_n = 0;
        data  = 0;

        #12 rst_n = 1;

        @(negedge clk);
        data = 8'h12;

        @(negedge clk);
        data = 8'h34;

        @(negedge clk);
        data = 8'h56;

        #20 $finish;
    end

endmodule
這個 testbench 同時用了： #delay、@(negedge clk)、clock generator， 是 Timing Control 的綜合練習。

10. Timing Control 與可合成 RTL

在一般 synchronous RTL 裡，最重要、最常合成的 timing control 是： @(posedge clk)、@(negedge clk)， 以及 reset edge。

典型可合成風格

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 0;
    else
        q <= d;
end

模擬型 delay

#10 q = d;
不要把兩件事混在一起：
#10 表示 simulator 的時間控制；它通常不是在一般 ASIC RTL 中要求 synthesis 幫你做「固定 10 ns delay hardware」的方式。真實 cell delay 會由 library timing model、 synthesis、P&R、STA 等流程分析。

12. 常見錯誤與考試重點

錯誤 1：把 #delay 當成 clock

#10 q = d;

這不是 flip-flop；它只是 simulation delay。

錯誤 2：混淆 Regular 與 Intra-assignment Delay

#10 y = a;   // regular delay
y = #10 a;   // intra-assignment delay

第一個先等 10 才開始整個 assignment；第二個是 assignment statement 內部的 delay。

錯誤 3：以為連續的 #delay 都從 t=0 算

#10 a = 1;
#20 b = 1;

第二個 delay 是從第一個 statement 完成後再算，因此 b 在 t=30 更新，不是 t=20。

錯誤 4：Combinational sensitivity list 漏掉訊號

always @(a)
    y = a & b;

b 改變時不會觸發。較安全：

always @(*)
    y = a & b;

錯誤 5：Clocked logic 用錯 edge

posedge 和 negedge 會直接決定是哪一個 clock edge 更新。 設計規格要求正緣觸發時，不可誤寫成 negedge。

錯誤 6：把 reset edge 的極性搞反

always @(posedge clk or negedge rst_n)

這表示 active-low asynchronous reset；因為 reset 的「啟動事件」是 rst_n 從 1 掉到 0。

13. 自我測驗

Q1：#25 y <= ~x; 屬於哪種 Timing Control？

Regular delay control。整個 statement 延後 25 time units 才執行。

Q2：y <= #25 ~x; 屬於哪種 Timing Control？

Intra-assignment delay control。LHS 更新排程到 25 time units 之後。

Q3：@(posedge clk) 在等什麼？

等待 clk 發生上升緣事件。

Q4：always @(posedge clk or negedge rst_n) 何時會執行？

clk 上升緣或 rst_n 下降緣任一事件發生時。

Q5：#10 a=1; #20 b=1; 若從 t=0 開始，b 何時更新？

t=30。

Q6：a<=#10 1; b<=#20 1; 兩行都在 t=0 執行時，何時更新？

a 在 t=10；b 在 t=20。

Timing Control 的核心不是「時間數字」本身，而是精確描述 procedural statement 何時被啟動、何時取樣 RHS、何時更新 LHS。
