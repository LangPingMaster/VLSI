1. Cell Characterization 是什麼？

課程對 Cell Characterization 的核心定義是： 在不同 PVT（Process、Voltage、Temperature）corners 下，執行大量 transistor-level SPICE simulations， 量測 standard cell 的 delay、slew rate 與 power。

Transistor-Level Cell例如 INV / NAND / DFF
→
SPICE Simulation
→
Sweep ConditionsPVT / Slew / Load
→
MeasureDelay / Slew / Power
→
Library Model.lib / .db
一句話：Characterization 就是在真正使用 cell 之前，先把它在很多 operating conditions 下的「速度、輸出轉換品質、耗電」量清楚。

2. 為什麼不能只知道 Boolean Function？

假設一顆 inverter： 

Y = ~A

這只告訴你功能，但不知道：

有多快？

Input 改變後，Output 多久才跟著改變？

邊緣有多陡？

Output transition 是快還是慢？

耗多少電？

Switching / internal / leakage power 是多少？

因此 Standard Cell 不只需要 function，也要事先 characterize area、timing、power、functionality。 課程把這些稱為 standard cell 的 pre-characterized attributes。

同樣是 INV_X1，在不同 PVT、不同 input slew、不同 output load 下，delay 不會是同一個固定數字。

3. Characterization 基本流程

Step 1：準備 transistor-level cell

.SUBCKT INV_X1 A Y VDD VSS
MP1 Y A VDD VDD PMOS ...
MN1 Y A VSS VSS NMOS ...
.ENDS INV_X1

Step 2：設定 operating condition

選擇 process corner、supply voltage、temperature。

Step 3：設定 input waveform

改變 input transition time，例如 fast / medium / slow slew。

Step 4：設定 output load

在 output 接不同大小的 capacitance。

Step 5：執行 SPICE

量 input/output waveform。

Step 6：萃取量測結果

取得 propagation delay、output slew、power。

Step 7：整理成 tables/models

將結果寫成 library timing/power model，提供 synthesis / STA 使用。

課程使用「thousands of transistor-level SPICE simulations」描述這個流程，重點就是大量掃描條件，不是只模擬一次。

4. PVT Corners

PVT意思為什麼重要
P = Process製程變異造成 transistor 快慢不同影響 drive current、delay、leakage
V = VoltageSupply voltage 不同影響速度與功耗
T = TemperatureOperating temperature 不同影響 transistor 行為、delay、leakage

概念例子

Corner A:
Process = Slow
Voltage = Low
Temperature = High

Corner B:
Process = Typical
Voltage = Nominal
Temperature = Room

Corner C:
Process = Fast
Voltage = High
Temperature = Low
上面的 corner 命名是概念示意；課程明確支持的是 Characterization 需要跨 Process、Voltage、Temperature corners 執行。

5. Propagation Delay

Propagation delay 描述 input transition 發生後，output response 到達定義觀測點所需的時間。 課程以 inverter cell 的 timing delay 為例。

5.1 Input 0→1，Inverter Output 1→0

A : ____/‾‾‾‾
Y : ‾‾‾‾\____
        ← delay →

5.2 Input 1→0，Inverter Output 0→1

A : ‾‾‾‾\____
Y : ____/‾‾‾‾
        ← delay →

實務 timing library 通常會區分 output rise / output fall， 因為 PMOS 與 NMOS network 的驅動能力不一定完全相同。

「rise/fall 分開」是常見 library 實務補充；課程頁面本身明確說的是 characterization 量測 cell delay、slew、power。

6. Slew Rate / Transition Time

課程 NLDM 頁面使用 Input Slew (Transition Time) 作為 delay table 的一個 index。 Slew 可以理解為訊號從 low 到 high 或 high 到 low 的轉換快慢。

Fast Slew

____/‾‾‾‾

transition 很快，邊緣較陡。

Slow Slew

______/‾‾‾

transition 較慢，邊緣較緩。

為什麼 Input Slew 會影響 Delay？

因為 transistor 不會在 input 還沒轉換完成時瞬間到達完整驅動狀態。 所以不同 input transition time 會造成不同 cell response。

7. Output Load Capacitance

NLDM 的第二個重要 index 是 Output Load Capacitance。 Output load 可以來自後級 cell input capacitance、wire capacitance 等。

例子：一顆 INV 驅動一顆 INV

INV1 ───→ INV2
          ↑
       input cap

例子：一顆 INV 驅動四顆 gates

            → Gate1
INV1 ───────→ Gate2
            → Gate3
            → Gate4

第二種情況 output load 通常更大，因此驅動更困難，output transition 可能變慢，cell delay 也可能增加。

這也解釋了為什麼 library 需要 X1、X2、X4 等不同 drive-strength cells：大 load 時可以選更強的 cell。

8. Power Characterization

課程明確指出 characterization 會量 power，而且 `.lib/.db` 包含 dynamic 與 leakage power 資訊。

Dynamic Power

與 switching activity、capacitance、voltage、frequency 等因素有關。

Leakage Power

即使沒有切換，transistor 仍可能有 leakage current。

概念例子：X1 vs X4

INV_X1 : smaller transistor / weaker drive
INV_X4 : larger effective drive / often larger cap and power

功能相同，但 timing / power / area 特性不同，因此 characterization 必須分別建立模型。

9. NLDM：Non-Linear Delay Model

課程明確指出： NLDM 的 delay 存在 2D lookup table 中，索引為 Input Slew 與 Output Load Capacitance。

Input Slew ↓ / Output Load →0.0010.0100.050
0.0100.0200.0300.050
0.0500.0300.0450.070
0.1000.0500.0700.110
上表數字是教學用假設值，不是課程的實際 cell data；課程提供的是 2D table 結構與兩個 index 的概念。

示意 Liberty table

cell_rise(delay_template) {
    index_1("0.01, 0.05, 0.10");   // Input Slew
    index_2("0.001, 0.01, 0.05");  // Output Load

    values(
      "0.020, 0.030, 0.050",
      "0.030, 0.045, 0.070",
      "0.050, 0.070, 0.110"
    );
}
記憶：Input 越慢、Load 越大，cell 通常越難快速切換，因此 delay table 會反映這種 dependence。

10. 如果 Slew / Load 不剛好落在 Table Index 呢？

這一節是為幫助理解 NLDM 的延伸說明；課程片段本身只明確說 delay 儲存在以 input slew 與 output load 為 index 的 2D lookup tables。

實際使用時，STA tool 會根據目前 net 的 slew/load，在 table 中查找附近的資料點，並用 library model 的方法得到對應 delay。 可以把概念想成： 

Input Slew = 0.035
Output Load = 0.020

不是表格中的精確格點
→ 使用附近 table entries
→ 得到估計 delay

11. 大量 Characterization 例子

例 1：INV_X1 — 小 Load

Input Slew : Fast
Output Load: Small

Input Slew : Fast
Output Load: Large

→ 記錄另一組 delay/slew/power

例 3：INV_X1 — Slow Input Slew

→ transistor turn-on / turn-off 過程不同
→ cell delay 與 output transition 重新量測

例 4：INV_X1 — 多個 Slew × 多個 Load

Slew = [S1, S2, S3, S4]
Load = [C1, C2, C3, C4]

總共至少形成：
S1×C1, S1×C2, ...
S4×C4

例 5：INV_X1 vs INV_X4

INV_X1 → characterize
INV_X4 → characterize separately

兩者功能都是 inverter，但 transistor sizing 不同，因此 timing / slew / power table 不可直接共用。

例 6：NAND2_X1

Y = ~(A & B)

Characterization 不只要知道 Boolean function，還要量 input transition 經過 transistor network 後造成的 output delay / slew / power。

例 7：NAND2 不同輸入 Pin

A changes, B = 1
B changes, A = 1

不同 input pin 到 output 的 timing path 可以視為不同 timing arc；實務 library 會分別描述相關 timing behavior。

「timing arc」的說明是實務延伸；課程這一頁沒有逐項列 timing arc syntax。

MUX 的不同 input-to-output path 也需要 timing characterization，讓 STA 知道不同選擇路徑的 timing behavior。

Sequential cell 的 characterization 不只需要 combinational propagation delay，還常會建立 clock-related timing constraints / response models。

       ←setup→

例 13：High Output Fanout

BUF_X1 → 1 load
BUF_X1 → 8 loads

8 loads 對應更大的 effective load，因此 characterization table 可讓工具估計 delay 與 slew 的變化。

例 14：Cell Upsizing

Current cell : INV_X1
Timing too slow

FF → NAND2 → AOI → INV → FF

STA 可以依每一顆 cell 的 characterized timing table，配合實際 slew / load，估計整條 path delay。

12. Characterization 結果如何進入 .lib / .db？

課程指出 `.lib/.db` 是 Timing & Power View，內容包含： propagation delay、setup/hold times、dynamic / leakage power，以及 NLDM / CCS models。

Conceptual Flow

→

→

→
EDA Tools

示意 cell model

cell (INV_X1) {
    area : 1.20;

    pin(A) {
        direction : input;
        capacitance : ...;
    }

    pin(ZN) {
        direction : output;
        function : "!A";

        timing() {
            related_pin : "A";
            cell_rise(...);
            cell_fall(...);
            rise_transition(...);
            fall_transition(...);
        }
    }
}
這段 Liberty syntax 是教學化示意，用來說明 characterization data 最後會以 timing/power model 形式存在 library；課程沒有提供這段完整文字。

13. Synthesis / STA 怎麼使用 Characterized Data？

13.1 Synthesis

比較不同 cells 的 area、timing、power，決定要用哪一顆 standard cell。 

AND2_X1
AND2_X2
AND2_X4

功能一樣
→ 但 timing / area / power 不一樣
→ tool 根據目標選擇

13.2 Static Timing Analysis

STA 根據每一級實際 input slew 與 output load 去查 timing model，累積 path delay。

13.3 Timing Optimization

Path too slow
→ stronger drive cell
→ buffer insertion
→ logic restructuring
→ re-evaluate timing

這些操作都依賴 characterization data，而不是只依賴 Boolean logic。

14. 常見誤解與考試重點

誤解 1：Cell delay 是固定值

錯。課程的 NLDM 明確指出 delay 依 Input Slew 與 Output Load Capacitance 查 2D table。

誤解 2：Characterization 只模擬一個 corner

錯。課程明確說是在 PVT corners 下執行大量 SPICE simulations。

誤解 3：只量 delay 就夠了

錯。課程明確列出 delay、slew rate、power。

誤解 4：X1 / X4 可以共用同一 timing table

不應這樣理解。它們 drive strength 不同，cell characteristics 不同，因此需要各自的模型。

誤解 5：Verilog functional model 可以取代 transistor-level characterization

錯。Verilog model 可描述 logic behavior，但 characterization 需要 transistor-level SPICE behavior。

誤解 6：Output load 與 timing 無關

錯。課程明確把 Output Load Capacitance 列為 NLDM delay table 的 index。

15. 自我測驗

Q1：Cell Characterization 的核心工作是什麼？

跨 PVT corners 執行大量 transistor-level SPICE simulations，量測 cell delay、slew rate、power。

Q2：PVT 三個字母代表什麼？

Process、Voltage、Temperature。

Q3：NLDM 的兩個主要 index 是什麼？

Input Slew（Transition Time）與 Output Load Capacitance。

Q4：為什麼 INV_X1 和 INV_X4 都需要 characterization？

因為 drive strength 與 transistor sizing 不同，所以 timing、slew、power 特性不同。

Q5：Characterization 結果主要寫入哪類 library view？

Timing & Power View，也就是課程列出的 `.lib/.db`。

Q6：Characterization 只是為 simulation 用嗎？

不是。其 timing/power model 會被 synthesis、STA 與 optimization 使用。
