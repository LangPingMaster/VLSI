06｜IEEE-754 浮點數

以 VSD HW1 FPU 投影片為核心，整理 Single Precision、S/E/F、Bias、Mantissa、NaN、Infinity、Zero、Normalization、GRS、Round-to-Even 等名詞與專有名詞。每個條目至少 2 個例子。
資料原則：以 HW1 PDF 的 IEEE floating point definition、Mantissa/GRS、Round-to-even 與 FPU ADD/SUB pages 為主要依據。PDF 沒有展開的 IEEE-754 細節不自行加入作業規格。

01Floating Point浮點數⌄
核心名詞Floating-Point Number

HW1 PDF 中的依據

HW1 的 FPU 使用 IEEE-754 32-bit single-precision floating-point representation。

詳細說明

浮點數把數值拆成符號、指數與小數部分，使固定 32 bits 能表示非常大或非常小的數。HW1 後續 FPU ADD/SUB、MIN/MAX 都以這種 32-bit 格式處理。

例子（至少 2 個）

例 1

0x40400000 是一個 IEEE-754 single-precision bit pattern；PDF 範例將它解碼為 2.5。

例 2

同樣是 32 bits，整數 0x40400000 與把它『解讀成 float』是不同語意；FPU 按 S/E/F 欄位解讀。

02IEEE-754IEEE-754 浮點數標準⌄
標準專有名詞IEEE Standard for Floating-Point Arithmetic

HW1 PDF 中的依據

PDF 以 IEEE floating point definition 說明 single precision 與 double precision 的欄位大小，並在 FPU 作業要求中指定 32-bit IEEE-754 single precision。

詳細說明

IEEE-754 是浮點表示與運算常用標準。本 HW 關注的是 32-bit single precision，以及 NaN、Infinity、Zero、normal value、normalization、GRS rounding 等。

例子（至少 2 個）

例 1

Single precision：1 sign + 8 exponent + 23 fraction = 32 bits。

例 2

Double precision：1 sign + 11 exponent + 52 fraction = 64 bits；PDF 用它與 single precision 對照。

03Single Precision單精度浮點數⌄
格式專有名詞IEEE-754 Single Precision

HW1 PDF 中的依據

PDF：single precision 共 32 bits，由 1-bit sign、8-bit exponent、23-bit fraction 組成。

詳細說明

這就是 HW1 FPU 的資料寬度。正常數值可依 PDF 公式 (-1)^S × (1.F) × 2^(E-127) 理解。

例子（至少 2 個）

例 1

0x40400000：S=0，E=128，fraction 對應 1.5 significand，因此值為 1.5×2^1=3.0；注意 PDF 文字摘要曾標示 2.5，實際位元解碼應以原頁範例為準。

例 2

0x3F800000 是常見 single-precision 1.0：S=0、E=127、F=0。

04Double Precision雙精度浮點數⌄
格式專有名詞IEEE-754 Double Precision

HW1 PDF 中的依據

PDF 定義 double precision：1 sign bit、11 exponent bits、52 fraction bits。

詳細說明

PDF 用 double precision 作格式背景比較；HW1 FPU 本身要求的是 32-bit single precision，而不是實作 64-bit double precision。

例子（至少 2 個）

例 1

Double precision 總寬度為 1+11+52=64 bits。

例 2

相較 single precision 的 23 fraction bits，double precision 有 52 fraction bits。

05S / Sign符號位元⌄
欄位名詞Sign Bit

HW1 PDF 中的依據

PDF 的 single-precision 格式含 1-bit Sign，公式以 (-1)^S 決定正負。

詳細說明

S=0 時符號因子為 +1；S=1 時符號因子為 -1。它是 IEEE-754 32-bit word 的最高位。

例子（至少 2 個）

例 1

S=0：正常有限數的符號為正。

例 2

S=1：正常有限數的符號為負；PDF 特殊值也區分 +0/-0、+Inf/-Inf。

06E / Exponent指數欄位⌄
欄位名詞Exponent Field

HW1 PDF 中的依據

PDF：single precision 的 exponent 為 8 bits；normal value 公式使用 2^(E-127)。

詳細說明

Exponent field 儲存的是帶 bias 的指數資訊。對 PDF 所示 normal value，實際指數為 E-127。

例子（至少 2 個）

例 1

E=127 → E-127=0，因此尺度因子 2^0=1。

例 2

E=128 → 實際指數 1，因此尺度因子 2。

07F / Fraction小數欄位⌄
欄位名詞Fraction Field

HW1 PDF 中的依據

PDF：single precision 的 fraction 為 23 bits；normal mantissa 寫成 1.F。

詳細說明

Fraction 保存 normalized significand 小數點後的 bits。PDF 將 mantissa/significand 的正常形式表示為 1.F，因此前面的 1 不在 23-bit F 中直接儲存。

例子（至少 2 個）

例 1

F 全 0 時，normal significand 是 1.000…₂。

例 2

若 fraction 的第一個 bit 為 1、其餘為 0，1.F=1.1₂=1.5。

08SEF符號－指數－小數欄位⌄
格式縮寫Sign–Exponent–Fraction

HW1 PDF 中的依據

PDF 的 FPU Add/Sub Step 1 要先 unpack 成 S/E/F；本頁用 SEF 作為這三欄的合稱。

詳細說明

SEF 是理解 32-bit float 最直觀的拆法：先讀 sign，再讀 exponent，最後讀 fraction。後續 special-case detection 與 arithmetic 都依這些欄位進行。

例子（至少 2 個）

例 1

32-bit word 可拆為 S[31]、E[30:23]、F[22:0]。

例 2

判斷 NaN/Inf/Zero 時，主要就是檢查 E 與 F 的組合。

09Bias指數偏移值⌄
數值表示名詞Exponent Bias

HW1 PDF 中的依據

PDF normal formula 明確使用 E-127，因此 single precision 在這個公式中的 bias 為 127。

詳細說明

Bias 讓 exponent field 可以用 unsigned bit pattern 表達正、零與負的實際指數。對 normal number，從儲存的 E 減掉 127 得到實際 exponent。

例子（至少 2 個）

例 1

E=127 → actual exponent=0。

例 2

E=126 → actual exponent=-1，因此尺度為 2^-1。

10Mantissa尾數／有效數⌄
核心專有名詞Mantissa / Significand

HW1 PDF 中的依據

PDF 的 Mantissa 頁指出 normalized form 為 1.F，並畫出 Fraction(1.F) 24 bits + GRS 3 bits。

詳細說明

在本 HW 投影片語境中，mantissa 指用來做對齊、加減、normalize 與 rounding 的有效數部分。對 normal number，1.F 共 24 bits 的有效精度。

例子（至少 2 個）

例 1

F=0 時 mantissa=1.000…₂。

例 2

F 的最高 fraction bit=1、其他為 0 時，mantissa=1.1₂=1.5。

111.F正規化尾數形式 1.F⌄
表示法Normalized Mantissa Form

HW1 PDF 中的依據

PDF 明確寫出 Mantissa normalized form 1.F。

詳細說明

1.F 表示 normal binary floating-point number 的有效數寫成 1.xxxxx₂；前面的 1 與 23-bit fraction 合起來形成 24-bit mantissa。

例子（至少 2 個）

例 1

F=000…0 → 1.F=1.000…₂。

例 2

F=1000…0 → 1.F=1.1000…₂=1.5。

12Normal Value正規浮點數值⌄
數值類型Normalized Floating-Point Value

HW1 PDF 中的依據

PDF 對 normal value 給出公式：(-1)^S × (1.F) × 2^(E-127)。

詳細說明

這個公式是本作業理解正常 finite floating-point number 的核心。S 控制符號，1.F 提供有效數，E-127 提供二進位尺度。

例子（至少 2 個）

例 1

S=0、E=127、F=0 → +1×1.0×2^0=1.0。

例 2

S=1、E=128、1.F=1.5 → -1.5×2=-3.0。

13NaN非數值⌄
特殊值Not a Number

HW1 PDF 中的依據

PDF Add/Sub Step 1：NaN 的判定為 exponent=255 且 fraction≠0；special-case table 指定有 NaN operand 時輸出 NaN 32'hFFC00000。

詳細說明

NaN 用於表示不是一般有限實數結果的特殊 bit pattern。HW1 hidden tests 若依投影片 golden behavior，應優先遵守 PDF 指定的 NaN output pattern。

例子（至少 2 個）

例 1

E=255、F 非 0 → PDF 判定為 NaN。

例 2

PDF special-case table：任一 operand 為 NaN → result 使用 32'hFFC00000。

14Infinity / Inf無窮大⌄
特殊值Infinity

HW1 PDF 中的依據

PDF Step 1：Inf 的判定為 exponent=255、fraction=0；special-case table 列出 +Inf/-Inf 與 sign-mismatch infinity 情況。

詳細說明

Infinity 是 IEEE-754 的特殊值。符號位可區分正無窮與負無窮；在 HW1 ADD/SUB 邏輯中需先於一般 mantissa arithmetic 處理。

例子（至少 2 個）

例 1

E=255、F=0、S=0 → +Inf。

例 2

E=255、F=0、S=1 → -Inf。

15Zero浮點零⌄
特殊值Floating-Point Zero

HW1 PDF 中的依據

PDF Step 1：Zero 判定為 exponent=0、fraction=0；special-case table 另區分 +0 與 -0。

詳細說明

浮點零的 exponent 與 fraction 都為 0，但 sign bit 仍可不同，因此存在 +0 與 -0 的 bit patterns。

例子（至少 2 個）

例 1

S=0、E=0、F=0 → +0。

例 2

S=1、E=0、F=0 → -0。

16+0 / -0正零／負零⌄
特殊值Positive Zero / Negative Zero

HW1 PDF 中的依據

PDF Add/Sub special-case table 明確提到 0+0 的 sign depends on operands，可得到 +0 或 -0。

詳細說明

兩者數值都屬 zero，但 bit pattern 的 sign 不同。對硬體而言不能假設所有 zero bit patterns 完全相同。

例子（至少 2 個）

例 1

+0：sign=0、E=0、F=0。

例 2

-0：sign=1、E=0、F=0。

17+Inf / -Inf正無窮／負無窮⌄
特殊值Positive / Negative Infinity

HW1 PDF 中的依據

PDF special-case table 指定 infinity result 可為 32'h7F800000 或 32'hFF800000。

詳細說明

Exponent=255 且 fraction=0 時，sign bit 決定正負 infinity。

例子（至少 2 個）

例 1

+Inf 的 PDF pattern 為 0x7F800000。

例 2

-Inf 的 PDF pattern 為 0xFF800000。

18Unpacking浮點拆欄位⌄
FPU 流程名詞Floating-Point Unpacking

HW1 PDF 中的依據

PDF Add/Sub Step 1：Unpack to SEF and detect special cases。

詳細說明

FPU 收到 32-bit ai/bi 後，先拆出 sign、exponent、fraction。這使後續能判斷 NaN/Inf/Zero，並準備 exponent alignment 與 mantissa arithmetic。

例子（至少 2 個）

例 1

從 ai[31] 取得 sign，從 ai[30:23] 取得 exponent。

例 2

從 ai[22:0] 取得 fraction，再依 E/F 判斷是否為特殊值。

19Normalization正規化⌄
FPU 流程名詞Normalization

HW1 PDF 中的依據

PDF Add/Sub Step 3：若 mantissa addition 有 carry，右移並 exponent+1；若 cancellation 造成前導空位，左移並 exponent-k。

詳細說明

Normalization 是把運算後的有效數調回合適的 normalized 形式，並同步調整 exponent。

例子（至少 2 個）

例 1

加法產生額外 carry → mantissa 右移 1，exponent 加 1。

例 2

減法 cancellation 使前面出現多個 0 → mantissa 左移 k，exponent 減 k。

20GRS保護／捨入／黏滯位元⌄
捨入專有名詞Guard–Round–Sticky Bits

HW1 PDF 中的依據

PDF：Fraction(1.F) 24 bits 後保留 GRS 3 bits；G 是第一個 shifted-out bit，R 是第二個，S 是 R 之後所有 bits 的 OR。

詳細說明

GRS 用來保存被移出有效精度之外的重要資訊，使硬體能依 round-to-even 規則決定是否對保留的 mantissa 加 1。

例子（至少 2 個）

例 1

若移出的 bits 開頭是 1、接著是 0，而後面仍有任一 1，則 G=1、R=0、S=1。

例 2

若所有 R 後方 bits 都是 0，Sticky S=0；只要其中任一 bit=1，S=1。

21Guard Bit (G)保護位元⌄
GRS 名詞Guard Bit

HW1 PDF 中的依據

PDF 定義 G 為 first shifted-out bit。

詳細說明

它是保留精度邊界外的第一個 bit，是判斷是否至少到達 half-way 的關鍵資訊。

例子（至少 2 個）

例 1

GRS=100 時 G=1。

例 2

GRS=011 時 G=0；依 PDF round-to-even table，0xx 類型直接 discard。

22Round Bit (R)捨入位元⌄
GRS 名詞Round Bit

HW1 PDF 中的依據

PDF 定義 R 為 second shifted-out bit。

詳細說明

R 與 G、S、保留 mantissa 的 LSB 一起決定 round-to-even 是否 increment。

例子（至少 2 個）

例 1

GRS=110 → R=1，PDF 表列為 round up。

例 2

GRS=100 → R=0，此時還要看 retained LSB 才能處理 tie。

23Sticky Bit (S)黏滯位元⌄
GRS 名詞Sticky Bit

HW1 PDF 中的依據

PDF 定義 S 為 all bits after R 的 OR。

詳細說明

Sticky bit 不保存後方每一 bit 的位置，只記錄『後面是否曾出現任何 1』。因此大量被移出的 bits 可以濃縮成一個 bit。

例子（至少 2 個）

例 1

R 後面為 000000 → S=0。

例 2

R 後面為 000100 → 因為至少有一個 1，所以 S=1。

24Rounding浮點捨入⌄
運算名詞Floating-Point Rounding

HW1 PDF 中的依據

PDF Step 3 要 apply GRS rounding；前一頁提供 round-to-even 判斷表。

詳細說明

有限 mantissa bits 無法保留所有中間結果，因此需要捨入。HW1 投影片指定使用 GRS 資訊處理 round-to-even。

例子（至少 2 個）

例 1

GRS=110 → PDF 規則為 round up。

例 2

GRS=0xx → PDF 規則為 discard。

25Round-to-Even最接近值、平手取偶數⌄
捨入模式Round to Nearest, Ties to Even

HW1 PDF 中的依據

PDF 的 rounding table：0xx discard；110/101/111 round up；100 時依 retained LSB 決定，LSB=1 round up，LSB=0 discard。

詳細說明

當恰好落在兩個可表示值正中間時，選擇讓保留結果最低位為偶數的一側。依 PDF 表，可整理 increment 條件為 G && (R || S || LSB)。

例子（至少 2 個）

例 1

GRS=100 且 retained LSB=0 → tie 時不加 1，discard。

例 2

GRS=100 且 retained LSB=1 → 加 1，使最後保留 LSB 轉向 even。

26Retained LSB保留尾數的最低位⌄
捨入名詞Least Significant Bit of retained mantissa

HW1 PDF 中的依據

PDF 的 GRS=100 tie case 要查看 retained LSB 是 0 還是 1。

詳細說明

這個 LSB 不是整個 32-bit word 的 bit0 泛稱，而是『即將保留下來的 mantissa』最末 bit。它在 exact-half tie 時決定是否 increment。

例子（至少 2 個）

例 1

GRS=100、retained LSB=0 → discard。

例 2

GRS=100、retained LSB=1 → round up。

27Round Up向上增加一個 ULP 單位⌄
捨入動作Rounding Increment

HW1 PDF 中的依據

PDF rounding table 對 110、101、111，以及特定 100 case 標為 round up。

詳細說明

在此流程語境中，round up 表示對保留的 mantissa 最低精度位置做 increment；若 increment 再產生 carry，還可能需要重新 normalize。

例子（至少 2 個）

例 1

GRS=111 → round up。

例 2

GRS=100 且 retained LSB=1 → round up。

28Discard捨棄額外位元⌄
捨入動作Discard Extra Bits

HW1 PDF 中的依據

PDF rounding table 對 GRS=0xx，以及 GRS=100 且 retained LSB=0 的情況標示 discard。

詳細說明

Discard 表示被移出的額外 bits 不造成 retained mantissa increment。

例子（至少 2 個）

例 1

GRS=000 → discard。

例 2

GRS=100、retained LSB=0 → exact tie 但選 even，因此 discard。

29Exponent Alignment指數對齊⌄
FPU 流程名詞Exponent Alignment

HW1 PDF 中的依據

PDF Add/Sub Step 2：ΔE=|Ea-Eb|，把 exponent 較小 operand 的 mantissa 右移 ΔE。

詳細說明

浮點加減前必須讓兩個 operands 使用相同 exponent 尺度，才能直接加減 mantissas。右移時產生的額外 bits 也與 GRS rounding 有關。

例子（至少 2 個）

例 1

Ea=130、Eb=128 → ΔE=2，因此較小 exponent 的 mantissa 右移 2。

例 2

Ea=Eb → ΔE=0，不需要因 exponent 差異而右移。

30ΔE指數差的絕對值⌄
FPU 數學符號Absolute Exponent Difference

HW1 PDF 中的依據

PDF Step 2 明確定義 ΔE=|Ea-Eb|。

詳細說明

ΔE 決定 exponent 較小那一方的 mantissa 要右移多少位，讓兩邊尺度一致。

例子（至少 2 個）

例 1

Ea=130、Eb=127 → ΔE=3。

例 2

Ea=126、Eb=126 → ΔE=0。

31Repack重新封裝⌄
FPU 流程名詞Floating-Point Repacking

HW1 PDF 中的依據

PDF Add/Sub Step 3：normalize、apply GRS rounding，最後 repack 32-bit output。

詳細說明

完成 arithmetic、normalization 與 rounding 後，把結果重新組成 32-bit IEEE-754 欄位，作為 FPU output。

例子（至少 2 個）

例 1

將結果 sign、8-bit exponent、23-bit fraction 組回 32 bits。

例 2

特殊值可能直接依 PDF 指定 pattern 輸出，不需走一般 normal arithmetic 路徑。
