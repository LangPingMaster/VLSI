Code Files

design.sv

`timescale 1ns/1ps
module binarization(
 input wire clk, input wire rst_n, input wire [7:0] pix_in,
 input wire [7:0] threshold, output reg pix_out
);
always @(posedge clk or negedge rst_n) begin
 if(!rst_n) pix_out <= 1'b0;
 else if(pix_in >= threshold) pix_out <= 1'b1;
 else pix_out <= 1'b0;
end
endmodule

testbench_image.sv

`timescale 1ns/1ps
module tb_binarization_image;
localparam N=65536;
reg clk, rst_n; reg [7:0] pix_in, threshold; wire pix_out;
reg [7:0] img_mem [0:N-1]; integer i, fout;
binarization dut(.clk(clk),.rst_n(rst_n),.pix_in(pix_in),.threshold(threshold),.pix_out(pix_out));
initial clk=0; always #5 clk=~clk;
initial begin
 $readmemh("gray.hex",img_mem);
 fout=$fopen("rtl_binary.txt","w");
 threshold=8'd128; rst_n=0; pix_in=0; #12 rst_n=1;
 for(i=0;i<N;i=i+1) begin
   @(negedge clk); pix_in=img_mem[i];
   @(posedge clk); #1; $fwrite(fout,"%0d\n",pix_out);
 end
 $fclose(fout); $display("Processed %0d pixels. Done.",N); #10 $finish;
end
endmodule

prepare_image.py

from PIL import Image
from pathlib import Path
THRESHOLD=128
INPUT=Path("../images/drawBbox_result_p2.bmp")
img=Image.open(INPUT).convert("RGB")
gray=img.convert("L")
gray.save("../images/sample_gray.png")
vals=list(gray.getdata())
Path("../data/gray.hex").write_text("\n".join(f"{v:02x}" for v in vals)+"\n")
Path("../data/golden_binary.txt").write_text("\n".join("1" if v>=THRESHOLD else "0" for v in vals)+"\n")
gray.point(lambda p:255 if p>=THRESHOLD else 0).save("../images/sample_binary_golden.png")
print("Prepared",len(vals),"pixels")

rebuild_and_compare.py

from pathlib import Path
from PIL import Image
import numpy as np
golden=np.loadtxt("../data/golden_binary.txt",dtype=np.uint8)
rtl=np.loadtxt("rtl_binary.txt",dtype=np.uint8)
if rtl.size != golden.size: raise SystemExit(f"size mismatch: RTL={rtl.size}, golden={golden.size}")
mismatch=int(np.count_nonzero(rtl!=golden))
Image.fromarray((rtl.reshape(256,256)*255).astype(np.uint8),mode="L").save("../images/sample_binary_rtl.png")
print("Total pixels:",golden.size); print("Mismatch pixels:",mismatch); print("Accuracy: %.2f%%"%((1-mismatch/golden.size)*100)); print("PASS" if mismatch==0 else "FAIL")

二、code/：程式與模擬核心

檔案角色詳細說明是否通常要修改
code/design.sv RTL Design 真正要驗證的硬體設計。模組名稱為 binarization，輸入包含 clk、rst_n、8-bit pix_in 與 8-bit threshold， 輸出為 1-bit pix_out。每個 clock 正緣判斷 pix_in >= threshold；成立輸出 1，不成立輸出 0。 因為使用 always @(posedge clk or negedge rst_n)， 所以這是一個有暫存器的 synchronous pixel-processing RTL，而不是純 combinational comparator。 要改硬體演算法時才修改。
code/testbench_image.sv SystemVerilog Testbench 負責驅動 65,536 個 pixel。N=65536 對應 256×256 影像。 Testbench 使用 $readmemh("gray.hex", img_mem) 載入灰階 pixel， threshold 設為 8'd128，每次在 clock 負緣送入一個 pixel， 再於下一個 clock 正緣後讀取 pix_out。 每一個 RTL 結果透過 $fwrite 寫入 rtl_binary.txt。 改影像尺寸、threshold、輸入檔名或刺激方式時修改。
code/prepare_image.py Python 前處理／Golden Model 此程式目前讀取 ../images/drawBbox_result_p2.bmp， 先轉 RGB，再使用 Pillow 的 convert("L") 轉成 8-bit grayscale。 接著產生三類結果： sample_gray.png、 ../data/gray.hex、 ../data/golden_binary.txt。 Golden binary 的規則與 RTL 相同：灰階值大於等於 128 記為 1，否則為 0。 因此它同時扮演「輸入資料產生器」和「軟體參考模型」兩個角色。 換影像或 threshold 時通常要修改。
code/rebuild_and_compare.py 結果重建與驗證 讀取 Python Golden Model 的 ../data/golden_binary.txt 與 RTL simulation 的 rtl_binary.txt。 先檢查兩者 pixel 數量是否相同，再用 NumPy 做逐 pixel 比較。 RTL 的 0/1 資料會 reshape 成 256×256，再乘以 255， 產生可觀看的 ../images/sample_binary_rtl.png。 最後列印 Total pixels、Mismatch pixels、Accuracy 以及 PASS/FAIL。 若 mismatch = 0，代表 RTL 與 Golden Model 完全一致。 若影像尺寸或比較規則改變時修改。
code/run_local.sh Linux / Git Bash 一鍵執行腳本 把完整本機流程串起來： python prepare_image.py → cp ../data/gray.hex . → iverilog -g2012 -o simv design.sv testbench_image.sv → vvp simv → python rebuild_and_compare.py。 其中 copy 動作是因為目前 Testbench 用 $readmemh("gray.hex", ...)， 因此 simulator 執行時必須在 code/ 看到一份 gray.hex。 一般不需要；流程或路徑改變時才改。
code/gray.hex RTL Simulation 輸入資料 256×256 共 65,536 個灰階 pixel，每一行是一個 8-bit grayscale value 的十六進位文字。 例如十進位 128 會寫成 80。 這份檔案目前與 data/gray.hex 內容完全相同， 是由 run_local.sh 的 cp 指令複製到 code/， 讓 $readmemh("gray.hex", ...) 可以直接讀到。 不要手動改；由 Python 重新產生。
code/rtl_binary.txt RTL Simulation 輸出 由 Testbench 的 $fwrite 產生，共 65,536 筆 0/1。 每一行代表一個 pixel 經 RTL threshold comparator 處理後的結果。 本 ZIP 中此檔已經產生完成，而且目前與 data/golden_binary.txt 完全相同， 因此此版本的 RTL 驗證結果為零 mismatch。 不要手動改；每次 simulation 會重新產生。
code/simv Icarus 編譯產物 執行 iverilog -g2012 -o simv design.sv testbench_image.sv 後產生的 simulation executable / intermediate simulation image。 它不是 RTL 原始碼，也不是 ASIC gate-level netlist。 下一步使用 vvp simv 執行，才真正開始 Testbench simulation。 不要手動修改；由 iverilog 重建。

三、data/：Python 與 RTL 之間的資料交換

檔案資料格式詳細說明
data/gray.hex 65,536 行 hexadecimal pixel data 由 prepare_image.py 產生，是彩色 BMP 經灰階化之後的 8-bit pixel stream。 它是 Python 世界轉交給 Verilog Testbench 的橋樑。 256×256 = 65,536，因此理論上有 65,536 筆 pixel。 run_local.sh 再把它複製成 code/gray.hex 供目前的 Testbench 使用。
data/golden_binary.txt 65,536 行 0/1 Python Golden Model 的標準答案。 每一個 grayscale pixel 使用相同 threshold = 128： gray >= 128 → 1，否則 0。 最後 rebuild_and_compare.py 會把它和 RTL 的 rtl_binary.txt 逐 pixel 比較。

六、哪些是「原始檔」、哪些是「自動產生檔」？

分類檔案建議
主要原始碼 design.sv、testbench_image.sv、prepare_image.py、rebuild_and_compare.py、run_local.sh 這些才是主要需要閱讀、理解與版本控制的程式。
原始影像 drawBbox_result_p1~p4.bmp 作為真實影像測試來源。
Python 產生資料 data/gray.hex、data/golden_binary.txt、sample_gray.png、sample_binary_golden.png 不要手動修改；重跑 prepare_image.py 即可重建。
Compile / Simulation 產物 code/simv、code/rtl_binary.txt、sample_binary_rtl.png 不要手動修改；重新 compile/simulate/compare 即可重建。
方便顯示的預覽 drawBbox_result_p1~p4.png 主要供 HTML 與人工檢視，不是 RTL 必需檔案。
目前這個 ZIP 的驗證狀態： code/rtl_binary.txt 與 data/golden_binary.txt 完全相同， 而 sample_binary_rtl.png 與 sample_binary_golden.png 也完全相同。 因此現有資料代表 65,536 個 pixel 的 RTL 輸出和 Python Golden Model 一致。
