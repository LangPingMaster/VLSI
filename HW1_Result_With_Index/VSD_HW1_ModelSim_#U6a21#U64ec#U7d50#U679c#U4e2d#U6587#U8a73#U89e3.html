二、ModelSim 指令流程

cd → vlib work → vlog → vsim → run -all → $finish → quit -sim

1. cd E:/StudentID_HW1/Sim

切換 ModelSim 目前工作目錄到 HW1 的 Sim 資料夾。之後編譯檔案、建立 library 等操作都以此處為基準。

2. vlib work

建立名為 work 的 ModelSim library。Verilog/SystemVerilog 編譯完成後的設計單元通常會放在這個 library 中。

3. vlog -sv 檔名

vlog 是 ModelSim 的 Verilog compiler；-sv 表示以 SystemVerilog 語法編譯。例如 vlog -sv ALU_tb_iverilog.sv。

4. vsim work.tb_ALU / work.tb_fp32

vsim 載入準備模擬的 top-level testbench。work.tb_ALU 表示從 work library 載入 tb_ALU。

5. run -all

讓模擬持續執行，直到 testbench 遇到 $finish 或其他停止條件。

6. quit -sim

結束目前 simulation session，但不一定關閉整個 ModelSim。

三、Problem A：ALU 詳解

編譯訊息顯示 ModelSim 找到了兩個 module：ALU 與 tb_ALU，並判定 tb_ALU 是 top-level module。

-- Compiling module ALU
-- Compiling module tb_ALU
Top level modules:
    tb_ALU
Errors: 0, Warnings: 0

接著執行 vsim work.tb_ALU，ModelSim 會載入 testbench 與被測試的 ALU。執行 run -all 後，Instruction 0 到 Instruction 30 全部出現 ALL PASS。

因此可解讀為：testbench 對 ALU 所定義的 31 組 instruction/function 測試，其實際輸出都符合 testbench 的 expected result。

Instruction  0 ALL PASS !!!
...
Instruction 30 ALL PASS !!!

Simulation PASS!!
====== Your score : 62 ======

Your score : 62 是 testbench 自己印出的評分結果，不是 ModelSim 的分數。若作業設計為每個 instruction 對應固定配分，這表示 ALU 此部分取得 testbench 所計算出的 62 分。

$finish : ALU_tb_iverilog.sv(110) 也不是錯誤，而是 testbench 在第 110 行主動呼叫 $finish，代表測試正常完成。

四、Problem B：FPU 詳解

FPU 的編譯階段同樣沒有 error 或 warning。ModelSim 編譯了 FPU 與 tb_fp32，其中 tb_fp32 是 testbench top module。

-- Compiling module FPU
-- Compiling module tb_fp32

Top level modules:
    tb_fp32

Errors: 0, Warnings: 0

載入 work.tb_fp32 後執行所有測試，最重要的結果如下：

TOTAL=2000 PASS=2000 FAIL=0
ALL TEST PASS
欄位意思
TOTAL=2000testbench 總共檢查 2000 筆測試資料。
PASS=20002000 筆實際結果皆符合預期結果。
FAIL=0沒有任何測試案例失敗。
通過率2000 / 2000 = 100%。

Time: 1040015 ns 是模擬世界中的 simulation time，不是電腦實際花費的執行時間。它代表 testbench 的模擬時間軸執行到 1,040,015 ns 時呼叫 $finish。

五、為什麼看到 Break in Module 不是錯誤？

ALU 與 FPU 最後都有類似：

** Note: $finish : FPU_tb_iverilog.sv(480)
Time: 1040015 ns
Break in Module tb_fp32 at FPU_tb_iverilog.sv line 480

這裡的 Break 是因為 testbench 執行到 $finish 而停止。真正判斷是否發生編譯問題應看 Errors、Warnings 與 testbench 的 PASS/FAIL 統計。本次最後為 Errors: 0, Warnings: 0，而且測試全部 PASS，因此屬正常結束。

六、重複執行 vlog / vsim 是否有問題？

紀錄中 ALU 的 vlog 執行兩次，FPU 的 vlog 與 vsim 也有重複執行。這本身不代表錯誤；重新編譯會更新 work library 中的設計，而重新 vsim 則重新載入 simulation。

正式操作時可以簡化成：每個設計修改後重新 vlog，再 vsim 載入 testbench，最後 run -all。若正在 simulation 中需要切換設計，可先使用 quit -sim。
