4. Yosys：ALU parsing → hierarchy → synthesis → check

4.1 先做 SystemVerilog parsing 與 hierarchy

yosys -p "read_verilog -sv Src/ALU.sv; hierarchy -check -top ALU"

結果：PASS。ALU 可被 Yosys 正常解析，top module 正確。

4.2 完整 synthesis + stat

yosys -p "read_verilog -sv Src/ALU.sv; hierarchy -check -top ALU; synth -top ALU; stat"

重要結果：

Checking module ALU...
Found and reported 0 problems.

Warnings: 3 unique messages, 3 total

3 個 warning 為：

Latch inferred for signal `\ALU.\i'
Latch inferred for signal `\ALU.\cnt [5:0]'
Latch inferred for signal `\ALU.\cnt [31:6]'

解析：Yosys 的 synthesis 本身完成，而且最後 CHECK 為 0 problems。warning 集中在程序內部的 i / cnt，並非直接指出 result_o latch。之後 Verilator 也沒有報同樣 latch warning，因此先記錄、待 JasperGold 正式判讀，不在此時修改 ALU。

5. Yosys：FPU parsing 與 fp_addsub 限制

5.1 FPU hierarchy 預檢

yosys -p "read_verilog -sv Src/FPU.sv; hierarchy -check -top FPU"

結果：

Src/FPU.sv:126: ERROR: Function \fp_addsub can only be called with constant arguments.

第 126/127 行的呼叫為：

2'd2: next_result = fp_addsub(ai,bi,1'b0);
2'd3: next_result = fp_addsub(ai,bi,1'b1);

進一步檢查 function：

Select-String -Path Src\FPU.sv -Pattern "function.*fp_addsub" -Context 0,80

其中可見 runtime-dependent normalization：

while((mr[26]==0) && (mr!=0) && (er>1)) begin
    mr=mr<<1;
    er=er-1;
end

5.2 AST 交叉確認

yosys -p "read_verilog -sv -dump_ast1 Src/FPU.sv" 2>&1 | Select-String -Pattern "fp_addsub|while|ERROR" -Context 2,2

AST 可辨識 AST_FUNCTION fp_addsub、AST_WHILE，並在以 runtime ai/bi 呼叫 function 時報 constant-argument error。

結論：這裡應記錄為 Yosys frontend/elaboration 對此 function procedural constructs 的限制；AST 顯示 while 與此限制高度相關，但不應宣稱已證明「唯一原因」就是 while。由於 ModelSim FPU 全部通過，且後續 Verilator 能完整解析 FPU，因此沒有依據為了 Yosys 而修改 FPU。

6.1 修正 VERILATOR_ROOT

第一次 lint 找不到內建檔案 verilated_std.sv。先定位：

Get-ChildItem E:\oss-cad-suite-windows-x64-20260914\oss-cad-suite -Recurse -Filter verilated_std.sv | Select-Object -ExpandProperty FullName

實際位置：

E:\oss-cad-suite-windows-x64-20260914\oss-cad-suite\share\verilator\include\verilated_std.sv

設定：

$env:VERILATOR_ROOT="E:\oss-cad-suite-windows-x64-20260914\oss-cad-suite\share\verilator"
echo $env:VERILATOR_ROOT

設定後 Verilator 可以正常進入真正的 RTL lint。

9. 正式 wrapper：HW1_lint_top 整合 lint

正式 JasperGold Tcl 的架構是同時 analyze 三個 RTL，再以 HW1_lint_top elaboration。因此本機用 Verilator 做相同 hierarchy 的預檢：

verilator_bin.exe --lint-only -Wall --top-module HW1_lint_top Src/ALU.sv Src/FPU.sv Src/HW1_lint_top.sv

得到：

HW1_lint_top
├── u_alu : ALU
│   ├── WIDTHEXPAND × 3
│   └── UNUSEDSIGNAL × 3
└── u_fpu : FPU
    └── WIDTHEXPAND × 4

Total warnings = 10

沒有出現新的 wrapper port mismatch、missing module、multiple-driver 或 syntax 類問題。

9.1 讓 warnings 保留，但不要 fatal exit

verilator_bin.exe --lint-only -Wall -Wno-fatal --top-module HW1_lint_top Src/ALU.sv Src/FPU.sv Src/HW1_lint_top.sv

最終完整跑到：

- V e r i l a t i o n   R e p o r t: Verilator 5.053 devel rev v5.052-80-g0bad0faca (mod)
- Verilator: Built from 0.099 MB sources in 5 modules, into 0.364 MB in 3 C++ files needing 0.000 MB
- Verilator: Walltime 0.038 s (elab=0.003, cvt=0.024, bld=0.000); cpu 0.000 s on 1 threads; allocated 18.973 MB
最終判讀：使用 -Wno-fatal 後，10 個 warning 仍完整顯示，但流程成功跑到 Verilation Report，沒有真正的 %Error。因此三檔 wrapper hierarchy 的 Verilator lint/elaboration 可視為完成。

10.1 現在是否要修改 RTL？

目前不建議。原因是 ModelSim 功能 regression 已全部通過；Yosys 與 Verilator 對部分項目的判讀不同；真正課程要求的 VCS / JasperGold 尚未執行。最安全做法是先鎖定目前 RTL，等 JasperGold Superlint 的正式訊息再決定是否修正 width、unused 或 latch 類問題。
